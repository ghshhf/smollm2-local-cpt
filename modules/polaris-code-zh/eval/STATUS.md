# 编程模块现状与判据 · 2026-10-18

> 一句话：**内容层（代码对不对）由底座决定，模块决定不了；格式层（会不会按协议吐代码块）才是模块的地盘——而自家 0.3B 连格式都是 0。**

---

## 一、结论前置

| 问题 | 实测答案 |
|---|---|
| 编程模块的数据够不够？ | **够**。1463 条全唯一、0 冲突、100% 带代码块、100% 正确收尾；6 epoch 曝光 239.7 万 completion token，是对话模块的 11 倍 |
| 底座有代码底子吗？ | **没有**。0.3B 预训练语料是 Ultra-FineWeb-zh 中文网页（3.7GB），无代码语料 |
| 底座会跟指令吗？ | **不会**。裸 0.3B 拿到编程题先把 prompt 复述一遍，然后退化成复读（R7-R10 古籍/小说把指令能力冲掉了） |
| 那模块能教出编程能力吗？ | **不能**。同题对照：裸 0.3B 严格通过 0/4，裸 Qwen2.5-0.5B 严格 2/4、宽松 3/4 |

**根因与对话模块同构**：SFT 只能把底座已有的能力"按协议搬出来"，不能无中生有。对话模块缺的是知识深度，编程模块缺的是整个代码表征。

## 四、两层验收框架（`tools/code_eval.py`）

编程模块比对话模块多一层，因为**代码能直接执行**：

| 层 | 判据 | 归属 | 现状 |
|---|---|---|---|
| **格式层** | 有 ``` 代码块、带语言标注、块外有说明、以 `<|im_end|>` 收尾 | 模块职责 | 待测 |
| **内容层** | 提取代码块 → 按语言执行 → stdout 与期望比对（strict / loose） | 底座职责 | 待测 |

产物：`logs/code_eval_<tag>.json`，逐题可复核。

**盲测集**：`data/code_holdout_v1.jsonl`，20 题，与训练集平均 4-gram 重叠 **13.4%**（最高 31% 是"JavaScript 代码片段"这类模板套话），可作未见题。

题分两类：
- **可执行验证**（14 题）：题目自带期望 stdout，直接跑，strict 逐字符比对 + loose 关键片段比对
- **格式/API 验证**（6 题）：无标准输出，判代码里是否出现规定的 API 关键词

## 五、三组基线对照（各 4 题，同 prompt、同评测器）

| | 裸 0.3B（自家） | 裸 Qwen2.5-0.5B |
|---|---|---|
| 出代码块 | **0%** | 100% |
| 语言标注 | **0%** | 100% |
| 块外有说明 | 100%（但内容是复读） | 75% |
| 正常收尾 | **0%** | 100% |
| 严格通过 | **0/4** | **2/4** |
| 宽松通过 | **0/4** | **3/4** |
| 生成速度 | 75 s/题 | 22 s/题 |

**裸 0.3B 的实际输出（原文）**：

```
题：写一段 Python 代码，打印 1 到 10 每个数的平方，每行一个。
答：写一段??注的代码，打印 1 到 10 每个数的平方。
    随着时间的推移，代码的内容不断增加，但是代码的内容不断增加，代码的内容不断增加…
```

它连"这是要我写代码"都没识别，先把 prompt 复述一遍，然后卡死在复读循环里，**永不收尾**。这与对话模块测出的"0.3B 裸模型是语料退化复读机"是同一个病灶。

**Qwen 的输出**：代码块、语言标注、收尾全对，`py_sq` 与 `py_prime` 严格通过，`py_sum` 输出的数值对（5050）只是格式不精确。唯一失败的是字符串反转（生成了非 Python 语法）。

## 六、这个对照证明了什么

**同样的题、同样的 prompt 拼接、同样的评测器，两个底座的差距是 0% vs 75%。**

所以：

1. **内容层完全由底座决定。** 模块再怎么训，也变不出底座没有的代码表征。Qwen 有代码底子（预训练 + 官方 SFT），0.3B 没有（预训练只有中文网页）。
2. **格式层对强底座是免费的。** 裸 Qwen 不需要任何模块就 100% 出代码块、100% 收尾。**对这类底座，模块的价值不在权重，在那 1463 条数据和验收标准。**
3. **对自家 0.3B，模块是必需品但天花板很低。** 它要同时补三样：指令跟随、输出格式、代码内容。前两样能教，第三样教不了。

预期（诚实标注，跑完再兑现）：6 epoch 后 format 层大概能从 0% 爬到 60~90%，内容层接近 0。**这已经比裸模型强，但它不是"会编程的模型"，是"会按格式吐代码块的模型"。**

## 七、三条路（按"能不能真正解决问题"排序）

| 优先级 | 动作 | 解决什么 | 代价 |
|---|---|---|---|
| **1** | 给预训练配方加**代码语料**（0.4B / 0.5B 阶段就加） | 唯一能真正让自家模型会编程的办法 | 改语料配方，重跑或续训 |
| **2** | 编程模块按"格式模块"定位收口，内容层外挂工具（执行器 / 检索） | 承认模块能力边界，把内容交给工具 | 几乎零成本，但要改架构定位 |
| **3** | 用这 1463 条在**有代码底子的底座**上重训行为模块（跨血统正解） | 想要"我们的规矩 + 别人的代码能力" | 小时级实验，本机 CPU 可做 |

第 3 条是纯增量、成本最低、且能立刻验证的。它的产出是：**在 Qwen2.5-Coder 之类底座上，用我们的数据训出"说中文、给可运行代码、配关键说明、认主"的编程模块**。
