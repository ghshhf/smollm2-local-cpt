## 三·五、实测收益（`eval/vocab_add_gain.py`，30 万字真实语料）

基线：**2.4589 token/汉字** —— 现词表 48,843 条里**只有 77 个汉字是独立 token**，汉字词只有 3 条。

| 方案 | 加什么 | token/字 | 节省 | 1024 多装 | 参数增量 |
|---|---|---|---|---|---|
| A | 只加 8105 常用字 | 1.4252 | **42.0%** | +73% | **+4.6M** |
| B | 只加词频 top 3 万 | 2.3229 | 5.5% | +6% | +17.3M |
| C | 字表 + 词 top 3 万 | 1.3684 | **44.3%** | +80% | +21.9M |
| D | 字表 + 词 top 6 万 | 1.3514 | 45.0% | +82% | +39.2M |

**结论**：字表是收益主体且极便宜（性价比约词表 15 倍）；**只加词不加字几乎无效**；词表 3 万封顶。
→ 加的顺序：**8105 字表 → 高频词（≤3万）→ 可选成语/专名**。

## 四、下一步（待定稿，尚未执行；时机 = 0.4B 阶段）

1. 合并三源 → 按词频归一排序 → 取**高频词 top N**（N≈3-5 万）作为**待追加**词表
2. **「加」不是「换」**（2026-10-14 用户明确纠正）：
   - 旧 49,152 个 token 一行不动、id 不变，只在尾部 append 新中文词
   - 旧 embedding / lm_head 行原样保留 ⇒ **现有 0.2B/0.3B 权重可继续训练，不用从头训**
   - 反例：重建 tokenizer（"换"）会让 embedding 全变，必须从头训 —— 那是错的路线
3. 新行初始化 = **该词在旧词表下各子词 embedding 的均值**（Chinese-LLaMA 同款），**禁止随机初始化**
4. 参数增量 = 576 × N（N=40k → +23M，约 214M 的 11%）；lm_head 若 tied 需同步扩或改 untied
5. 训练节奏：先冻结主干只训新增 embedding 一小段 → 再全放开
6. 验收口径：随机抽 1000 句中文，平均 token/字 从现在 ~1.5-2 降到 ≤1.2
7. 纯 CPU 活儿，本机可跑，不占 node1
