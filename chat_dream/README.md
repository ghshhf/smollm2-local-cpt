# 对话闭环（chat dream loop）

0.3B 北极星的对话能力生产线：**出题 → 批量生成 → 规则闸 → 语义判分 → 入库 → 增量训练 → 换卡继续做梦**。
全程无人在场，热更新，不重启。

## 文件

| 文件 | 作用 |
|---|---|
| `chat_dream.py` | 做梦主程序。五路出题（expand/selfplay/emotion/life/replay）、批量生成、14 道规则闸、语义 judge、入库、自动训练、supervisor 热重启 |
| `chat_train.py` | 增量训练。训练前用当前闸门复核全库，防脏数据入训；输出 `adapter_r{N}_clean` |
| `emotion_core.py` | 情感核。五个需求通道 + PAD + 显式耦合 + 表达门 + 共情传导。用来生成带情感标注的训练数据 |
| `judge_bench.py` | 打分机实测。同一批已知答案的样本发给所有候选模型，看谁真的会判死 |
| `probe_models.py` | 网关模型探活。面板显示不可信，以实测为准 |
| `clean_bank_judge.py` | 用当前打分机全库复查，挑出旧标准放进来的垃圾 |
| `recheck_bad.py` | 复核被判坏的样本，防聚合规则误杀 |
| `policy.example.json` | 配置模板（令牌置空，跑之前填 `ZEN_GATE_TOKEN` 环境变量） |

## 跑法

```bash
export ZEN_GATE_TOKEN=...        # 本地网关令牌，不要写进仓库
cp chat_dream/policy.example.json policy.json
python chat_dream.py --supervise  # 常驻：worker 退出码 78 时用新代码重启
```

改了 `policy.json` 不用重启，最多 5 条样本后生效；改了 `.py` 要等 worker 自己轮换。

## 几件踩过的事

**批量不是并发。** 单个模型不接受并发（4 线程打同一个模型会挂一半），但一条请求里打包 8 条不触发限制，反而更快。实测 44 个能判分的模型里只有 3 个支持这种打包格式。

**判分要用中位数 + 多数票，不要用均值。** 均值会让「一个模型判 2 分、另一个判 9 分」变成 5.5 分被拒；同时 `min<=3` 一刀切会误杀约 7% 的好样本（有模型会把「去吧主人，晚安」判成生硬）。现在的规则是：多数票 pass + 中位分达标 + 至少两个模型判死才否决。

**脏数据有三层防线。** 生成端闸门 → 入库端判分 → 训练前全库复核。任一层漏了，一轮增量训练就足以把 base 的代码先验激活（那时会出现疯狂输出 `<jupyter_output>` 的卡）。

**情感核是教师，不是外挂。** 它只用来产出带状态的训练数据，最终目标是压进权重、外挂退役。表达门的存在是为了让情绪不外显——低强度时什么都不说，这本身就是气质。
