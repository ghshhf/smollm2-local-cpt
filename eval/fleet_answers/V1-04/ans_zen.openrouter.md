# zen.openrouter (vendor=openrouter, served=openrouter/free, 34.7s)

## 1. 机制/最佳理论：执行器与评估器的严格分离（Leaving-Out 架构）

**核心结论**：第一版 RS-loop **必须**采用**完全分离**的执行器/评估器架构，执行器（Student）与评估器（Teacher）必须来自不同模型实例，且评估器**绝对不能**看到学生模型未见过的问题。这是避免“自欺”（self-deception）的唯一可靠手段。

### 为什么分离是必要的
- **自欺机制**：如果评估器是学生模型自身，它会遇到“它自己生成的问题”，自然会给自己打高分（因为它知道答案），导致训练目标失效——模型被奖励“答对自己”，而不是“发现新知识”。
- **理论依据**：这对应强化学习中的“自我监督陷阱”。只有当评估者是独立于被评估者的外部观察者时，才能获得真正的“真空检测”信号。
- **解决方案——Leaving-Out 状态机**：
  ```
  状态机设计：
  ┌─────────────┐    ┌──────────────┐    ┌─────────────┐
  │   Student   │───▶│  Leave-Out   │───▶│  Teacher    │
  │ (0.5B)      │    │  Evaluation  │    │ (Reference) │
  │             │    │  (External)  │    │             │
  │ • 生成问题  │    │ • 接收问题   │    │ • 提供答案  │
  │ • 求解问题  │    │ • 计算NLL    │    │ • 提供标签 │
  │ • 输出答案  │    │ • 打分评分   │    │ • 更新Teacher│
  └─────────────┘    └──────────────┘    └─────────────┘
  ```

**关键原则**：
- **Student** 只负责推理（生成问题 → 求解 → 输出答案）
- **Teacher** 是固定的、不可变的参考模型（0.5B主线模型）
- **评估** 必须在 Student 未见过的问题上进行（Leave-Out），即“留出法”
