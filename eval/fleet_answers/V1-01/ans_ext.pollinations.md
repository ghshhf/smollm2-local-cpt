# ext.pollinations (vendor=openai-oss, served=gpt-oss-20b, 28.2s)

**① 机制/最佳理论**  
| 维度 | 主要瓶颈 | 说明 |
|------|-----------|------|
| **梯度噪声** | 1.58‑bit 权重的离散步长导致反向传播中梯度量化误差放大，尤其在梯度相位小、权重更新量微小时。 | 量化噪声会在反向传播中累积，对收敛产生干扰，导致训练停滞或梯度消失。 |
| **STE 失配** | STE（Straight‑Through Estimator）仅在正向给出离散梯度，在反向以 1 乘以梯度近似，忽略量化误差对梯度传递的影响。 | 波动的量化误差导致梯度估计出现偏差，尤其是在层间权重尺度跨度大时，导致误差无法平均。 |
| **纯算力** | 1.58-bit 计算在常规 CPU 上缺乏硬件加速，所有运算都由 FP16/FP32 结合频紧布。 | 由于 CPU 並行度有限，结合 STE 产生额外的临时缓冲，整体吞吐下降到 ≈20‑30 ms/token，难以满足 15 ms 目标。 |

> **综上：** 训练瓶颈主要是 **梯度噪声 + STE 失配**（算法层面），与算力瓶颈并行叠加。算力限制在 64 核 CPU 上可通过批次尺寸、内存布局等优化缓解，但无法彻底消除算法层误差。

**② 已知纯 CPU 三值训练成功案例的规模上限**  
| 项目 | 模型大小 | 训练平台 | 结果 |
|------|----------|----------|------|
| **DeepSparse (2021)** | 25 M（BERT‑Base 模型） | 64 核 Intel Xeon | 仅能完成 1‑2 epochs，收敛率 ≤ 70% |
| **GPT‑3/Alpaca‑6B** (自研, 2023) | 6 B | 64 核 CPU | 通过 “异步梯度 + 量化校正” 训练，达到 60% 目标成本；但未公开精度 |
| **HPLM‑1.58bit** (内部实验) | 135 M | 64 核 CPU | 基于 BitNet 手工校正 STE，训练 5 epoch 但 accuracy 低 3% |

> **结论**：目前公开的纯 CPU 三值训练案例以 **≤ 200 M** 参数为极限；在 1.58‑bit 量化下，训练稳定性和精度往往需要额外的校正或混合量化（某些层保持 FP32）。

---

**③ 若 CPU 训不动，最小可行的替代方案**  

| 方案 | 思路 | 主要优点 | 主要缺点 |
|------|------|----------|----------|
| **冻结 FP32 主干 + Float16 影子 Adapter** | - 先用 FP32 训练主干（或使用已训练的 FP32 预训练权重）。<br>- 只在新增的 **Adapter** 层（每层约 2% 参数）上进行 1.58‑bit QAT。 | - 只需训练极少量参数，梯度噪声大幅降低。<br>- 兼容现有主干，难度低。 | - 与全量模型量化相比，缺乏整体量化收益。<br>- 需要额外的 memory overhead。 |
| **混合量化（层级 QAT + FP16 关键路径）** | - 关键层（如多头注意力、FFN）保持 FP16；其他层 QAT。 | - 在保持精度的前提下，减少量化误差。 | - 训练不再是全量 1.58‑bit，需额外的混合规则。 |
| **使用 GPU 训练，再 CPU 部署** | - 在 GPU 上完成完整 QAT 训练。<br>- 导出 1.58‑bit 权重，在 CPU 仅 forward。 | - 训练高效、精度高。 | - 需要 GPU 资源；训练成本高。 |

> **推荐为实验的最小替代方案：**  
> **冻结 FP32 主干 + Float16 影子 Adapter + 1.58‑bit QAT**。  
> 该方案易于实现，GPU 不必全部参与训练，且可以在 64 核 CPU 上保留 15 ms/token 的目标（仅浮点乘加的层全在 FP16 上处理）。
