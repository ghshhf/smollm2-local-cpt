**① 机制/最佳理论**

| 现象 | 小尺寸模型（≤1 B）中的预期行为 | 为什么理论可能“弱化” |
|----------|---------------------------------------------------|--------------------------------|
| **归纳头**（将模式从演示中*学习*并应用于查询的专用注意力头） | 仍然存在，但**出现频率**和**纯粹度**都会大幅下降，因为每个头可以学习的模式数量有限，短路径深度不足以支持多步归纳。 | 深度优先设计使最早期的层只学到浅层正则表达式；大多数“元学习”头可能被拆分为多个低秩子头或与无标签的模式混杂。 |
| **层数不足** | 0.4 B 模型通常只有 **12‑16** 层（BitNet‑b1.58 的深窄设计）。一个完整的归纳过程（捕获*演示→规则→应用*）可能需要 ≥3 个互连层。 | 层数限制了信息的 sequential processing，导致某些演示头与输出 head 的关联性较弱。 |
| **头数不足** | 每个自注意力子空间中的专用归纳头通常占 **5‑10 %**。在 0.4 B 模型中，这意味着**~2‑4** 个真正用于 ICL 的头，而大多数头用于嵌入/表示转换。 | 头数少 → 并发编程能力弱 → 更容易被训练数据格式噪声覆盖。 |
| **训练数据格式** | SFT 数据通常为单例（`提示 → 回答`）或无结构批次。许多微调工作证明，**统一的“演示占位符”**（` Demonstration … Demonstration`）可以显著提高 ICL 能力。 | 如果训练数据缺乏展示 *模式匹配* 能力的样例，模型甚至无法**学习**到一个有效的工作机制（如归纳头）。 |

**综合观点：**
- 归纳头机制仍然适用，但其信号在 ≤1 B 模型中**更微弱、更分散**。
- 微弱的原因是**三重约束**：(1) 深度不足以完全扩展 multi‑step 计算；(2) 头数不足以容纳纯粹的归纳子空间；(3) 训练数据的*格式*未强化*模式匹配*范式。

def build_icd_sft_record(task_name: str, demos: List[Dict], query: Dict) -> str:
    """
    返回适合微调的字符串模板。
    模板固定化，便于模型学习模式：
        Task: <task_name>
        Demonstrations:
            Demo 1:
                Input:  <输入>
                Output: <输出>
            Demo 2:
                Input:  <输入>
                Output: <输出>
        Query:
            Input:  <输入>
            Output: <占位符>
    """
    lines = [f"Task: {task_name}", "Demonstrations:"]
    for i, d in enumerate(demos, 1):
        lines.append(f"    Demo {i}:")
        lines.append(f"        Input:  {d['input']}")
        lines.append(f"        Output: {d['output']}")
    lines.append("Query:")
    lines.append(f"        Input:  {query['input']}")
    lines.append("        Output: ")
    return "\n".join(lines)
