一、为什么现在认真对待"睡眠"

用户直觉指向的方向，在 2026 年 10 月的前沿里已经是一条清晰的主线：模型的持续学习瓶颈不在容量，在"把经历转化成能力"缺少一个离线加工阶段。生物用睡眠解决这个问题——海马体把白天的短期记忆在睡眠中重放、巩固进皮层。两篇同期论文把这条路在语言模型上走通了，而且分工恰好覆盖我们设计的两个层。

论文 A：Language Models Need Sleep arXiv 2605.26099

CMU + 马里兰大学（Sangyun Lee / Sean McLeish / Tom Goldstein / Giulia Fanti），2026-05

机制：上下文窗口将满时，模型进入"睡眠"——对已累积内容做 N 次离线递归前向，通过可学习的局部规则把信息写进 SSM 块的 fast weights；睡眠结束清空 KV cache，之后只做单次前向预测。睡眠期不收任何外部 token，只做内部加工。

实测（同 token 预算下）：

任务基线睡眠后提升
Rule 110 元胞自动机（演化 32 步）~10%>30%3 次/4 次循环均超 30%
Depo 多跳检索（16 跳）4 跳以上几乎学不到4 次循环开始在最难 16 跳取得进展质变
GSM-Infinite 6 步运算（Jet-Nemotron 2B）0.7420.812+9%
GSM-Infinite 6 步运算（Ouro 1.4B）0.4190.615+47%
滑动窗口驱逐 L=512，2 步运算0.5960.905+52%
关键结论：瓶颈不是记忆容量，是把上下文转化成有用权重记忆所需的计算量。"睡得越久"（循环次数 N 越大）推理越深——且推理延迟不变，额外计算全花在睡眠期。这与思维链等推理时扩展有本质区别：开销转移到记忆整合阶段，而非预测阶段。

论文 B：Language Models Need Sleep: Learning to Self-Modify and Consolidate Memories arXiv 2606.03979

Google（Ali Behrouz / Farnoosh Hashemi / Vahab Mirrokni —— Nested Learning 团队）

机制：给持续学习者两个周期性状态，睡眠分两阶段：

① Memory Consolidation（记忆巩固）：Knowledge Seeding —— 一种向上蒸馏，把"更活跃的小 self"的知识蒸馏进"更稳定的大 self"（新解锁参数层）。既可塑性又保旧知识，缓解灾难性遗忘。

② Dreaming（做梦）：模型用 RL 自己生成一套合成数据课程，对新知识 rehearsal、对旧能力精炼——无人工监督的递归自我改进。

关键结论：持续学习的正解不是永远在线训练，而是"清醒时接收 → 睡眠时巩固 + 做梦时自产"的节律。Dreaming 阶段直接对应"自进化"：模型自己出题、自己练。

二、同构映射：我们的架构就是睡眠范式的端侧实现

把两篇论文的组件和我们已经落地的东西摆在一起——几乎每个概念都有对应物，这不是巧合，是收敛：

论文概念出处我们的对应物（已落地/已设计）
fast weights + N 次离线递归论文 A（CMU）In-Place TTT（ByteDance，ICLR 2026 Oral）：fast weights = 各 MLP 块 down_proj 的外积累积更新，纯前向、drop-in、已用 r6_final 权重跑通 sanity。"睡得多学得多" = 对同一批上下文多过几遍前向——TTT 的 chunk 累积就是它的轻量端侧版。
Knowledge Seeding（小 self → 大 self 向上蒸馏）论文 B（Google）保函数扩容链：R2→0.2B→0.3B→0.5B 逐级扩容，实测 diff=0.000000，同一个"学生"越换越大——这就是 Knowledge Seeding 的保函数实现，且教师始终是云端强模型（蒸馏不中断）。
Dreaming（RL 自产数据课程）论文 B（Google）三元组银行（任务, 代码, 验收结果）：模型自己生成任务+代码，vid_verify 八项确定性验收当 reward，通过的沉淀成库。一库两用：检索库 + 未来唯一的 SFT 数据。这是"用 verifier 代替 RL"的端侧 Dreaming。
睡眠期不收外部输入论文 A睡眠态由排队器/schtasks 驱动：银行新增量到达阈值或机器空闲时触发，与"白天干活"（VLM/编程/爬虫）时间隔离——本地永远只跑一条，天然就是两态。

睡眠态的两个阶段（端侧实现细节）

阶段 1 · 巩固（论文 A 的 N 次循环 + 论文 B 的蒸馏）：把银行里当日新增三元组作为上下文，用 TTT 做 2-4 遍前向累积更新 fast weights。只动 fast weights——推理时丢弃即可回滚，主干锚定不动。长期性知识（"这是谁、这是什么界面"）进记忆层不进权重。

阶段 2 · 做梦（论文 B 的 Dreaming）：模型从银行抽样/组合生成新任务（如"把这三段素材剪成一个 15 秒转场片头"），自己写 FFmpeg/Remotion 代码，vid_verify 验收。通过的（任务, 代码, 验证）三元组回银行——银行自我生长；失败的诊断信息也回库（负样本，未来当反例教材）。每一轮就是一次秒级进化，全程不碰主干权重。

宪法 E-7 兼容性（重要）：睡眠期的全部权重改动只发生在两个可弃层——fast weights（推理时可卸载）和记忆层（可寻址可删除）。个人数据绝不进被训练参数。推理路径钉成确定性。睡眠范式不仅不违宪，反而是 E-7 的正例。

为什么这条路线对 0.2B 是刚需不是奢侈品

  • Fast-Slow 论文的佐证：纯权重 RL 会让小模型越学越僵（权重离基座越远，注入新知识即崩）——所以进化必须走"主干锚定 + 外置可删"，睡眠态正是这个形态。
  • 算力账：推理时学习 + 外置记忆比预训练便宜 1-2 个数量级，本机 12 核就能跑；node1 那边继续按部就班扩容，两边不打架。
  • mdlARC 实证：75M + TTT 在 ARC 任务上 44% 命中率、成本 $0.67，反杀多个大模型——小模型 + 推理时进化是被验证过的路线。
