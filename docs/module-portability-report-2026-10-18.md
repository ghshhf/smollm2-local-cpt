# 模块跨主干可移植性实测报告

> 2026-10-18 05:22。回答一个问题：**"一个模块随便搭到别人的模型上"到底能不能成立？**
> 六组实测，全部本地 CPU，同一批 prompt、同一套贪心解码。不推测，只报数。

---

## 一、结论前置

| 关系 | 行为迁移 | 证据 |
|---|---|---|
| **同血统**（我们的 0.2B → 0.3B，跨代 + 跨 inter，只加层） | ✅ **成立** | "好，主人。" 两个代际都复现 |
| **同架构不同血统**（SmolLM2-200M） | 🟡 **一半** | 从复读机变成会说话，但身份/内容全错 |
| **跨血统**（Qwen2.5-0.5B，不同词表、不同 hidden） | ❌ **不成立，且有害** | 完全无"主人"概念，偶尔比裸模型更差 |

**一句话**：模块的可移植性边界，就是**预训练血统的边界**。同血统权重可直接搬，跨血统只能重训——但**数据、方法、验收标准可以整体带走**，这才是模块化真正兑现的东西。

---

## 二、实验设计

- 同一批 prompt：`你好 / 在吗 / 你是谁 / 你的主人是谁 / 1+1等于几 / 现在几点了`
- 贪心解码，48 token，`eos=<|im_end|>`
- **两个条件**：带 system（"你是北极星，主人的私有助手。"）与**不带 system**
- 🔴 **不带 system 是唯一干净的判据**：带 system 时强模型会直接复述系统提示，看起来"认主"，其实是抄的。

2. **0.3B 裸模型是语料退化的复读机**（R7 古籍/小说阶段把对话能力冲掉了），**挂上模块就从复读机变回会说话的模型**。这说明模块补的是行为，不是知识。
3. **Qwen 挂不挂模块，回答一字不差。** 模块在 Qwen 上是 336 个张量的纯噪声。

## 四、为什么？机制层面

模块学的是 `ΔW`，一个**作用在 hidden 空间上的线性映射**。

零填充保证了：

```
ΔW'[i, j] = ΔW[i, j]   (i < d_out, j < d_in)
```

即"把前 576 维喂进旧矩阵，输出和以前一模一样"。

**但这个保证有个隐含前提：目标模型的第 0~575 维，和我们的第 0~575 维是同一个东西。**

- 0.2B → 0.3B：同一份预训练血统续训而来，前 576 维**语义连续**（实测残差流 cos：0% 层 0.9986 / 25% 0.9375 / 50% 0.9085 / 100% 0.9263）→ 保证成立。
- Qwen：不同词表（151936 vs 49152）、不同预训练语料、不同 hidden（896）→ **维度编号之间没有任何语义对应** → 保证失效。

所以 `max|diff| = 0.000e+00` 只证明"移植是精确的"，**不证明"移植是有意义的"**。这两件事过去被混为一谈了。

## 五、一个我自己犯的错，已修

第一版 `module_loader.py` 把 MLP 的 `gate/up/down`（180 个张量，占 43%）**一律丢弃**，理由是"可扩维，扩容即失效"。

这是把**跨代场景**的规则误用到**跨模型场景**：给定目标主干时，`intermediate_size` 是已知常量，只要目标更大就能零填充。

已修。修正后：

| 目标 | 旧行为 | 新行为 |
|---|---|---|
| Qwen2.5-0.5B | 240 直装 + 丢 180 | **360 零填充 + 60 截断 + 0 丢弃** |
| polaris-0.3B | 240 直装 + 丢 180 | **330 直装 + 90 零填充 + 0 丢弃** |

补测结果：**保留全部 420 张量后，Qwen 依然完全无效**。所以"丢 MLP 导致迁移失败"这个假设被推翻——真正的障碍是表征空间不匹配，不是张量缺失。

（`fragile` 标记保留：MLP 张量这次能装，但主干下次加宽就失效，报告里会显式提示。）

## 六、那"通用模块"到底怎么办

### 6.1 能做的：同血统复用（已验证）

- 0.2B → 0.3B → 0.4B：零填充，`max|diff|=0`，行为复现
- 这是我们的主线，**完全成立**

### 6.2 跨血统的正解：带数据重训，不是搬权重

跨血统时能整体带走的是三样：

1. **一套行为规范**（谁、什么语气、多长、怎么收尾）
2. **一份训练数据**（几百条就够，因为只教行为不教知识）
3. **一套验收标准**（in-set CE < 0.6、盲测、过拟合探针）

在目标主干上重新训一遍，成本是**小时级**，不是"从零训模型"。这才是"挂到 Qwen-Coder 上就拥有我们的规矩"的真实路径——**用我们的数据和标准，在它的骨架上快速长出一个行为模块**。

### 6.3 真正零成本通用的形态：指令层

如果要求"一份东西、零训练、挂哪都能用"——那它不是权重，是**文本**：

```
你是北极星，主人的私有助手。回答简短、直接、不客套。
```

实测：裸 Qwen 读到这句 system，立刻自称"我是北极星，主人的私人助手"。

**表达力弱（改不了深层行为），但 100% 可移植。** 权重模块表达力强，但绑血统。这是一个明确的取舍，不是缺陷。

## 七、对模块规范的修订

| 原表述 | 修订为 |
|---|---|
| "L1 同架构异构：零填充即装" | 改为"**同血统**异构：零填充即装，行为可迁移" |
| "L2 跨架构：零填充 + 200~500 条重定位" | 改为"**跨血统**：权重不可迁移，需在新主干上重训行为模块（数据/标准可带走）" |
| "`max|diff|=0` ⇒ 移植成功" | 改为"`max|diff|=0` ⇒ **移植精确**；**行为是否迁移需另测**（无 system 生成对照）" |

新增验收铁律：

> **跨主干验收不得只看形状或 loss，必须跑无 system 生成对照。**
> 带 system 时强模型会复述系统提示，会产生"模块生效"的假象。
