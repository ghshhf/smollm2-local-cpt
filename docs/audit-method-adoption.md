## 办法一 · 磁盘实证优先于任何模型陈述

**源**（终裁原则）：委员会 5 例事实错误 + 4 例「已修」伪状态，**全靠 grep / GitHub API 取证推翻**；模型/委员会说自己改了不算数，磁盘说了算。

**训练线落地**——任何状态结论出口前，必须留一条可复现取证命令：

| 结论类型 | 取证命令（照抄即用） | 通过判据 |
|---|---|---|
| git 是否同步 | `git -C D:/work/_local_ai/train_15b ls-remote origin HEAD` 对 `git -C ... rev-parse HEAD` | 两个 SHA 相同；`git log origin/main..HEAD` 为 0 |
| 权重身份 | `sha256sum <file>`（源 vs 本地 vs 拼回，三处比对） | 前缀一致即字节级一致 |
| 文件新旧 | `ls -la <dir>` + `wc -c <file>` | 时间戳/字节数对得上预期档位 |
| 训练是否在跑 | `node/node1_status.py` → 看 `tok/s` 和 `done_steps` | **不按 CPU% 判断** |

**反面案例（2026-10-16 本会话三次，全部自己打脸）**：
1. 说「推上去了」→ 远程 HEAD 停在 3 个 commit 前，从没推过；
2. 说「代理没监听、代理慢」→ Karing 3067 一直活着，是拿**国内 ECS** 测代理（场景错）；
3. 说「200M 权重已经在本地」→ 本地是 10-10 旧版，R6 封顶版在 NAS。

## 办法二 · 凡称「已修」，先证伪再采信

**源**（流程修正）：终裁前主席对每题「需核验点」逐一取证；**凡收口标「已修」的一律先证伪**。

**训练线落地**：
- 权重验收禁只看结构 → 必跑「同批中文 holdout CE + 2 条贪心生成」（已是纪律，继续）；
- 训练链每档产物 → 先看日志告警再宣布完成（R7 那条 **256 万 token 超长样本**就是靠日志取证挖出来的，不是靠"跑完了"）；
- 任何"节点恢复了/任务完成了"的判断 → 用 `node1_status.py` 取证，不凭上一次印象。

**源**（文档 §1.3）：伪状态 / 定性错误 / 方案缺一半 / 字段臆想 / 锁设计错误 / 凭空施工 / 版本号凭记忆。

**训练线台账（续记，格式照搬）**：

| 病症 | 实例 | 成因 | 防护动作 |
|---|---|---|---|
| 状态先行 | 三次误判（推成功/代理没开/权重在本地） | 不看磁盘先下结论 | 出口前跑取证命令（办法一） |
