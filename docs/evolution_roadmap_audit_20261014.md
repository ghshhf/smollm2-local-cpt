## §1 路线主干（背景，不重写）

- 容量链：从 ~0.1B 起逐级 Net2Net 保函数扩容（只加宽 MLP / 加零输出恒等层，**绝不改 attention / RoPE / GQA / hidden 维**，因 v1 576→640 曾致 200M 乱码）。里程碑：R2(135M)→0.2B(214M)→R4→R5→0.3B(350M,36层)→R6→**0.4B 分水岭**→**0.5B 断裂点**→1B→3B→8B。
- 0.4B：词表尾部 append 中文 token（旧 id 不动、新行用旧子词 embedding 均值初始化、lm_head 同步扩、tokenizer.json 直接 append 使旧编码不变）；灌 owner_corpus + 自有语料；训认主对比头。
- 0.5B：**架构从零**（BitNet b1.58 三值强制从零训）但**能力从 0.4B 强到弱蒸馏继承**；引入 10M 个人记忆层（user embedding + 检索库 + adapter）。
- 目标形态：端侧常驻个人服务，看门狗内嵌、开机自启、RSI 自进化。
- **算力基底（简单说明）**：现阶段用**免费 CPU**（魔塔 64 核，时间换主权）；规模越过临界点后切到**免费 GPU 基底**（预留算力 / 社区 GPU 资源），算力成本不再由本地 CPU 承担。本委托不涉及支付方式。

## §2 算力基底定量拐点（已立前提，待你精算）

- 本机实测：1 小时 ≈ 1.1e15 FLOPs，仅能做方法学对照。
- 魔塔 64 核实测：214M 全模型约 18.7~29.1 s/step。
- 请推导：在 1.58bit 下从 0.1B 逐级到 1B / 3B / 8B 的每级 step 数与单步耗时，给出**免费 CPU 墙钟不可行的临界规模**（必须切 GPU 基底的拐点），并说明该拐点如何随「1.58bit 把最优容量推向更大参数」而移动。

## §3 已立前提（DO NOT RE-DERIVE，直接作为已知条件向上推）

- **P1 三值 Net2Net**：实测宽度扩容三值跳变 **+1.70%**（对应某加宽比例与规模，比例未记录故不可外推）；根因 γ=mean|W| 全局标量被零填充稀释。两解法：A 在 fp32 潜权重上做结构操作（三值仅推理表示）；B 分块 γ（跳变 0.0000）。**规避方案已升级：结构操作时冻结旧坐标三值符号 + 该行 α，使部署函数逐位不变。**
- **P2 词表 append 类型论冲突**：「保函数」要求输入输出同类型，append 把 logit 空间 V→V+k，严格函数相等在命题层写不出，只能退化成「限制映射相等」（旧词表输入→旧词表输出等于旧模型）。不变量必须写成「旧 pre-softmax logits 逐位不变 + 输出分布变化有界」。仅比 logits 会通过、比分布会失败。softmax 分母系统性 +~0.04 nat（k=2000,V≈49152 量级估计）；因 tokenizer.json 直接 append 使旧编码不变，loss 定义域不改变，残留收敛到「分母抬高 + 梯度耦合」两条有界路径。
- **P3 身份连续性**：0.4B→0.5B 是架构重置 + 蒸馏，历史上即「新模型」；功能 KL 可压到任意小但**不能识别谱系**——「同一模型」在此路线是**叙事约定而非客观性质**。科学命题应写成「能力 C、用 M 测、在分布 D 上、容差 τ 内」。
- **P4 Delétang 三值重算**：adjusted rate 把模型存储计入后，同语料在三值（~2bit vs 32bit，约 16×）口径下最优点被推向**更大参数量**。用 fp32 口径说某规模「已过最优」是算错口径。
- **P5 RSI 自进化红线**：闭环新数据只来自自产输出时信息不增；**替换**真数据→坍塌（Shumailov et al., Nature 2024），**累积不替换**→安全（Gerstgrasser et al.）。10M 记忆是此路线容量天花板之一。
- **P6 决策门系统**：已落成 10 道 Gate。Gate 0 评测底座（冻结留出集 + 噪声宽度 + 最小可分辨效应 + 血统）是其余前提；Gate 1 plateau **三分类**（容量 / 优化 / 数据受限，仅容量受限放行扩容）；Gate 2/3 阶梯经济性与算子质量；Gate 4 词表；Gate 5 认主头；Gate 6 架构断裂；Gate 7 记忆层；Gate 8 RSI；Gate 9 三值扩容每级重测跳变。互斥规则：RSI 激活后扩容与闭环不得并行。

## §4 请产出的执行手册（核心交付）

### 4.1 逐 0.1B 步进时间表（到 8B）
对每一个里程碑与中间 0.1B 步，给出：**本步最优容量增量 ΔN**、**为不越过 Delétang 最优点所需的数据增量 ΔD**、**该步的验收指标（留出损失下降幅度 / 能力地板）**、**前置 Gate**。
必须显式给出 **纯缩放边际收益趋零的临界规模 N\***（此后继续放大参数无效、必须靠模块插入），并写出 N\* 对「数据总量」与「1.58bit 记账」的显式依赖（非拍常数）。

### 4.2 「参数缩放 vs 能力复合」统一切换规则
把四条约束（Delétang 数据最优点 / plateau 三分类 / 三值离散边界余量 F_δ / RSI 累积不替换）合成**单一可落地判定规则**——最好写成**判定清单或伪代码**，让我们能在每次扩容前机械执行：当前应「继续放大参数」还是「插入能力模块（词表/认主/记忆/蒸馏）」？并排定这四条约束随 N 增长（0.1B→8B）**各自最先 binding 的顺序**。

### 4.3 CPU→GPU 墙钟拐点
用 §2 实测基准，给出必须切 GPU 基底的具体规模，并说明该拐点如何随 1.58bit 记账移动。

### 4.4 三个模块插入点的具体设计规格（我们最缺、请从零推演）
1. **0.4B 认主对比头**：triplet 负样本如何构造（源自已有的 owner_corpus，需多少来源数才够）、与主任务如何联合训练、梯度冲突如何解、如何验证主干未泄露身份（主干线性探针判据）。
2. **0.5B 记忆层联合训练协议**：user embedding / 检索库 / adapter 三组件的 loss 如何配比、训练顺序、检索库何时更新与如何预防漂移；并给出选型判据（端到端首 token 延迟 + 常驻内存峰值 + 可删除/可审计/可回滚，替代「不增 FLOPs」这一待验证前提）。
3. **0.5B 蒸馏桥接**：BitNet 从零架构 + fp32 教师输出，梯度如何桥接（前向 KL / 反向 KL / JSD 在 5 万+ 词表下的差异）、如何把教师能力无损压进三值、对照臂设计（无蒸馏 / 换教师 / fp32 扩展后量化）。

### 4.5 三值离散性沿整链的聚合漂移预算
随 K 次 Net2Net + 1 次架构重置 + 记忆插入，给出**聚合功能漂移预算**（M-DRIFT）与安全阈值判据；明确「fp32 潜变量上操作」是否充分，还是必须叠加「冻结旧符号 + 该行 α」。
