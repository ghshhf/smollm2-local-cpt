# 0.5B 融合版：设计纲领（2026-10-14）

## 零、第一原则：不封死

**"只有不封死的模型，它未来才能自己进化。"**

这是本项目的**元约束**，优先级高于任何性能目标。任何设计决策先过这条。

### ❌ 会"封死"的操作（禁止）
| 操作 | 为什么封死 |
|---|---|
| 换词表 | token id 全变，旧 embedding 全废，已学的一切作废 |
| 改注意力维度 / GQA 头数 / hidden | 打乱所有层已建立的注意力配对 = 已压缩的记忆碎掉（v1 576→640 的 200M 乱码教训） |
| 丢弃旧权重从头训且不蒸馏继承 | 能力断层，等于重开 |
| 词表写死、不留扩展位 | 以后加字/加词无处可放 |

### ✅ 保持开放的设计（强制）
- 词表**尾部预留扩展空间**（append 制，旧 id 永不变）
- 层数可加（**零输出恒等层**，保函数）
- MLP 可加宽（**零填充**新行，保函数）
- 记忆槽可加（新模块**零输出初始化**，保函数）
- **用户记忆空间独立于主干**，可增删、可换人，不动主干一个参数
- config 保留扩展字段

> 规律：**所有"加"都用零初始化/零输出，起步即恒等，不破坏已学函数。**
> 这跟"加词表不是换词表"是同一条原则。

### ⚠️ 手册矛盾1 收口：模块插入分支（2026-10-14）
执行手册（execution_manual.md §7 矛盾1）指出：过了压缩最优点 N\*（≈0.2B–0.4B）后，Gate 1（plateau 三分类）会把每一个 plateau 判为"数据受限"，从而**永久否决参数扩容**——"学满 plateau 再扩"在 0.4B 后会自动变成"永不扩容"。
⇒ **本宪法（参数扩容：MLP 加宽 + 零输出恒等层）保持不变；另立一条平行规则：当 Gate 1 判数据受限 / N>N\* 时，切换为「能力模块插入」，而非继续放大参数。** 模块插入的合法项：词表 append（0.4B，P2 保 logits 逐位不变）、认主对比头（0.4B）、记忆层（0.5B）、蒸馏桥接（0.5B 架构重置）。这条分支必须在 0.4B 之前就写进规则，否则路线会在 0.4B 停住而无人知晓原因。

## 一、逐级夯实，不一步登天

**"0.1B、0.1B 慢慢夯实上去，而不是直接起步拿个多大的——那种初期需要的知识太大，每一步都规划不好、夯实不好，等于境界虚浮。"**

### 数据量验证（用户判断 = Chinchilla 实测吻合）

| 项 | 数值 |
|---|---|
| Chinchilla 最优 | **20 token / 参数** |
| 每 +0.1B 参数 | → 需 20 亿 token |
| 换算（加词表后 1 GB 中文 ≈ 4.56 亿 token） | **≈ 4.4 GB** |

⇒ **用户说的"每加 0.1B 就要几个 G 的资料"，精确对上。**

### 学术对应（我们不是野路子）
- **Net2Net**（Chen et al. 2015）：函数保持的网络变换 —— 正是我们 0.2B→0.3B 的做法
- **Progressive Stacking**（Gong et al.）：逐层堆叠增长
- **Qwen3 强到弱蒸馏**：小模型不从头训，继承大模型的推理能力

### 阶梯
```
0.1B → 0.2B(已跑) → 0.3B(排队) → 0.4B(词表+我们的资料+认主) → 0.5B(融合版)
                                  每级：先学满 plateau，再扩
```

> 📌 **N\* 定位（执行手册 §4.1.2）**：按"压缩即模型"判据，现有 3.5B 语料下三值口径最优点 N\*≈0.2B–0.4B（fp16-embed 口径 193M；三值名义 1.58 口径 411M）。**0.4B 即分水岭——它是现有语料支撑的最后一级参数扩容**；1B 需 3.3× 语料、3B 需 14×、8B 需 53×。0.4B 之后一律走「补数据 + 插模块」二选一（见 §零 模块插入分支）。

## 三、效率：BitNet b1.58（几乎为我们量身定做）

| 指标 | BitNet b1.58 2B | 4-bit | 全精度 |
|---|---|---|---|
| 内存 | **0.4 GB** | 1.2 GB | 6.0 GB |
| CPU 延迟/token | **15 ms** | 28 ms | 120 ms |
| 能耗 J/1K token | **0.5** | 1.8 | 8.2 |

- `bitnet.cpp`（微软开源）：x86 CPU **加速 2.37~6.17×，能耗降 72~82%**
- iPhone 14 PM 上 0.7B 跑 **45 tok/s**（~200 MB）；骁龙 8 Gen 3 上 1.3B 仅 **65 MB RAM**
- **CPU-first，GPU 反而不优化 1-bit** ⇒ 与我们"免费 CPU 算力 + 本机 CPU 部署"完全契合

### 🔑 "从头训 vs 继承"的冲突解法
BitNet 必须原生 QAT 从头训，与"继承不重来"看似矛盾，实则能拆：
- **架构层：从头**（BitNet 强制）
- **能力层：继承**（0.4B 强到弱蒸馏给 0.5B）

= BitNet 原生 QAT + Qwen3 强到弱蒸馏的组合。

### ✅ 已验证（2026-10-14，实测非推测）

脚本：`eval/trinet_probe.py`（解析级）+ `trial_1h.py`（20M 代理模型实跑）。
判据：扩容前后同一 holdout 的 CE 跳变。

| 扩容动作 | fp32 | 三值 b1.58 | 判定 |
|---|---|---|---|
| **加零输出层 / 加整个 Block**（深度方向） | 0 | **0** | ✅ 完全兼容 |
| **MLP 零填充加宽**（宽度方向） | **0（严格保函数）** | **+1.70%** | ❌ 有扰动 |
| 分块 γ（旧块新块各自一套缩放） | — | **0** | ✅ 可修 |

**根因**（可解析，不靠猜）：三值量化是 `y = round_clip(W/γ)·x·γ`，其中 **γ = mean\|W\| 是全局标量**。
加宽时补零行/列 → 权重总数变多但 `sum\|W\|` 不变 → **γ 被稀释**（实测 0.01595→0.01367）
→ 所有**已有权重**的量化步长同时改变 → `round()` 结果系统性翻转 → 旧函数被改。
注意：**复制式(replicate)加宽也救不了**，它保住的是 `sum\|W\|` 不是 `mean\|W\|`（T4 实测同样 FAIL）。

### 🔧 两个解法（都不牺牲三值的效率）

**解法 A（推荐）——扩容发生在 fp32 潜权重上，三值只做推理表示。**
BitNet QAT 本来就有 fp32 潜权重 `W_latent`（前向量化、反传 STE 直穿）。
Net2Net 加宽只改 `W_latent` → **fp32 层面严格保函数** → 之后继续 QAT 训练即可。
三值化是每次前向临时算的，扩容后重新量化是**既定行为**，不是破坏。
代价：扩容瞬间推理函数会变（实测 +1.7%），需要一小段恢复训练 —— 而 Net2Net 本来就要继续训。

**解法 B——分块 γ。** 权重矩阵按"扩容世代"分段，每段独立 γ。
实测跳变 **0.0000**，严格保函数。代价：实现上多存一个分段表（几十字节）。

### 📌 修正后的结论

> 之前的判断「任一不成立 → 不用 BitNet」**过于绝对，予以撤回**。
> 三值与「不封死」**不冲突**：深度方向零成本，宽度方向换 A/B 任一解法即可。
> **0.5B 继续按 BitNet b1.58 规划。**

### 🔑 embedding 量化决策（手册矛盾3 收口，2026-10-14）
**决定：embedding 与 lm_head 保持 fp16，不三值化。** 0.5B+ 阶段记账口径 = 三值权重(1.58) + fp16 embedding ⇒ b_eff≈5.5，N\*≈**193M**（取此最现实口径，不用 1.58 名义的 411M 做决策）。
理由：
1. 照搬 BitNet b1.58 原配方（原文 §3 «the embedding remains full precision»，已全文核验）；
2. 规避 0.4B 中文 token「均值初始化」在 0.5B 三值化时的"低范数→logits 天然小"与 lm_head 目标冲突；
3. 我们 CPU-first，embedding 是 lookup 非 compute-bound，fp16 不增计算量，仅增存储（0.5B 下 ≈56MB，端侧常驻可接受）；
4. 与"最小内存最快速度"目标差 ~40MB，可接受。

### ⚠️ 仍待验证
1. **扩容后能否训回** —— +1.7% 的跳变是否只是瞬时扰动（待跑：加宽后续训 N 步看 CE 是否回到加宽前）
2. **后训三值化不可行** —— 随机权重三值化误差达 58%（标尺），说明绝不能拿现有 fp32 权重直接压成三值，必须 QAT 从头训
3. node1 免费 64 核从头训 1-bit 能撑到什么规模

## 四、10M 个人记忆：夯进向量空间

**前提**：10 MB 绝不能进上下文 —— 我们 1024 token（加词表后 ≈750 汉字）装不下。

### 三层设计
| 层 | 大小 | 作用 | 技术 |
|---|---|---|---|
| **user embedding** | 几 KB，常驻上下文 | **认出你** | triplet 对比损失（人脸识别同款数学） |
| **记忆库** | ~10 MB | **记得你的事** | 原文片段 + 向量索引，用时检索（本地知识库思路） |
| **user adapter** | 参数化 | **像你说话** | 个人风格的参数化 |

### 容量换算（576 维）
| 精度 | 每条 | 10 MB 可存 |
|---|---|---|
| fp32 | 2,304 B | 4,340 条 |
| fp16 | 1,152 B | 8,680 条 |
| int8 | 576 B | 17,360 条 |
| 原文 | — | ≈ 333 万汉字 |

若改用**三值存储**：10 MB ≈ **5060 万参数**（80 Mbit ÷ 1.58），是 fp32 的 **20 倍** ——
用户记忆容量极其奢侈。

> 用户原话："最近我看本地知识库相关的，可以把它夯进向量空间之类的。"
> ⇒ 主路线走**向量库**（可增量写入、无需训练），参数化 adapter 作为增强层。

---

### 🔑 记忆层数据政策（手册矛盾4 收口，2026-10-14）
**决定：个人数据可删除 = 硬需求（0/1 判据）。**
- **选型限**：外置可寻址记忆（Memory Layers 式：key/value 是可训练参数，删除=删一条目、不触权重）＋ user embedding ＋ user adapter。
- **明确排除 Titans 式**（测试时在线把数据写进自身参数）：其删除演练（写→删→查权重）必然失败，与用户「个人数据删除权」红线不可调和，选型阶段即用 0/1 判据淘汰，不上线后补救。
- **删除演练**作为 Gate 7（记忆层）前的硬性门：写一条→删一条→查记忆/查权重/重训撤销，不通过即淘汰方案。
- **数据住哪**：原始个人数据只住外置索引（记忆库），绝不直接写进 adapter/主干权重；adapter 只学通用风格映射（可参数化但不承载原始个人数据）⇒ 删除权针对外置索引即可成立。
- 与用户红线一致：个人数据绝不出境（云端只跑公开信源），记忆是本地端侧常驻。

## 六、自进化（RSI）落点顺序

1. **代码层自修改**（最现实，已有雏形）：`chain_v1.sh` 热升级 + 看门狗 → 模型自己改进训练脚本

### 8.1 三条统摄规则（报告新立，原清单没有）
- **L1 压缩准入规则**：模块也要偿付自身体积——`ΔH_saved > N_m·b_eff·ln2`；完整形式是偏导判据 `|∂ℓ_data/∂B_model| ≤ 1`。**把「插模块」与「放大参数」放进同一把尺子**，过 N\* 后插模块需过此关。
- **L2 信息天花板**：自蒸馏只提升对固定语料的压缩效率，不提升语料本身信息量 ⇒ **RSI 能力上限 = 语料相对模型先验的可压缩信息量**（可算的符号/零点，绝对值缺 H_raw）。宪法③「进化即存在」由此变为**有上限的量**。
- **L3 通道分离**：删除权是**架构期**约束（切断记忆→主干梯度，删除才成定理），不是删除期操作；蒸馏是**绕过架构的信息通道**。

### 8.2 深度优先 = 唯一严格保函数扩容方向（升级原经验结论）
报告 §4.2 修正了咱们「分块 γ 跳变 0.0000」的解法 B：宽度扩容在共享/分组 α 下**不可能严格保函数**——除零填充稀释外，**Net2Wider 的 1/r 缩放**让新进入统计量的不是零而是「旧值÷r」，任何对含新增坐标求统计量的 α 方案（逐张量/块/行/通道）都不可能精确，只能减小跳变。严格保函数充要条件是**冻结旧坐标量化决策 + 新增坐标用独立 α 组**。
⇒ 结论升级：**扩容主轴默认选深度（插零输出恒等层），宽度仅在机制可解释性给出「某层饱和」证据时用**。宽度还会改 hidden 维→认主头必须同步加宽→再触发一次量化扰动；深度无此问题。

### 8.3 subliminal learning 挑战 P3（⚠️ 待 E1 实验裁决，不可静默改写）
报告 §3.8：0.4B→0.5B 是「同族教师-学生 + 教师生成数据」= subliminal 效应**最强构型**。0.4B 的窄微调痕迹/过拟合会**无声进入 0.5B，只看输出行为检测不到**。
⇒ 这直接冲击咱们已决的「0.5B 架构从零 = 新模型 / 能力层蒸馏继承」。**处置**：不立即改写 P3，先跑 **E1 双盲属性传递测试**（node1_minimal_experiments.md）：给 0.4B 注入冷门癖好→蒸馏 0.5B→测出现率；若 TREAT−CTRL ≤ 2σ 则 P3 保留，否则 P3 必须改写且蒸馏桥接加「分歧 token 门控」。E1 成本极低（一次 0.1B 级蒸馏），**排本周实验第一**。
⇒ **附带矛盾自曝**：data-plan §8「0.5B 前 AI 池零掺」在 0.5B 蒸馏节点会**自动失效**（蒸馏本身就是 AI 数据进主干）。报告建议改措辞为「主干预训练数据加载路径在 0.5B 之前不得含模型生成数据」，须显式消除此歧义。

### 8.4 N\* 完整表 + 小模型嵌入决策更关键
三值权重+fp16 嵌入口径（b_eff≈5.185）：现有 3.5e9 语料下 N\*≈202M，恰好压在 0.2B 里程碑。**让 N 成为最优点所需语料**：1B=29.9B(×8.5)、3B=130.2B(×37.2)、8B=484.5B(×138.4)。
新洞察：混合口径相对纯三值的偏移**在小模型上更大**（小模型嵌入占比高）→ **0.2B 附近「是否把嵌入也三值」的决策比 8B 时更重要**（与直觉相反）。**这不改咱们「embed 保 fp16」的拍板，但提示该决策的相对权重在 0.2B 处最高**。

### 8.5 记忆层改为双层 + 删除契约 DC-1..4（细化原有设计）
- **Tier-E 会话级**（TTT 式梯度更新，会话结束即消失 ⇒ 删除权天然满足）+ **Tier-P 持久层**（外置可寻址键值库，删除地址=bit-exact 回到无记忆）。同时拿到 Titans 式测试时适应与可删除。
- **DC-2（关键）**：记忆损失→主干的梯度贡献恒为零（参数 mask 强制）。满足时 DC-3「删除后输出逐位等于从未写入」是**定理而非经验**；不满足则退 certified unlearning。代价：记忆层永远不能改善主干，要提升主干能力得走蒸馏（§8.3 桥接），两件事被报告厘清。

### 8.6 IDENTITY-R 比较器（省工程）
报告 §13.9 形式化：「不分裂」↔「限制映射相等」↔「保函数（P2 退化义）」是**同一判据**（旧定义域逐位一致）。⇒ 只需实现一次限制映射比较器，**同时服务架构验收（§5）与身份验收（§13.1）**。

### 8.7 RoPE 长上下文路径（不破宪法）
报告 §5.1：宪法「禁改 RoPE」只在训练长度**以内**成立；对 `n ≥ L_train` 的位置，保持所有旧 θ 不变、只对新位置做部分插值（路径 A），旧位置逐位不变 ⇒ 保函数成立，旧记忆不被打乱。另一条更省的路：若需求是「用很久以前的信息」而非「处理长序列」，外置记忆（§8.5）比改 RoPE 便宜且不违宪。

### 8.8 其他已核验要点（索引，详见报告）
- §4.6 Grokking 会污染 Gate 1：训练降/验证停 = 容量受限特征，与 grokking 完全重合 ⇒ Gate 1 判「容量受限」前须先排除「优化受限+跃迁待发」（条件 G：延长 ≥5× + 退火重启）。
- §11.1 Schaeffer 反例：所谓涌现 92% 是度量选择造成 ⇒ 小模型+小评测集必须用连续指标，验收用「能力地板连续量」而非阈值。
- §10.2 混合精度稀释三值加速：嵌入查表不享三值内核加速，端侧实测加速远低于 2.37× 下界 ⇒ 须实测（F10-2，决定 CPU→GPU 拐点方向）。

### 8.9 三值 QAT 失败预警清单（Grok Q-04 采纳，0.5B BitNet 训练监控项）
训练循环必须每 N 步记录以下信号，任一触发即暂停并诊断：
1. **激活方差爆炸**（逐层激活方差偏离基线 >3σ）；
2. **scale 因子剧烈抖动**（absmean γ 相邻窗口变化 >30%）；
3. **loss 平台后突然发散**；
4. **shadow fp16 权重与三值权重的余弦相似度持续下降**（梯度与量化方向脱钩）。
最小防御配置：LayerNorm 前置 + absmean 量化 + 适度 weight decay。
失败判据：同 token 预算下三值 PPL 比 fp16 差 >15% 且无法用加深补偿 ⇒ 该规模三值失败。
⏳ 0.5B 前先在 214M 跑 50–100 步三值探针验证信号管线。
⚠️ 附注（E1 实测教训同步）：蒸馏门控的分歧度量已从 KL 换成 **JSD**（KL 阈值随词表/峰度漂移不可移植），见 `eval/distill_gate.py`（自检通过）。

## §十·二 V1-01 交叉裁决：三值 CPU 路径已改（2026-10-14）

三模型(gemini-3.8-flash/grok-4.7/cohere-north)独立交叉 V1-01，裁决全文见 `docs/netarch/v1_01_verdict_ternary_cpu_20261014.md`。

- **一致结论**：STE 梯度噪声是 CPU 三值 QAT 首要瓶颈（非算力、非带宽）。
- 🔴**推翻原方案①**：CPU 从零预训练 0.5B 三值物理不可行（gemini 定量：~3.5B tokens≈1.05e19 FLOPs≈120天满载）。
- 🔴**推翻原方案②「冻结fp32主干+float16影子Adapter QAT」**：三值无法无损吸收浮点Adapter，留到推理则内存同FP16⇒**必然击穿15ms/token**。Adapter 只能作训练期残差且须退火到0。
- ✅**新采纳路线**：0.4B FP16 → Net2Net 深度优先扩容至 0.5B 深窄 → 作 Master Weights 继承 → CPU 小样本(50M~100M tok) **渐进残差退火 QAT**（α:1→0，推理纯三值）。
