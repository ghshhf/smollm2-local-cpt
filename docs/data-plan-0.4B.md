# 0.4B 数据方案（定稿 2026-10-14）

**定位**：0.4B 是分水岭 —— 加中文词表 + 注入咱们的资料 + 认主。
**前提**：0.3B 及以前的链路不动（"不要修改过去的"）；词表是**加**不是**换**。

---

## 一、词表扩展（必须先做，它影响后面所有数据）

| 项 | 决定 |
|---|---|
| 加什么 | 8105 常用字 **＋** 词频 top 30,000 词 |
| 怎么加 | 旧 48,843 token **一行不动**，尾部 append；token id 全不变 |
| 新行初始化 | **该词在旧词表下各子词 embedding 的均值**（Chinese-LLaMA 同款），**禁止随机初始化** |
| 参数增量 | 576 × ~38,000 ≈ **+21.9M**（214M 的 10%） |
| tied lm_head | 同步扩或改 untied |
| 实测收益 | token/字 2.4589 → **1.3684**（省 44.3%），1024 上下文装 417 → **748 汉字** |
| ⚠️ 副作用 | **全部语料必须重新分词**，cache .npy 重算（与新语料一起做，别分两次） |

> 顺序不能反：字表是收益主体（单独加就省 42%），词表是边际（再 +2.3pp）。
> 词加到 6 万只多 0.7pp，**3 万封顶**。

## 二、总盘目标

| 项 | 数值 |
|---|---|
| 目标总量 | **35 亿 token**（≈ 8 GB 文本） |
| 现有 | 12 亿 token（2.7 GB） |
| **需补** | **约 23 亿 token ≈ 5 GB** |

> Chinchilla 最优是 80 亿（20×参数），我们取 35 亿是因为**继承续训**而非从头训，打个折。
> 换算口径：加词表后 1 GB 中文 ≈ 3.3 亿字 ≈ **4.6 亿 token**。

> 📌 **epoch 策略决策（手册矛盾7 收口，2026-10-14）**：0.1B–0.4B 阶段**默认单遍（epoch≤1）**，执行手册 §4.1.3 的 D_needed 数字即为本阶段终值（D_needed(0.4B)=3.4B ≈ 现有 3.5B，单遍够）。0.5B 之后一律走「补数据 + 插模块」二选一；**多 epoch 重复采样仅作受控例外**（须先跑 P7/P16 尾部 NLL 监控：替换>重复采样>累积），不常态、不默认。
> 注：本方案「咱们的资料 upsample 4×」属**认主度量学习的局部受控重复**（仅 2% 份额、每域 epoch≤4，社区 SLM 实测上限），非全量多 epoch 重复采样，与上方决策兼容，不冲突。

| 板块 | 占比 | 来源 | 需补 |
|---|---|---|---|

| **创意·文章** | 8% | 见下 | 0.5 GB |
| **创意·文案** | 7% | 见下 | 0.5 GB |

**两条硬约束：**

- **创意型合计 15%，但预训练段只给到这个数就停**。业界的实际做法（SparkMuse 1.7 亿 token、WritingBench 1.2 万条）证明**主战场在 SFT，不在预训练堆比例**。
- **"咱们的资料"只能到 2%，且 upsample 上限 4×**。社区实测每域 epoch 上限约 4 轮，超了收益急剧下降（原计划 50× 已废）。份额不够的部分**靠度量学习目标（ArcFace + in-batch 负样本 + 难负样本挖掘）补，不靠堆量**——这正是人脸识别用几千条样本就能分辨几千人的原因。

### ⚠️ 完整作品层（不切碎，占总量约 15%）

**从上述各类中抽取短篇（≤700 汉字），保留不切。**

理由（学 Claude Artifacts）：artifact 的判定标准是"能脱离对话独立成立、用户会修改复用"——**它产出的是完整成品，不是片段**。我们的语料全是 512 chunk，模型只学过"接着往下写"，没学过"从头到尾完成一件作品"（开头定调—中段发展—结尾收束）。

加词表后 1024 token ≈ 750 汉字，已装得下完整短文/文案/脚本。**这是唯一能用少量数据换到"整体感"的办法。**

### 两个坑（已踩过一个）
- **模板化**：曾退化到反复输出"你是一位小说写手…"⇒ 网文占创意类 **≤20%**，设上限
- **质量稀释**：低质网文教口水话 ⇒ **不自己写过滤器**，直接用已过滤的 Ultra-FineWeb-zh

## 五、咱们的资料（2% + 度量学习）

> 2026-10-14 修订：upsample 由 50× 降到 **4×**，认主手段由朴素 triplet 改为
> **ArcFace 角度间隔 + in-batch 负样本 + 难负样本挖掘**（人脸识别的现代做法）。

| 项 | 内容 |
|---|---|
| 语料 | `owner_corpus/owner_corpus.jsonl` 5,146 条（1.6 MB）＋ 小说设定 ＋ 会话存档 |
| **upsample** | **4×**（原 50× 已废，见下） |
| 位置 | **压在训练末尾**，靠 recency |
| **主手段** | **ArcFace 监督式角度间隔**（不是朴素 triplet） |
| 目标 | "主人 vs 他人"嵌入余弦间隙 ≥ 0.3，ROC-AUC ≥ 0.95 |

### 5.1 为什么 upsample 从 50× 砍到 4×

社区 SLM 数据工程的实测结论：**每个域的 epoch 上限约 4 轮，超出后收益急剧下降**，
再往上堆基本是纯死记硬背，不产生泛化。50× 远超拐点。
且我们真正的目标是"认出风格"，不是"背下说过的话"——背诵反而会让它复述而不是识别。

### 5.2 认主改用 ArcFace（人脸识别的现代做法）

朴素 triplet 的问题：要专门备"他人"负样本（我们一直缺）、pair 组合爆炸、训练不稳。
改用三项组合，全部是人脸识别里验证过的东西：

1. **ArcFace 加性角度间隔**——在余弦角度上加一个 margin `m`，把决策边界推开。
   比 triplet 收敛更稳、小样本（几千条）下明显更好，且**直接给出可度量的余弦间隙**。
2. **in-batch negatives**——同一个 batch 里的其他文档天然就是负样本，
   **不用专门准备"他人"语料**，解决了遗留的"负样本待备"问题。batch 越大负样本越多，
   恰好我们正要调大 batch（见 `docs/cloud-training-spec.md`），一举两得。
3. **难负样本挖掘**——最容易误判的不是随机语料，而是**风格最接近主人的文本**
   （例如助手自己的输出、模仿用户口吻的回复）。专门把它们挖出来当 hard negatives，
   这是把"余弦间隙"从 0.1 推到 0.3 的关键。

### 5.3 容量核算（还是那个人脸识别的类比）

人脸识别 128 维嵌入能分辨几千人。我们的 user embedding 用 hidden=576 维：
- fp32 = 2.3 KB / 人；**三值 = 0.14 KB / 人**
- 10 MB 个人空间若走三值，可存约 **5,000 万参数**级别的记忆，fp32 只有 250 万

> 关键：认主**不靠语料量，靠度量学习目标**。5 千条样本 + 正确的损失函数就够了。

## 六、训练编排（五步）

1. **加词表** → 全部语料重新分词
2. **冻结主干**，只训新增 embedding（均值初始化）
3. **全放开**，继续吃知识语料
4. **注入咱们的资料**（upsample 后压末尾）
5. **lr 衰减 + 训认主对比头**

> ②③⑤ 这三段的节奏，正是 Naive-N0.5-Flash 的「先 KL 对齐新组件 → 放开 → 衰减」三段式。

## 八·五、ClawsGO 报告补充（2026-10-14 追加）

> 来源同 vision §八。以下为对 0.4B 数据方案的具体修订/补充，均已在报告核验。

### A. 多 epoch 单遍决策的操作化（强化原 §4.1.3 单遍终值）
报告 §8.1：固定语料多遍重复**不注入新统计噪声**，故不触发 Shumailov 坍塌，危险是「过拟合到语料特殊性」。且**同语料 holdout 检测不到**（模型向经验分布收敛时同语料 holdout 一直改善）。唯一有效检测器是**外部 holdout**（与训练语料不同来源的真实数据）。
判据 RPT-1：每遍末测 `Δ_in`(同语料) 与 `Δ_out`(外部)；`Δ_out` 连续 2 遍上升 >σ ⇒ 停止重复或降权。**⇒ 必须先造一个与训练语料独立的中文外部集，否则多 epoch 安全性在本路线永远无法判定**——列为最高优先级基础设施。

### B. σ 标定（Gate 0 底座）
报告 §8.5：`σ ≈ s/√n_items`，且**中间能力处 σ 最大**（接近饱和或随机时方差小）。建议每代用 **bootstrap 1000 次重采样**取 2.5/97.5 分位半宽为 σ，每个 Gate 放行前重跑（不能只在 Gate 0 标一次）。最小可分辨效应 MDE ≈ 2.8σ（按验收标准调）。

### C. 蒸馏桥接 + 分歧 token 门控（接 vision §8.3 的 P3 挑战）
0.5B 蒸馏管线（报告 §8.2）：① 教师只在公开语料生成、温度稍高；② **分歧 token 过滤**（教师 top-k 与更早/更小教师的分歧位置降权/mask，这是 subliminal 通道的已知门控）；③ 学生先硬标签热身再软标签(KL/JSD)；④ 传递检测走 F3-8 双盲。
**规则改辞（消除歧义）**：原「0.5B 前 AI 池零掺」改为**「主干预训练数据加载路径在 0.5B 之前不得包含任何模型生成数据」**——因为 0.5B 蒸馏节点会不知不觉越线，须显式写清。

### D. 留出集独立性是持续维护状态（B2，单点故障）
报告 §12 B2 / §3.2：留出集独立性在 RSI 闭环与多代蒸馏下**会持续退化**（任何一次数据管线改动都可能让留出集变训练集）。须建**留出集指纹机制**（内容哈希 + 使用计数 + 与训练语料 n-gram 重叠监测）。数据加载器配置须纳入锁定集（模型改不了加载器，否则所有 Gate 失效）。

### E. 解码策略与身份耦合（B8，需消融）
身份判定（认主余弦间隙）、风格一致性、是否「同一模型」的观感都依赖采样温度/解码策略。同一权重集在不同温度下可像不同模型 ⇒ 身份验收须固定解码协议，或测跨温度稳定性（F 未定，列为待消融）。

### F. 多 epoch 在线信号（Grok Q-08 采纳，矛盾7 的实时监控）
外部 holdout（条 A）是事后判定；训练期内用以下在线信号实时区分「学习 vs 死记」：
1. **梯度噪声范数 / 信噪比（GSNR）**：噪声变窄+信噪比升高 ⇒ 开始记忆化；
2. **参数漂移速率**（相邻 checkpoint 的参数位移）；
3. 层间 CKA 表示相似度。
判据：在线信号与外部 holdout 记忆率相关性 <0.5 ⇒ 该信号无效。**⏳ 实测**：0.4B 第一遍 epoch 尾部开始每 100 步记录上述信号。

## 八·五·二 Q-08 交叉裁决：epoch 在线判据 = 梯度余弦对齐度（2026-10-14）

矛盾7 补充：多 epoch 的**训练时实时**判据已由 gemini+nemotron 独立收敛给出（强趋同），全文见 `docs/netarch/q08_verdict_epoch_signal_20261014.md`。

- **采纳信号 = 梯度方向一致性（梯度余弦相似度）**：gemini 用 `cos(g_t, AdamW动量m_{t-1})`（CMA），nemotron 用 token-wise `cos(g_t, g_{t-1})`（TGCSM）——数学同源。
- **机制**：泛化期梯度与历史方向共识（cos>0.15~0.40）；记忆期趋正交（cos→0）甚至对抗（cos<0）。
- **排除**：参数漂移率（滞后指标）、单样本 loss 方差（随语料漂移）、loss 曲率（CPU 信噪比低）、GSNR（单遍下退化/需存全梯度历史）。
- **双门限 Early-Stop**：以 epoch1 末期 CMA 均值 Ā 为基线，`EMA(CMA)<0.3Ā` 进警戒；`EMA(CMA)≤0.02 且 P(CMA≤0)≥0.45` 立即停止 epoch2。
- **CPU 可行**：不开反向额外 FLOPs，一次内积+范数归约，1.5~4.5ms/步，开销<1%，可训练内嵌。
- ⏳ 待实测：0.1B/0.2B 实跑 epoch2 验证 CMA 是否真在记忆期趋0。
