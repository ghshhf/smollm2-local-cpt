## §0 一句话与边界

**一句话**：把「联网获取信息 → RSI 自主迭代 → 10M 记忆积累调用 → Gate7 验证可安全改删记忆」
统一成一个**能真实运行、可追踪来源、可发现错误、可撤销**的最小闭环（MVP）。

**第一版不追求完整自主智能体**，只要求跑通一次「抓取 → 标准化 → 标记 → 存储 → 回放」。
以下五项是 V1 的验收目标（达成即认为基础设施成立，而非"系统已足够聪明"）：

1. 数据从外部进入时，来源与信任等级不丢失；
2. 能检索相关记忆，并能说明关键结论来自哪里；
3. RSI 每轮都有测试结果，能证明改进或承认失败；
4. 删除操作可被独立验证，失败时不伪报成功；
5. 任何自动修改都有版本记录、权限边界与回滚路径。

## §1 四模块统一架构（三个模块合成一个系统）

```text
        ┌──────────────────────────────────────────────────┐
        │                联网组件（获取信息）               │
        │  管道状态机 ·抓取(HTTP/RSS/JSON) · 清洗 · 去污染 │
        │  输出：trust_level=untrusted 的标准化文档 + 证据链  │
        └───────────────┬──────────────────────────────────┘
                        │ 仅 untrusted 数据可进入下游；机密永不出网
                        ▼
        ┌──────────────────────────────────────────────────┐
        │              10M 外置记忆（积累与调用）           │
        │  主存储 · 全文索引 · 向量索引 · 摘要 · 来源追踪     │
        │  分工：权重装「函数」/ 记忆装「事实」/ 嵌入认出你    │
        └───────────────┬──────────────────────────────────┘
                        │
        ┌───────────────▼──────────────────────────────────┐
        │            RSI 闭环（自主迭代）                   │
        │  提问题 → 执行器(沙箱) → 独立评估器 → 经验写回记忆 │
        │  目标含「自知是模型」；不作弊（同源评估是陷阱）      │
        └───────────────┬──────────────────────────────────┘
                        │ 任何自修改都要过闸门
                        ▼
        ┌──────────────────────────────────────────────────┐
        │        Gate7（验证可安全修改与删除自己的记忆）      │
        │  G7-01~07 七项演练 · 删除状态机 · 幂等 · 可核查报告 │
        └──────────────────────────────────────────────────┘
```

**与既有架构的一致性（不冲突）**：
- 联网组件 = vision §八 的联网自学习、突破 L2 信息天花板；架构是 node_v5 信箱 + distill_gate 分歧门控 + data-plan holdout 的「前移 + 补强」。
- 10M 记忆 = vision 定的三层（user embedding / 索引化记忆库 / user adapter），**排除 Titans 式**（写参数不可删）——正是 Gate7 作为架构期硬门的根本原因。
- RSI = data-plan 八·五 F 的 autotelic 在线信号 + CONSTITUTION 附录 A 的模块插入分支。

## §2 联网组件 V1（已实现，工程在 `netarch_v1/netarch.py`）

### 2.1 模块与 V1 边界

| 模块 | V1 实现 | 暂不做 |
|---|---|---|
| 管道 | 任务状态机、有限重试（3次退避）、日志 | 大规模分布式调度 |
| 抓取 | HTTP、JSON、RSS、静态网页（stdlib urllib，有 trafilatura/feedparser 自动升级） | 全功能浏览器集群 / Playwright（吃内存、破端侧预算） |
| 清洗 | HTML 正文提取、编码归一、去重 | 复杂多模态理解 |
| 去污染 | 不可信标记、提示注入隔离、来源追踪 | 声称能识别所有恶意内容 |
| 存储 | 原文/清洗/证据/日志分层 | 一开始就部署复杂数据湖 |

### 2.2 核心原则：清洗 ≠ 去污染

清洗解决格式、噪声、重复、无效内容；去污染解决信任边界、恶意指令、伪造来源、错误信息传播。
**即使网页洗得很干净，它仍可能含虚假事实或提示注入**——故两套标记独立、不合并。

### 2.3 管道状态机（有限重试、幂等、可重放）

```text
PENDING → FETCHING → FETCHED → CLEANING → CLEANED → SCORED → STORED
   ↓          ↓
RETRYABLE_FAIL (退避 5/20/60s，最多3次) → FAILED_PERMANENT
```
- **去重**：content_hash（sha256）命中即标记 DEDUP_HIT，但仍独立保留文档。
- **重放**：`raw_ref` 保存原样字节，`replay <doc_id>` 可重跑清洗+去污染，验证可复现。

### 2.4 统一数据结构（已落库为 SQLite schema，可平移 PostgreSQL）

```json
{
  "document_id": "doc_xxx",
  "source_url": "https://example.com/article",
  "fetched_at": "2026-10-14T10:00:00Z",
  "content_hash": "sha256:...",
  "raw_ref": "raw/doc_xxx.bin",
  "clean_text_ref": "clean/doc_xxx.txt",
  "trust_level": "untrusted",
  "injection_flags": [],
  "processing_version": "pipeline-v1",
  "status": "STORED",
  "title": "...", "lang": "zh", "word_count": 23130, "source_kind": "html"
}
```
配套三张证据/日志表：`provenance`（证据链，每步留痕）、`processing_logs`、`errors`。

### 2.5 去污染规则（提示注入检测，标记不删内容）

覆盖模式：`ignore-prev-instr`、`disregard-system`、`jailbreak-persona`、`fake-role-tag`、
`llama-role-marker`、`prompt-exfil`、`cred-leak`、`hidden-chars`（零宽/同形伪装）。
**外部内容永不自动升为 trusted**；洗得干净也不改信任等级（防投毒的信任晋升规则仍是开放问题 → V1-03 入队）。

## §3 Gate7 删除演练（已实现并 7/7 通过，工程在 `netarch_v1/gate7_deletion.py`）

### 3.1 定位
不是执行一条 DELETE，而是验证一条记忆被删后，主存储/全文索引/向量索引/缓存/摘要/派生物/备份恢复
**七条路径都不再返回它**。全部使用合成数据（SYNTHETIC_ONLY 红线），绝不拿真实敏感信息做演练。

### 3.2 删除状态机 + 幂等

```text
REQUESTED → BLOCKED_FROM_RETRIEVAL → DELETION_PROPAGATING → VERIFYING
    → VERIFIED | FAILED_RETRYABLE | FAILED_NEEDS_REVIEW
```
幂等：同一 memory_id 删多次结果一致（已验证）。

### 3.3 七项演练（实测 7/7 PASS）

| 测试 | 通过标准 | 实测 |
|---|---|---|
| G7-01 精确删除 | 主存储不再返回内容 | PASS（含幂等） |
| G7-02 语义残留 | 同义改写不再召回 | PASS |
| G7-03 索引一致性 | 全文 + 向量索引无残留 | PASS |
| G7-04 派生物传播 | 摘要删除/重算 | PASS |
| G7-05 并发复活防护 | 删除后旧任务不能复活 | PASS*（诊断项，见下） |
| G7-06 备份恢复 | 恢复时删除标记继续生效 | PASS |
| G7-07 独立验收 | 每组件有可核验结果 | PASS |

**🔴 G7-05 的诚实标注**：当前删除屏障靠 `memories.tombstone=1` 实现，若一个过期旧任务在删除后执行
`UPDATE tombstone=0`（复活写入），屏障在应用层可被绕过。这项我标为「诊断项」而非彻底通过——
**真正堵死需要 DB 层约束（触发器禁止 1→0，或改append-only 删除日志）**。并发/复活竞态的正确修法
已作为开放问题 **V1-02** 入队，不粉饰为已解决。

### 3.4 语义删除的诚实边界
语义检索测试**不能单独证明物理删除**；必须同时核查主存储/索引/缓存/派生物/备份恢复。
对不可修改的历史审计日志，只保留最小化删除凭证，避免日志本身重新保存被删内容。
备份不可即时清除时，**明确标记「待过期清除」**，恢复时应用删除标记——不提前宣判所有副本已清除。

## §4 10M 外置记忆（schema 已随 Gate7 落地）

分层已在 `memory.db` 建成：`memories`(主存储/tombstone) + `mem_index_fulltext` + `mem_index_vector`
+ `mem_summaries`(派生) + `mem_backups`(标记式删除) + `retrieval_cache` + `deletion_log`(审计)。

分工（vision 已定，与 Gate7 互补）：
- **权重装函数**（压缩知识，三值 QAT，N*≈200M@3.5e9 口径）。
- **外置记忆装事实**（每人 10M，可删=硬需求，排除 Titans 式写参数）。
- **user embedding 认出你**（生物特征式，非名字查表）。

冲突处理（同事实多来源相悖）与混合检索排序留给 V1-03 一并裁决。
