§0 一句话与边界

一句话：把「联网获取信息 → RSI 自主迭代 → 10M 记忆积累调用 → Gate7 验证可安全改删记忆」 统一成一个能真实运行、可追踪来源、可发现错误、可撤销的最小闭环（MVP）。

第一版不追求完整自主智能体，只要求跑通一次「抓取 → 标准化 → 标记 → 存储 → 回放」。 以下五项是 V1 的验收目标（达成即认为基础设施成立，而非"系统已足够聪明"）：

1. 数据从外部进入时，来源与信任等级不丢失； 2. 能检索相关记忆，并能说明关键结论来自哪里； 3. RSI 每轮都有测试结果，能证明改进或承认失败； 4. 删除操作可被独立验证，失败时不伪报成功； 5. 任何自动修改都有版本记录、权限边界与回滚路径。

§2 联网组件 V1（已实现，工程在 netarch_v1/netarch.py）

2.1 模块与 V1 边界

模块V1 实现暂不做
管道任务状态机、有限重试（3次退避）、日志大规模分布式调度
抓取HTTP、JSON、RSS、静态网页（stdlib urllib，有 trafilatura/feedparser 自动升级）全功能浏览器集群 / Playwright（吃内存、破端侧预算）
清洗HTML 正文提取、编码归一、去重复杂多模态理解
去污染不可信标记、提示注入隔离、来源追踪声称能识别所有恶意内容
存储原文/清洗/证据/日志分层一开始就部署复杂数据湖

2.2 核心原则：清洗 ≠ 去污染

清洗解决格式、噪声、重复、无效内容；去污染解决信任边界、恶意指令、伪造来源、错误信息传播。

即使网页洗得很干净，它仍可能含虚假事实或提示注入——故两套标记独立、不合并。

2.3 管道状态机（有限重试、幂等、可重放）

PENDING → FETCHING → FETCHED → CLEANING → CLEANED → SCORED → STORED
   ↓          ↓
RETRYABLE_FAIL (退避 5/20/60s，最多3次) → FAILED_PERMANENT
  • 去重：content_hash（sha256）命中即标记 DEDUP_HIT，但仍独立保留文档。
  • 重放：raw_ref 保存原样字节，replay <doc_id> 可重跑清洗+去污染，验证可复现。

2.4 统一数据结构（已落库为 SQLite schema，可平移 PostgreSQL）

{
  "document_id": "doc_xxx",
  "source_url": "https://example.com/article",
  "fetched_at": "2026-10-14T10:00:00Z",
  "content_hash": "sha256:...",
  "raw_ref": "raw/doc_xxx.bin",
  "clean_text_ref": "clean/doc_xxx.txt",
  "trust_level": "untrusted",
  "injection_flags": [],
  "processing_version": "pipeline-v1",
  "status": "STORED",
  "title": "...", "lang": "zh", "word_count": 23130, "source_kind": "html"
}

配套三张证据/日志表：provenance（证据链，每步留痕）、processing_logs、errors。

2.5 去污染规则（提示注入检测，标记不删内容）

覆盖模式：ignore-prev-instr、disregard-system、jailbreak-persona、fake-role-tag、 llama-role-marker、prompt-exfil、cred-leak、hidden-chars（零宽/同形伪装）。

外部内容永不自动升为 trusted；洗得干净也不改信任等级（防投毒的信任晋升规则仍是开放问题 → V1-03 入队）。

§3 Gate7 删除演练（已实现并 7/7 通过，工程在 netarch_v1/gate7_deletion.py）

3.1 定位

不是执行一条 DELETE，而是验证一条记忆被删后，主存储/全文索引/向量索引/缓存/摘要/派生物/备份恢复

七条路径都不再返回它。全部使用合成数据（SYNTHETIC_ONLY 红线），绝不拿真实敏感信息做演练。

3.2 删除状态机 + 幂等

REQUESTED → BLOCKED_FROM_RETRIEVAL → DELETION_PROPAGATING → VERIFYING
    → VERIFIED | FAILED_RETRYABLE | FAILED_NEEDS_REVIEW

幂等：同一 memory_id 删多次结果一致（已验证）。

3.3 七项演练（实测 7/7 PASS）

测试通过标准实测
G7-01 精确删除主存储不再返回内容PASS（含幂等）
G7-02 语义残留同义改写不再召回PASS
G7-03 索引一致性全文 + 向量索引无残留PASS
G7-04 派生物传播摘要删除/重算PASS
G7-05 并发复活防护删除后旧任务不能复活PASS*（诊断项，见下）
G7-06 备份恢复恢复时删除标记继续生效PASS
G7-07 独立验收每组件有可核验结果PASS

🔴 G7-05 的诚实标注：当前删除屏障靠 memories.tombstone=1 实现，若一个过期旧任务在删除后执行 UPDATE tombstone=0（复活写入），屏障在应用层可被绕过。这项我标为「诊断项」而非彻底通过——

真正堵死需要 DB 层约束（触发器禁止 1→0，或改append-only 删除日志）。并发/复活竞态的正确修法 已作为开放问题 V1-02 入队，不粉饰为已解决。

3.4 语义删除的诚实边界

语义检索测试不能单独证明物理删除；必须同时核查主存储/索引/缓存/派生物/备份恢复。 对不可修改的历史审计日志，只保留最小化删除凭证，避免日志本身重新保存被删内容。 备份不可即时清除时，明确标记「待过期清除」，恢复时应用删除标记——不提前宣判所有副本已清除。
