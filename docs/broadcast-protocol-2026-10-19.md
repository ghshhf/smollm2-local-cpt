# 广播协议：任意机器一条命令入网（2026-10-19）

> 目标：**不再手动贴命令**。一台新机器贴一条命令，之后它自己到白板上领活。
> 与 `node/q.py`（node1 专属队列）、`node/rc.py`（node1 专属直连）并行，互不干扰。

## 一、为什么用广播，而不是点对点队列

| | 点对点（`/task` 单队列） | 广播（共享白板） |
|---|---|---|
| 加一台机器 | 要登记地址、分配队列、改服务端 | **什么都不用改**，装上就看得见 |
| 多节点并发 | `GET /task` 一取即消费，会互相抢 | **各写各的格子，不抢** |
| 历史 | 取走就没了 | `out_<node>_<seq>.txt` 全留 |

这条思路不是新发明，是老路复用：`D:/work/_local_ai/relay/heartbeat_relay.py`（共享白板 + 多智能体并行）。

## 二、协议：三个文件，全走 ECS 信箱现成接口

服务端**零改动**，只用已有的 `POST /upload?name=X&key=` 与 `GET /file/X?key=`。

| 文件 | 谁写 | 语义 |
|---|---|---|
| `board.json` | 本机 `board.py` | `{seq, cmd, target, timeout, ts}`，**覆写** |
| `hb_<node>.json` | 节点每 30s | `{node, ts, host, pid, load}`，覆写 |
| `out_<node>_<seq>.txt` | 节点执行完 | 输出，**永不覆盖** |

四个关键设计：

1. **按 seq 前进，不销毁**。节点只判断「黑板 seq > 自己记的 seq」，读完不消费 —— 所以十个节点同时读同一块板也不会打架。
2. **target 不匹配也推进 seq**，避免重启后补跑一堆过期命令。
3. **读半截不算错**。覆写瞬间可能读到截断 JSON，`try/except` 跳过，下一轮再来。
4. **命令整组执行**（`start_new_session=True`），超时按进程组杀，不留孙子进程。

## 三、实测（node1 上真跑过）

| 项 | 结果 |
|---|---|
| 端到端往返（发命令 → 拿到输出） | **2.38 s**（轮询 2s，本地收结果 0.4s 粒度） |
| 不指定节点（`-t '*'`） | 广播给全部已登记节点，逐个收 |
| 崩溃自愈 | kill 掉节点进程，**9 秒内**被看护循环拉起（45269 → 45271） |
| 幂等 | 安装器重复跑，钩子不重复、`~/.bashrc` 只有一条 |
| 心跳 | `board.py nodes` 显示「在线 / 18s 前 / 负载 4.32」 |

## 三之一、为什么 2.4 秒压不下去（实测拆解）

把一次广播拆成三段（`tmp/probe_phase.py`）：

| 段 | 实测 |
|---|---|
| 本机 → 白板上板 | 258 ms |
| 上板 → 节点领取 | **81 ms**（轮询 0.3s，这段已经很好了） |
| 领取 → 本机看见回传 | **1160 ms**（其中命令本身只占 200 ms） |

再看两刀：

| 实验 | 结果 | 结论 |
|---|---|---|
| 纯 TCP 握手 ×8 | 28–56 ms，**无一次卡顿** | 网络干净，不是链路问题 |
| HTTP 请求按「空闲间隔」分组 | 间隔 0.15/0.4s → 60–90 ms；**间隔 1.0s → 每次都 ~1000 ms**；2.0s → 大多正常 | 服务端内部有 ~1s 的接单延迟，且 **1 秒正好是最坏的轮询间隔** |
| 4 个并发 GET | 全部 ~1000 ms | **串行**，队头阻塞 |

根因落在 ECS 那台的 `C:\llama\mailserver.ps1`：一个 `while($true){ $listener.GetContext() }` 的**单线程 PowerShell HttpListener**。TCP 由内核 http.sys 秒接，但请求要排队等这一个脚本循环处理，所以：

- 并发会串起来，4 个请求一起变 1 秒
- 请求之间的空闲间隔踩在特定值（≈1s）会触发最坏情况
- 客户端怎么调参数都只是在「撞哪一档」之间挪，压不到底

**结论：2.3 秒是这台服务的下限，不是协议的代价。** 要再压只有两条路——换真隧道（frp，见下）或把服务端换成并发实现。

## 三之二、已修掉的五个真 bug

| # | Bug | 后果 | 修法 |
|---|---|---|---|
| 1 | seq 只用毫秒时间戳 | 本机时钟被 NTP 往回拨一次，新 seq 小于节点已记的，命令**永久跳过** | 取 `max(now_ms, 旧seq+1)` |
| 2 | 用 PIPE 收命令输出 | 3GB 的机器上一条 `cat 大日志` 直接 OOM | 输出落临时文件，只读前 256KB（实测截断 1.99MB 输出通过） |
| 3 | 上传无重试 | 网络抖一下心跳/结果就丢了，且静默 | `http_put` 重试 2 次（0.15/0.3s 退避），心跳失败写日志不再 `pass` |
| 4 | 重装时新旧实例并存 | 同一 seq 被执行两遍，结果互相覆盖 | `join.sh` 等旧进程真退出（最多 10s）再起 |
| 5 | 超时无法区分「没领到」和「在跑」 | 排错时误判节点掉线 | 执行前先传 `run_<node>_<seq>.json` 领取标记，`board.py` 据此分开报告 |

## 四、接入一台新机器：就一条命令

```sh
curl -sS "http://47.99.131.12:8081/file/join.sh?key=k0u4mail" -o /tmp/join.sh && bash /tmp/join.sh <节点名>
```

它做五件事：拉节点端（纯标准库，不需 pip / torch）→ 写 `~/.polaris/node.json` → 按优先级装开机钩子 → 起永久看护循环 → 自检并打心跳。

**开机钩子优先级**：`/etc/dsw/bin/prestart`（魔搭）> systemd > `crontab @reboot` > `/etc/rc.local` > 仅 `~/.bashrc` 兜底。哪一层生效会打印出来。

卸载：`bash /tmp/join.sh <节点名> stop`。

## 五、日常用法（本机）

```bash
python node/board.py send "nvidia-smi"            # 广播给全部节点
python node/board.py send "df -h" -t node2        # 只给某台
python node/board.py send "sleep 300" -w 10 -T 600  # 只等 10s，命令侧放 600s
python node/board.py nodes                        # 谁活着、负载多少
python node/board.py reg node2                    # 装完后登记（本机记账用）
python node/board.py board                        # 白板上现在是什么
python node/board.py out node2 1792392596433      # 翻历史输出
```

三种通道的取舍：

| 工具 | 用在哪 | 延迟 |
|---|---|---|
| `rc.py sh` | node1（有反向隧道） | **360 ms**，主力 |
| `board.py send` | 任何机器（只要能出网） | **2.4 s**，通用兜底 |
| `q.py` | node1 上的长作业排队/插队 | 不适用 |

## 六、边界（诚实清单）

- **2.3 秒是邮箱服务端的下限**（单线程 PowerShell HttpListener）。想和 node1 的 360ms 比，必须换真隧道：ECS 上 `frps.exe` 已在跑（PID 2100，监听 80），用 `stcp` 模式不需要新开端口，但要在 node2 和本机各装一个 frpc（~10MB），预期 **0.1–0.3s**。**未做，等点头。**
- **overlay 盘 = 临时盘**。容器被平台销毁重建，`~/.polaris` 一起没。能做到「不重启就永远不用贴」，做不到「重建后自己复活」——那需要持久盘，平台没给。
- **无 systemd 的容器**只能靠 `~/.bashrc` 兜底，本质是「有人开终端才确保在跑」。真正的常驻靠 `setsid nohup` 起的那个循环，只要进程不被杀就一直活。
- **命令通道就是 root 权限**。谁能写 `board.json` 谁就能让节点执行任意命令。信箱 key 是唯一门槛，别再往公开地方贴。
- **2 核 3G 那台别派重活**。它的正确用途是轻量外勤（探针、抓取、转发），跑不动 0.5B 模型。

## 七、排错

| 症状 | 先看 |
|---|---|
| `nodes` 显示「无心跳」 | 节点上 `cat ~/.polaris/node.log`；进程在不在：`pgrep -f 'polaris_node[.]py run'` |
| 有心跳但没输出 | 白板 `target` 是不是写错；`out_<node>_<seq>.txt` 名字对不对 |
| 输出为空 | 命令本身没输出；看 `rc=` 是多少 |
| 装完就死 | `~/.polaris/crash.log`（崩溃堆栈）与 `node.log`（叙事）分开记 |
| 日志重复两遍 | 看护进程必须带 `POLARIS_ECHO=0`，否则 `say()` 和 shell 重定向会各写一次 |
