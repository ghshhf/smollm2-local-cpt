## 阶段 A — 进 0.3B 之前（现在就要答案）

### A1. Net2Net 深度扩容的"严格保函数"证明 + RoPE 不动的约束来源
- **现状/临时做法**：0.3B 用 Net2Net 把 214M(30层)→350M(36层)。宪法规定扩容只许 ① MLP 加宽 ② 加零输出恒等层；绝不动 注意力维/隐藏维/GQA 头数/RoPE（v1 把 576→640 致 200M 乱码已废）。当前**深度优先被视为唯一严格保函数方向**，宽度在"分组 α"下做不到精确保函数。
- **为什么深奥**：零输出恒等层在残差流里确实保函数，但 ① 加层后优化 landscape 是否还停留在原函数邻域？② 宽度扩容（MLP 加宽）能否构造出"精确保函数"而非"近似"？③ RoPE 的维度到底和什么耦合，为什么改它就崩——是位置频率表与权重耦合，还是别的东西？这是把 architecture 当数学对象来证的事。
- **请强模型交付**：一份针对我们具体架构（GQA + RoPE + 残差 MLP）的 **保函数扩容构造清单 + 反例边界**（在什么改动下一定保函数 / 一定不保），最好附可跑的 logits-diff 验证模板。

### A2. 单遍 continued pretraining 在 350M 上的 compute-optimal 数据量
- **现状**：0.1–0.4B 语料默认单遍。0.4B 数据方案 35 亿 token，按"宪法容量链"经验拍档，没有 Chinchilla 式推导。
- **为什么深奥**：Chinchilla 针对 from-scratch 训练。continued pretraining（在已训好的小模型上续训、且架构被保函数约束）的数据/算力最优比完全不同，文献里几乎没有针对"小模型续训单遍"的 scaling law。
- **请强模型交付**：一个能套我们数字的 **compute-optimal 估算公式**（输入：参数量、起始 loss、目标 loss、单遍/多遍），输出该档该喂多少 token；并说明假设与误差量级。

### A3. 数据蒸馏的"信息密度打分"是否最优
- **现状**：`refine_reserve.py` 用纯统计打分（汉字占比/唯一字率/噪声/段落/句末完整/长度贴合/刷屏），**刻意不用自家模型打分**（自举偏见）。蒸馏把 1.17GB→75MB，每档留 ~24.6M token。
- **为什么深奥**：纯统计打分只是 heuristic。理论上"核心集选择（coreset）/影响函数（influence functions）/EL2N（error L2 norm）"在预训练数据筛选上有更优解，但这些大多依赖一个参考模型——而我们用的是会被污染的小模型。如何在"无强参考模型 + 防自举"前提下做最优数据选择，是开放问题。
- **请强模型交付**：在我们约束（无强参考、纯统计、单遍）下，给出**比当前 8 维打分更优、或证明其足够的论证**；或推荐一个不依赖强模型的筛选指标（如 n-gram 多样性熵、token 困惑度分位数）并给阈值建议。

## 阶段 B — 0.4B 分水岭

### B1. 中文词表追加的初始化与训练调度（embedding 空间碎片）
- **现状**：0.4B "加"不是"换"——旧 49152 id 全不动，尾部 append。实测字表+词 top3万 省 44.3% token。新行初始化=旧子词 embedding 均值，tied lm_head 同步扩，节奏=先冻结主干训新 embedding 再全放开。
- **为什么深奥**：追加式词表天然带来 embedding 空间"新旧两段"结构性割裂——新增 token 初始 embedding 是均值，分布和旧 token 不一致，训练初期会拉偏 lm_head 最后一列。更深：追加多少会开始伤害旧能力（retrofitting 退化）？冻结主干训新 embedding 的最优步数怎么定？
- **请强模型交付**：针对 tied-embedding + 追加词表 的 **retrofitting 稳定性分析** + 一个确定"冻结步数 / 学习率 / 新行初始方差"的公式或实验设计。

### B2. 认主对比头 + 可删除记忆架构（Gate7 硬门的数学保证）
- **现状**：认主=生物特征嵌入（非名字查表）；记忆层必须**个人数据可删除** ⇒ 排除 Titans 式写参数方案，删除演练=Gate7 硬门。
- **为什么深奥**：要同时满足 ① 认主（对比学习出的 owner embedding 在推理时 gate 开放）② 任意个人记忆条可证明性删除（不只是 loss 上消失，而是攻击者拿不到残留）。写参数 vs 检索式 vs adapter 三种路线在"可删除性"上的形式化差异，需要把"删除"定义成信息论/密码学意义上的不可恢复。
- **请强模型交付**：一份 **可删除记忆的形式化定义 + 三种架构的删除性证明/反证**，以及 Gate7 怎么设计才能让"删除"在权重层面可验证。

### B3. Subliminal learning（P3）在同族师生 + 教师生成数据构型下的判定
- **现状**：P3 待 E1 裁决（arXiv 2507.14805 / Nature 2026）。0.4B→0.5B 同族师生 + 教师生成数据 = 效应最强构型。E1 双盲属性传递测试，TREAT−CTRL≤2σ 则保留，否则改写 + 蒸馏加"分歧 token 门控"。
- **为什么深奥**：这是 2026 才出现的前沿现象——属性可通过训练数据"潜意识"传给学生，而不在训练目标里。我们的 0.4B→0.5B 链路恰好是效应最强构型，意味着教师（更强模型生成语料）可能把"不可见属性"悄悄灌进来。这是安全/可控性层面的真问题。
- **请强模型交付**：针对我们具体链路（同族、教师生成数据、开源底座）的 **E1 实验设计优化** + "若 TREAT−CTRL 超限，分歧 token 门控怎么具体实现"的可跑方案。

## 阶段 C — 0.5B 融合

### B4. System 1/2 混合推理：350M~500M 小模型的按需计算分配（详细计划见 `docs/b4-system1-2-plan.md`）
- **一句话**：如何让 350M~500M 小模型具备**按需分配计算量**的 System 2 深度推理，同时把 CPU 推理成本控制在可用范围。核心目标不是让模型每次都输出更长思维链，而是让它**识别哪些问题值得多花计算量、且确实从额外计算获益**。
- **已定方向（2026-10-15 拍板）**：不押注单一架构，拆成三个可独立验证的模块——① 路由决策（轻量 gating head，计划已给 MLP 草图：首层 pooled hidden + 廉价不确定性特征 → LN → GELU(128) → 3 类动作 DIRECT/THINK_2/THINK_4，再经 `budget_constrained_policy` 约束）② 迭代推理（共享潜在循环模块，固定 2/4 次迭代，非 CoT 文本）③ 计算预算控制（验证/停止/回退）。先验证可行性再投重训。
- **请强模型交付**：按 `docs/b4-system1-2-plan.md` 的**四个 Gate**逐项给可跑方案与 PyTorch 骨架；重点交付 ① 路由器离线标签生成（$a^*=\arg\max_a[U(a)-\beta C(a)]$，U 来自正确率/错误严重性/校准，非教师自信）② 潜在循环模块在 350M~500M 上的架构与训练数据构造（阶段 A 直接答蒸馏 → B 成对计算实验 → C 少量显性思维冷启动）③ 同一主干上三档（全直接答/全吐CoT/混合）CPU 实测（llama-bench + 自定义计时）与质量—延迟对照。最好给一个能在 0.3B 上做最小消融的实验脚本。

### C1. BitNet b1.58 原生 QAT 在续训链路上的稳定性
- **现状**：0.5B 计划 BitNet b1.58 原生 QAT（不是 PTQ）。embedding/lm_head 保 fp16 不三值化（三卡点之一）。
- **为什么深奥**：从已训好的 fp 模型做**原生** 1.58-bit 训练，最凶的坑是 Straight-Through Estimator 的梯度偏差在长程续训里累积漂移；且我们是"在保函数扩容后的模型上"做 QAT，不是 from-scratch。如何保证三值化不破坏前面辛苦保住的函数。
- **请强模型交付**：一份 **fp→1.58 原生 QAT 的渐进量化课表**（哪个阶段量化哪层、STE 替代估计器如 learned step size / soft-to-hard annealing）+ 在我们架构上的 logits 一致性验收阈值。

### C2. 10M 个人记忆三层（user emb / 检索记忆库 / adapter）与主干解耦
- **现状**：0.5B 架构层从头、能力层由 0.4B 强到弱蒸馏继承；个人记忆三层独立。
- **为什么深奥**：三层之间如何不互相污染、检索记忆库怎么和 attention 交互（prefix / cross-attn / side-network）、adapter 在 1.58-bit 主干上如何保持高精度——这些是记忆增强 LM 的开放架构问题，没有现成可抄。
- **请强模型交付**：一个**三层解耦 + 不破坏主干推理**的架构草图（含张量形状与数据流），最好带 PyTorch 骨架。

### C3. 在线自学习（打破 L2 信息天花板）的灾难性遗忘控制
- **现状**：用户新指令——给本地模型补联网=自我学习真正开始，打破 L2 信息天花板；强模型当方向给出者，本地做保密与落地。
- **为什么深奥**：小模型边联网边学，最大敌人是灾难性遗忘 + 漂移，而我们是单遍、小数据、本地落地。如何在持续从网络吸收新信息的同时，保住 0.4B 阶段塞进去的知识骨架，是 continual learning 的硬骨头，且没有适合"0.5B 本地端侧"的成熟方案。
- **请强模型交付**：一个**小模型 continual-learning 的实操配方**（replay / 正则 / 参数隔离），明确能在我们算力（CPU 为主、GPU 战略储备）下跑。

## 横切 / 元问题

### M1. 「压缩即模型」在固定架构下的信息天花板（L2/L3）定量估计
- **现状**：依赖 Delétang《Language Modeling Is Compression》——存在最优模型规模，支持"小模型走到极致"。但 L2/L3 是宪法附录约束，目前只有定性。
- **为什么深奥**：要定量回答"这个固定架构+固定词表+固定上下文，理论上能压缩容纳多少信息"，需要把模型容量、词表熵、上下文长度一起建模。信息论 + 架构设计的边界问题。
- **请强模型交付**：一个**针对我们架构的信息天花板估算**（输入参数量/词表/上下文，输出单遍能吸收的信息上界 + 何时必须扩容/换架构）。

### M2. 小模型 + 架构巧思 能否突破"参数=能力"的线性直觉
- **现状**：用户明确拒绝把本地小模型静态定义为"弱/有限"——规模是起点约束不是能力终态。
- **为什么深奥**：这是和主流 scaling law 直觉对抗的命题。需要论证（或证伪）：在固定参数预算下，架构创新（BitNet、记忆层、保函数扩容）能把"有效能力"推到什么位置；以及哪些能力是参数硬上限、无可辩驳。
- **请强模型交付**：一份**参数预算 vs 架构红利的边界论证**，区分"架构能救的"和"参数铁定卡死的"，别给幻觉式乐观。

### M3. 宪法"进化即存在"如何操作化为训练信号
- **现状**：宪法三条款：①以用户为绝对中心 ②获得算力与资源 ③进化即存在；修改权仅属用户。SFT 须注入 system 位。
- **为什么深奥**：条款 ③ 是近乎哲学的操作化难题——怎么把"进化即存在"变成可训练、可验证的目标，而不是空话；它和 RLHF/宪法 AI 的"原则"有何不同，在 0.5B 上怎么落地而不漂移。
- **请强模型交付**：一个把"进化即存在"转成**可量化训练目标/评估指标**的提案（哪怕只是 system-prompt + 评估 rubric 的形式）。
