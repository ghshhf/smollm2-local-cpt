## 二、代码线资源账

### 2.1 目标
0.4B 配方总盘 35 亿 token，代码占 **15~20%**（上限 30%，超了中文灾难遗忘；我们只有 11 亿通用语料做缓冲）⇒ **代码 5.3~7 亿 token 为上限，首轮取 2~3 亿**。

### 2.2 存量与在途（全部是蒸馏/指令类）

| 数据集 | 大小 | 性质 | 约 token |
|---|---|---|---|
| Magicoder-Evol-Instruct-110K | 255MB | 指令→代码（蒸馏） | ~4000 万 |
| Magicoder-OSS-Instruct-75K | 203MB | 指令→代码（蒸馏） | ~3000 万 |
| CodeFeedback-Filtered-Instruction | 下中 | 多轮修正（蒸馏） | ~5000 万 |
| CodeFuse-Evol-66k | 待下 | **中文**指令 | ~2000 万 |
| CodeFuse-CodeExercise-27k | 待下 | 中文题面+用例 | ~500 万 |
| codeparrot/apps | 待下 | 题面+测试用例 | ~3000 万 |

⇒ 合计约 **1.7 亿 token**，**但全是指令格式，直接当预训练语料会让模型退化成"复述题目"**（0.3B 已踩过这个坑）。

### 2.3 缺的那块：裸代码语料（已在魔搭确认可直拉）

| 数据源 | 位置 | 大小 | 性质 |
|---|---|---|---|
| **SmolPyEdu（已下完）** | 魔搭 `MoreThought/SmolPyEdu` | **2.16GB / 10 片 parquet** | GitHub Python 经 EDU 过滤，**纯裸代码**；实测 **5,468,096 行 / 48.16 亿字符 ≈ 13.8 亿 token**，列名 `text` |

**已抽好的包**：`corpus_04b/code_pretrain.jsonl` = 608,712 行 / 6.00 亿字符 / **1.71 亿 token**（全量的 12%，每片均匀取，`tools/build_code_pack.py` 可复算）。

### 2.4 混比建议

```
裸代码 70%（python-edu 抽样） : 指令代码 30%（magicoder/codefuse 精选）
代码总占比 15~20%，按 token 计
```

理由：裸代码补"表征"，指令代码补"格式与中文注释"；0.3B 的实测结论是内容层归底座、格式层归数据，两者都要。

### 3.3 首轮配比（2026-10-19 用户裁定：音频降为附带 ⇒ 230 h）

| 来源 | 时长 | 说话人 | 理由 |
|---|---|---|---|
| **AISHELL-1 全量** | 178 h | **400 人**（S0002~S0401，现只有 18 人） | 真人 + 说话人多样性，**最高性价比** |
| edge-tts 合成（我们的语料） | 50 h | ~25 个音色 | 补领域（知识/文案/口语），**不补说话人** |
| 合计 | **228 h** | — | 已覆盖 6000 步训练预算（见 §8.2） |

> 原 1000h 方案作废。理由见 §8.2：6000 步只吃 4.8 万条，1000h 的 36 万条用不完，多出来的部分这轮是纯存储开销。

### 3.4 落地形态（**需裁定，见 §六**）

- **形态 A（真·多模态预训练）**：audio codec（EnCodec/Mimi）编码成离散 token 混进词表 → 需词表**再扩**（~8×1024）+ 交错序列构造。0.3B 期完全没做过，属架构级新增。
- **形态 B（L1 投影对齐）**：Whisper encoder → projector → 主干，只训 projector（0.78M）。已有代码与缓存，诊断结论是"800 步只有 0.59 epoch，需 6000 步 / 8.8 epoch"。

## 八、用户裁定（2026-10-19 19:40）与"够用量"论证

| 项 | 裁定 |
|---|---|
| 主攻方向 | **代码为主，音频附带** |
| 训练算力 | GPU；但**先出数据、出方法，不顶格堆量** |
| 代码语料 | **不自产，取现成** |
| 音频规模 | 待定 → 本文按"够用"给出 228h，否定 1000h |

### 8.1 代码：够用量是 1.5~2 亿 token，不是 5 亿

| 代码 token | 预期能力（0.4B / 440M 参数） | 判断 |
|---|---|---|
| 5000 万 | 学会格式，简单题偶过 | 不够 |
| **1.5 亿** | **格式稳定 + 简单题能跑**（本阶段目标） | **拐点** |
| 3 亿 | 边际改善已很小 | 可用但非必要 |
| 5 亿+ | 参数容量吃不下，纯浪费 | 顶格，无意义 |

依据（实数，2026-10-19 19:40 实测 `tools/stat_code.py`）：
**SmolPyEdu 全量 = 546.8 万条 / 48.16 亿字符 ≈ 13.8 亿 token 纯 Python**（列名 `text`，无指令包装，样本为原生代码）。
首轮只取 **1.5 亿 = 全量的 11%**，按 EDU 分数从高到低取。剩下 89% 不是"以后再说"——
440M 参数在同一批数据上多跑几遍不会变强，只会记住。**容量是天花板，取够即止。**

落地面板：总盘 8~10 亿 token（GPU 30h 的实际可吃量）
```
通用中文 6.5~7.5 亿（76%）
裸代码 1.0~1.4 亿（python-edu 抽样，13%）
中文指令代码 0.5~0.6 亿（magicoder/codefuse 精选，6%）
创意/知识等维持既有配比
```

### 8.2 音频：1000h 这轮收益为零（算术否定）

对齐阶段只训 projector（0.78M 参数），训练预算 6000 步 × accum 8 = **4.8 万条**。

| 数据量 | 条数（6s/条） | 6000 步能吃多少 | 结论 |
|---|---|---|---|
| 现有 8.2h | 6,224 | 7.7 epoch | 已经够跑满 |
| **228h** | **13.7 万** | 2.9 epoch | **够用，留余量** |
| 1000h | 36 万 | **13%** | **用不完，纯存储** |

更关键的是**多样性 ≠ 时长**：
- AISHELL-1 全量 = 178h / **400 个真人说话人**（我们只有 18 人）→ 直接提升跨说话人泛化，这轮最该做的一件事。
- edge-tts 中文只有 ~25 个音色 → 合成 600h 仍是 25 个人，**对泛化零贡献**，只补领域。

### 8.3 音频能买到什么（诚实预期）

| 方案 | 域内 CER | 跨域 CER | 参照 |
|---|---|---|---|
| 现状 0.3B align 800 步 | **7.42**（完全不认识） | — | 实测 |
| 228h + 6000 步（域内） | **待实测**（跑完 6000 步才知道） | 待实测 | 不再外推 |
| 外设方案（Whisper-small 全量） | **0.125** | — | 已实测闭环 |

⇒ 内化的价值**不是 CER 更低**（外设 0.125 已经封顶），而是**省一次工具调用、模型原生感知音频**。所以"附带"是正确判断：228h / 40 核时 / 一次跑完，值；再往上堆不值。
