#论证推论
1 这条链路从来就不干净：语料与方向来自多个云端模型，"多教师蒸馏"是我们构筑能力的唯一方式， 不是 0.4B→0.5B 这一环的偶发行为。 在最后一环设检疫站 = 在全程开放的通道末端设卡。它不阻断任何东西，只砍有用信号。

① "蒸馏"在我们的语境里 = 语料蒸馏，不是 logit KD。 我们的"蒸馏"（0.3B 那条线）是：硬过滤 → 块级去重 → 信息密度打分 → top 配额——筛数据喂给预训练， 全程 next-token CE，没有任何"教师 logit 教学生"的环节。 ClawsGO 报告里的"蒸馏管线"（三段式 KD / 分歧 token 门控）是模型教模型的 KD 范式， 从云端教师-学生场景搬来的，在我们的流程里根本不存在。 subliminal learning 的成立构型 = 同族基座 + 教师生成的语义无关数据流（数字流）； 我们 0.5B 从零训练、吃的是可审计的真实文本语料，学到什么由语料内容直接决定 —— 压根不在 subliminal 的适用构型里，连"天然防线"都谈不上，因为门根本没有。

② 议程归属错误（更根本）。 E1 是 ClawsGO 报告的议程，用户从未要求过。我把它排成"ROI 最高没有之一"并直接烧了几小时 CPU —— 违反了宪法①的精神：问题的提出权在用户（「自己提出问题→解决问题→发现问题」）。 外部模型的建议 ≠ 用户的指令；实验开跑前必须用户拍板。

但 ClawsGO 修正 1（open_questions_answers.md §0）明确： 词表改的是 (D, H) 而保持 D·H 近似不变 —— token 少了，每个 token 携带的比特就多了。 44% 不是独立乘数；输出压缩（算术编码）是"把交叉熵兑现成码长的机制"，是测量手段不是第三层增益。 真正只有一项杠杆：三值降 b_eff。

好消息：修正后的结论对我们更有利 ——「只有三值是真杠杆，且它只在语料小时显著，我们恰好语料小」。 但文档现在是用错误的理由支撑一个正确的结论，这会误导后续所有按此口径做的记账。
⏸ 认主：由「待裁决的分歧」转为「主动空缺」　2026-10-16 用户定稿

原状态：data-plan-0.4B.md §5.2 定 ArcFace，ClawsGO 修正 5 反对 （角边际为几万类百万样本设计，我们只有一两个身份，少样本下多数测试发散）。
裁定：两者都不执行。用户口径："实在不行暂时就空缺下来，未来往进去镶嵌数据也行。数据不够，不作为短期深刻理解的东西。未来我和它聊天聊多了，可以作为一些东西。"

延后的两条硬理由（不是"先放放"）：
① 数据类型不对：现有 5,146 条绝大多数是"关于主人的陈述"（转述、描述），不是真实交互的流式样本。 认主语料必须来自长期真实对话积累——不人造、不提前凑。
② 宪法 §4 E-7：个人数据绝不进任何被训练的参数（含 adapter），只进可寻址可删除的记忆层。 记忆层未落地 ⇒ 没有可删除的容器，就不许往里写个人数据。

0.4B 只做一件事：留接口。不训认主头、不改架构、不进任何参数； 只把 embedding 抽取点与记忆层挂载位置定死 —— 将来镶数据是"插上去"，不是"拆开重造"。

激活前置条件（三条不齐就不上）：① 可寻址可删除的记忆层已落地 ② 线性探针 AUC 实测分不开 ③ 真实交互语料积累到现存量级。
激活时先跑线性探针：探针能分开，认主头整个省掉，ArcFace 也根本不用上。 这条同时满足了 ClawsGO 修正 5 与用户"先空缺"的判断 —— 这条分歧不是被妥协掉，是被时间解决掉的。

⚠️ 外部证据更新 2：三值的收益来自带宽，不是算力（Q2 的答案是现成的）

Q2（带宽 vs 算力）本来排在一级空缺、需要实测。但 2026 年已经有三个独立来源实测过这件事， 结论高度一致，且与 ClawsGO 的推断同向。我们不用从零测，只要把结论落到自己的构型上。

来源实测结论落到我们身上
Litespark
arXiv 2605.06485, 2026-05		 在 M4 / Ice Lake / Zen4 / Core Ultra 四平台测 BitNet b1.58 2B：「memory bandwidth rather than SIMD width is the primary bottleneck」；全平台均为 memory-bandwidth-bound。内存降 14×、TTFT 快 8.3–12.6×。
注意其基线是 PyTorch 全 fp32 矩阵乘，作者自承是弱基线，加速比数字要打折看。		 向量宽度不是瓶颈 ⇒ 为了更宽 SIMD 去改架构是白费。
BitNet 延迟优化实测
perf stat 剖析		 >68% 的总延迟来自 L3 cache miss 与未对齐加载，不是算术。权重若不对齐、不连续，要多付 3–5× 内存停顿。 权重打包与内存布局的收益 > 换更快的算子。这是 0.5B 端侧该优先做的工程。
Project Zero
纯 C 无依赖引擎		 1.4 → 36.25 tok/s，终点是"该硬件解析 DRAM 带宽上限的 95%"。几大跳跃分别来自：关 earlyoom、单通道改双通道、线程数甜点、INT8/INT4 分类路径 —— 全部是访存侧改动，没有一项是算力侧。 证实了天花板形态：我们的 15ms/token 目标本质上是一个带宽目标，不是算力目标。
由此得到一条对 0.5B 架构直接有用的账

三值主干每 token 解码要读全部权重，而我们决定 embedding 保 fp16（不三值化） —— 这部分不享 14× 压缩，且每步都要读。

在 0.5B 档：三值主干 ≈ 79 MB（0.5B × 1.58 bit），fp16 embedding ≈ 56.6 MB（49,152 × 576 × 2B，tied 则共享）， embedding 占总访存约 42–43% —— 与 ClawsGO 在 Q-09 里点出的「embedding 那 43%」独立吻合。

含义：混合精度会稀释三值加速比，稀释量主要就来自这 43%。 所以"embedding 保 fp16"不是一个纯记账决策，它是一个有实测代价的推理延迟决策， 且与 N*≈193M（b_eff 5.5 口径）绑在一起。要拿回加速就得动 embedding，动 embedding 就得改 N* 口径 —— 这两件事必须在同一次决策里一起算。

§5未来整体还不懂什么：三个方向

A · 数学上还没定义的
三值权重空间里的模型算术 —— 欧氏空间的"平均"在离散格上没有定义。soups 理论整个失效，符号多数投票是候选但没数据。
模态扩展的保函数 —— 现有定义只对同类型空间的 append 成立。
时间一致性 —— 记忆会变错而非变淡，取代契约与删除契约是两回事。
B · 有理论但算不出数的
语料信息天花板 H_raw —— 不可点估计，只能给区间。绝对值缺 H_raw 无法判定，但符号与零点可算，靠 0.1B→0.4B 的纵向序列看趋势。
N*(D, b) 联合最优 —— 跨 1B/3B/8B 阈值后要重算，目前只有 0.4B 这一档的锚。
RSI 的安全累积率 —— 每代自改幅度 < x% 才稳定，x 未定。
C · 没人做过、我们独有的
血统完整性检验框架 —— 蒸馏隐写通道 × 身份连续性 × 留出集独立性，三位一体。这是可发表的评测方法论，不只是工程检查。
压缩准入规则 —— 把"插模块"和"放大参数"放进同一把尺子。学界算的是模型 vs 数据，模块化用的是能力指标，没人把两者放在同一个率里比。
决策门的失效模式 —— Grokking 的观测特征与"容量受限"完全重合，而十条 Gate 没有一条防它。
最容易被忽略、但可能是最根本的一条：B10 人机接口的带宽
整份知识体系都站在模型侧。但"以用户为绝对中心"这条宪法能否执行， 瓶颈可能在用户侧 —— 用户要怎么表达"我想要这个模型变成什么样"？ 如果表达带宽不足，模型所有的进化能力都无处施力。 这是全部清单里唯一一个"不是模型问题"的类别，而它决定宪法①成不成立。

§6一句话结论

这套知识的理论部分已经相当厚 —— 三轮 ClawsGO 交叉核验、59 源台账自报 0 错，L1/L2/L3 三条统摄规则已经把散落的经验收成了体系。

真正缺的不是答案，是测量：σ 没量、holdout 没造、斜率 x 没测、外部中文 holdout 未建。 判据分母为空，导致 ClawsGO 给的每一个 2σ 判据当下都不可执行。

在必须继承的系统里，控制点从输入端移到输出端 —— 继承多少不重要，能不能逐位目检才重要。
