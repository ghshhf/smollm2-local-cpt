# 通用模块接口规范 v1

> 2026-10-18 定稿。回答一个问题：**凭什么一个模块能挂到别人的模型上，还照样好用？**
> 这不是为自家 0.2B/0.3B/0.4B 写的胶水，是模块化路线本身的工程底座。

---

## 一、第一性原理：知识在主干，行为在模块

大模型把两类东西焊死在一起：

| 类型 | 例子 | 归属 |
|---|---|---|
| **知识** | "北京是中国的首都"、"`git rebase` 会改写历史" | 主干权重（谁的模型，就是谁的知识） |
| **行为** | "被问问题时先给结论再给代码"、"自称主人"、"答完要收尾" | **模块** |

焊死的代价是：想改行为，必须动知识；想要知识，必须连行为一起买。

模块化拆的正是这一刀。拆开之后：

- 挂到 Qwen 上 → 用 Qwen 的全部知识 + 我们的行为
- 挂到 Llama 上 → 用 Llama 的全部知识 + 我们的行为
- 挂回自家的 0.4B → 用自己训出来的全部知识 + 同一套行为

**同一个模块，三种知识库。这就是"通用"的真正含义。**

反过来说，如果模块里塞了知识，它就立刻绑死在某个主干上——因为知识是和表征空间一起长出来的。**模块越薄，越通用。**

## 二、可移植性分三级（必须分开讲，混在一起必错）

| 级别 | 跨什么 | 权重能不能直接搬 | **行为能不能迁移** | 实测 |
|---|---|---|---|---|
| **L0 同血统同规格** | 0.2B → 0.3B → 0.4B（同一份预训练续训，hidden 恒定，只加层） | ✅ 零填充，逐位相等 | ✅ **能** | "好，主人。"两代复现；`max\|diff\| = 0.000e+00` |
| **L1 同血统异构** | 同族不同规格（层数/inter/hidden 变化） | ✅ 恒定维零填充即装 | ✅ 能（需重定位） | 0.3B 挂 0.2B 模块：从语料退化复读机变回会说话 |
| **L2 同架构不同血统** | SmolLM2-200M（同架构、不同预训练权重） | ✅ 形状可对齐 | 🟡 **一半**：会说话，但身份/内容错 | 不再复读，但"你是谁"答成"我是你的家人" |
| **L3 跨血统** | Qwen2.5（不同词表、不同 hidden、不同语料） | ✅ 形状可对齐 | ❌ **不成立，且有害** | 挂与不挂，回答一字不差；带 system 时幻觉出假主人 |

### 🔴 最重要的一条：形状能搬 ≠ 行为能搬

`max|diff| = 0.000e+00` 只证明**移植是精确的**，不证明**移植是有意义的**。

零填充的保证是"前 d 维喂进旧矩阵，输出不变"——它**隐含假设目标模型的前 d 维和源模型的语义一致**。同一血统成立，跨血统不成立。

详见 `docs/module-portability-report-2026-10-18.md`（六组实测，含"无 system 生成对照"这一唯一干净判据）。

### 实测：同一份模块（Chat LoRA，420 张量）挂三个主干

| 目标主干 | hidden | layers | inter | kv_dim | 直装 | 零填充 | 丢弃（MLP） |
|---|---|---|---|---|---|---|---|
| 自家 0.3B | 576 | 36 | 4608 | 192 | **240** | 0 | 180 |
| SmolLM2-200M | 576 | 30 | 3072 | 192 | **240** | 0 | 180 |
| SmolLM2-135M | 576 | 30 | 1536 | 192 | **240** | 0 | 180 |
| 合成异构（hidden=768/24层/kv=4） | **768** | 24 | 2304 | **256** | 0 | **240** | 180 |

最后一行是关键：**hidden 从 576 到 768、kv_dim 从 192 到 256、层数 36 到 24、词表 49152 到 100000**，零填充后校验：

```
[verify] 校验 96 组 ΔW，旧子空间 max|diff| = 0.000e+00
[verify] PASS — 保函数成立（旧行为逐位不变，新维贡献恰为 0）
```

**结论：模块装到异构主干上，旧行为一字不改。** 变的只是"新维没学过"和"表征空间偏移"，用少量数据重定位即可（小时级），不是从头训。

## 三、接入点分类：决定 10 年后还能不能用

| 接入点 | 维度 | 是否随扩容变化 | 判定 |
|---|---|---|---|
| `q_proj / k_proj / v_proj / o_proj` | hidden（=576，宪法冻结）/ kv_dim | **恒定** | ✅ 允许 |
| 残差流 adapter | hidden | **恒定** | ✅ 允许 |
| `gate_proj / up_proj / down_proj` | intermediate（3072→4608→…） | **可扩** | ❌ 禁止 |
| `embed_tokens / lm_head` | vocab | **可扩**（追加词表就变） | ❌ 禁止 |

**第 0 条铁律：只许接恒定维，禁止接可扩维。**

违反的代价是实测过的：老模块 78.6% 的 MLP 张量在 0.2B→0.3B 时直接作废（3072→4608）。

## 四、移植算法

### 4.1 零填充（目标维 ≥ 源维）— 保函数

```
lora_A: [r, d_in]   →  [r, d_in']   末维右侧补 0
lora_B: [d_out, r]  →  [d_out', r]  首维下方补 0
```

于是 `ΔW = B' @ A'`：

```
ΔW'[i, j] = ΔW[i, j]   (i < d_out, j < d_in)     ← 旧子空间逐位相等
ΔW'[i, j] = 0          (i ≥ d_out 或 j ≥ d_in)   ← 新维贡献恰为 0
```

与 `expand_to_target.py` 的保函数扩容同源（Net2Net）。**模块挂上去，主干原有输出一比特都不变。**

### 4.2 SVD 截断（目标维 < 源维）— 不保函数

不能"砍掉一半"了事，那会直接毁掉旧行为。正确做法是低秩重构后截断，取误差最小投影：

```
U, S, Vh = svd(ΔW)
ΔW' = (U·S·Vh)[:d_out', :d_in']
```

这不是保函数，**装完必须短程重训补偿**。工具会显式告警。

### 4.3 层数不匹配

- 目标层数 **少** → 多余层丢弃（模块最深那几层的行为丢失，通常无感）
- 目标层数 **多** → 新增层没有模块，保持主干原样（这本就该由重定位补）

## 五、`interface.json` schema

每个模块目录下必须有一份，声明它依赖主干的什么、能移植到什么程度。

```json
{
  "module": "polaris-code-zh",
  "version": "0.1.0",
  "kind": "behavior",

  "requires": {
    "architecture_family": ["llama", "qwen2", "mistral"],
    "hidden_size": "any",
    "num_hidden_layers": "any",
    "vocab_size": "any",
    "tokenizer": "any",
    "note": "不依赖任何主干常量；维度全部运行时探测"
  },

  "attach_points": [
    {"slot": "q", "dim": "hidden",    "class": "constant"},
    {"slot": "k", "dim": "kv_dim",    "class": "constant"},
    {"slot": "v", "dim": "kv_dim",    "class": "constant"},
    {"slot": "o", "dim": "hidden",    "class": "constant"}
  ],
  "forbidden_points": ["gate_proj", "up_proj", "down_proj", "embed_tokens", "lm_head"],

  "portability": {
    "L0_same_lineage": "direct",
    "L1_same_arch": "zero-pad",
    "L2_cross_arch": "zero-pad + relocate (short finetune)"
  },

  "io": {"chat_template": "chatml", "loss_mask": "completion_only"},
  "acceptance": {"in_set_ce_lt": 0.6, "blind_test": true}
}
```

**设计约束**：模块代码里**不允许出现任何主干维度常量**。所有维度从 `config.json` 读，所有模块名从 `named_modules()` 探。

## 六、模块设计检查清单

- [ ] target_modules 只有 `q/k/v/o`（要加 MLP 必须写进 `forbidden_points` 的例外并说明理由）
- [ ] 没有任何 `hidden_size = 576` 这类硬编码
- [ ] 没有假设层号（`layers.35` 只在自家 36 层成立）
- [ ] 不碰 tokenizer / embedding / lm_head
- [ ] 自带 `interface.json` 与 `module.card.json`
- [ ] 移植后跑过 `module_loader.py verify`，`max|diff|` 必须为 0（零填充路径）
- [ ] **跨血统移植必须跑无 system 生成对照**——带 system 时强模型会复述提示，制造"模块生效"的假象
- [ ] 验收含盲测，不只看 loss

## 七、边界（诚实说明做不到的）

1. **跨血统不能"零成本"**：形状能对齐，语义不能。Qwen 实测挂了模块与不挂一字不差，甚至更差。
   **正解不是搬权重，是带走数据与标准，在新主干上重训行为**（几百条、小时级）。这才是模块化的兑现方式。
2. **真正零成本通用的形态是指令层**，不是权重。一句 system prompt 挂哪都能用，代价是表达力弱。
   权重模块表达力强但绑血统——这是取舍，不是缺陷。
2. **fused 投影（`c_attn` / `query_key_value` / `Wqkv`）不自动拆**：q/k/v 拼接规则各家族不同，硬猜会静默错位。要么人工给映射，要么不支持。
3. **模块不带知识**。想要"这个领域的深度"，那是另一个模块（检索 / TTT / 记忆层）的事，不是行为模块能给的。

## 八、工具

```bash
# 探测主干规格 + 接入点方言
python tools/module_loader.py probe --model <主干目录>

# 对比模块与主干的形状差异
python tools/module_loader.py diff  --model <主干> --adapter <模块>

# 生成可装载到目标主干的模块副本
python tools/module_loader.py port  --model <主干> --adapter <模块> --out <输出>

# 逐位校验保函数
python tools/module_loader.py verify --model <主干> --adapter <模块> --dst <输出>
```
