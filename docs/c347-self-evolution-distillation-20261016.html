0. 原始问题

如何在本地训练的小模型（0.5B 级别）上实现「模型自进化」闭环：让云端强模型产出精炼数据喂给它变强，变强后再自我复制扩容。设计工程闭环——

  • 数据飞轮如何避免退化 / 塌方
  • 评测器如何不被闭环自身修改
  • 扩容时如何保证保函数（权重继承可审计）
  • 每一步的可验证判据

1. 总体架构：三域隔离 + 单向闸门

97% 的回答明确采用「信任域」划分，是整张蓝图的底座。

域 A · 编排–训练（可写，仅追加） Orchestrator（纯编排，无裁决权）· Teacher Gateway（云端强模型，版本冻结）· Admission Gate（D0–D1 强制判定）· Immutable Data Lake（内容寻址 + Merkle 根）· Trainer（固定 seed/分词/学习率/代码 hash）· Scaler（Net2Net/Wider/Deeper）
↕ 只读挂载：A 读 B 的模型快照 / B 读 A 的数据快照（双向无写）
域 B · 评测–锚点（只读，闭环无写权限） Eval Service（独立容器/VM，只读根文件系统）· Gold Set（加密，永不回流训练）· Canary/Holdout（盐值+计数器，每 5 轮解封）· Smoke Set（固定探针）· Judge Ensemble（规则 + 2–3 LLM-Judge + Sandbox Oracle）· Statistical Verifier（Bootstrap CI / KS / 漂移检测）· Gate Attestation（通过才签名放行）
通过则签名放行 →
域 C · 制品库（write-once + sigstore/cosign 签名） Weight Manifest（parent_id / target_id / strategy / delta-hash / function_preserve_error）· Training Proof Bundle（ckpt hash + data-snapshot hash + config hash）· Eval Report（hash + verdict + regression_delta）· Audit Log（append-only，cosign 签名）

单向知识流：Teacher → Admission Gate → Data Lake → Trainer → Checkpoint。学生（本地 0.5B）的输出永不进入 Data Lake 当主训练数据，只能作为「待教师判分/改写的候选」。

2. 五条铁律（不可妥协）

#铁律工程含义
L1单向知识流知识只从「云端强模型(Teacher) + 人类锚点(Anchor)」流向学生；学生输出绝不直接成为训练数据
L2评测面物理隔离Eval / Gold / Judge 在权限、代码库、硬件、网络上独立于训练闭环；闭环任何组件无写权限访问评测域
L3制品不可变·可追溯·可回滚所有数据/权重/报告/清单内容寻址（CID = sha256(payload‖meta)），只追加不可覆写；回滚只能切到上一份已签名 Manifest
L4功能保守扩容扩容在 t=0 满足函数等价（max|Δlogit| ≤ 1e-6 ~ 1e-5，固定 smoke set），shadow run 验证训练可达性与能力非劣性（per-slice ≥ old−1%）
L5可验证判据每一步都有量化、可复现判据；未通过即自动拒绝或回滚，不得由模型/编排器自行豁免

防「教到考」三招（多个回答独立提出）
  • 泄露嵌入防御：对每条 candidate 算与 Gold Set 的 max 余弦，>0.95 即拒收并告警（潜在评测集记忆）
  • Canary Injection：评测时注入密封探针，仅返回签名后的 pass/fail 摘要，分数永不出评测域
  • 评测集防泄露：ngram 重叠 = 0 为硬红线；每次 eval 后 overlap>0.9 的 candidate 打标，下次拒收

5. 扩容保函数 + 自我复制（R1/R2/R3）

与本项目「保函数扩容链」同构：深度/宽度优先，所有权重变更可审计、可回滚。

Function-Preserving Test（FPT）— t=0 logit 检查 
python
def fpt_check(model_old, model_new, smoke_set, threshold=1e-6):
    for prompt in smoke_set:
        if max(abs(model_old(prompt) - model_new(prompt))) > threshold:
            return FAIL
    return PASS   # 之后还要 shadow run: Δacc ≤0.5%, Δlatency ≤30% 才 A/B 放开

8. 补充创新点（cat-jam 等少数回答提出的「第五根桩子」）

  • 分布锚定 / 蒸发闸门（Distribution Anchoring）：把 0.5B 的「知识」切成可测单元（reasoning/code/math/knowledge/format/safety），每轮在 per-slice held-out 上报绝对 pass@1。任一切片 < baseline×0.95 → 本轮 veto。针对「灾难性遗忘不是总分降，而是某能力 invisible evaporates」这一传统总分监控抓不到的盲区。
  • Anchor Flush Budget（动态锚定带宽）：Anchor 比例不固定 15%，而是 min(0.4, max(0.15, 1 − Δ_max_slice + 0.05))——哪片掉就补哪片，用数据锚定分布而非权重锚定。
  • Sink Detection + Provenance Chain：每条样本强制 meta 字段（teacher_version / prompt_hash / seed / parent_cid …），CID = sha256(payload+meta) 入 Merkle 树；Data Manifest 用 git tag 签名，回滚 = checkout tag（byte-identical）。
  • Leaked Embedding Defense：admission 时对 candidate 做与 Gold Set 的嵌入余弦，>0.95 即拒收并告警。
