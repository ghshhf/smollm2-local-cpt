## 2. 结构性结论（改路线认知的）

1. **压缩最优容量点落在 0.2B–0.4B（三值口径）**。逐级扩到 0.4B 与语料自洽；**0.5B 只需语料 1.3×**（约 +11 亿 token），是廉价一步；**1B 起才是真悬崖**（3.3× 起步，且越来越贵）。
2. **矛盾 1（真）**：过 N* 后每个 plateau 在定义上都是数据受限 → Gate 1 会永远拒绝扩容。**必须在 0.4B 前把「模块插入分支」写进 Gate 1**（词表/认主/记忆/蒸馏 = 不走纯缩放通道的能力增长）。
3. **embedding 量化是 0.5B 的真分叉**：照搬 BitNet 原配方（embedding fp16）→ 有效 bits/param 5.5 → N* 减半到 ~193M，3.5B 语料即过最优。**要么量化 embedding（保 2bit 记账、N*=411M），要么接受更早触顶**。须在 0.5B 架构冻结前拍板。
4. **矛盾 7（真空白）**：「累积不替换」的文献保证**不覆盖多 epoch 重复**。咱们 35 亿 token 必然多 epoch → 需自建判据（分层 NLL 尾部收缩 P7/P16），标【需消融】。
5. **M-DRIFT 精确化**：「fp32 潜变量上操作」单独不充分（组共享 α 仍会被零行稀释）；须「冻结旧符号 + 冻结该行 α」。与咱们 v2 已实测的分块 γ（跳变 0.0000）同族、更严，纳入扩容协议。
6. **引文三处自纠 + Titans 数字自删**：bert2BERT 45/47%（原 64.4% 错）、LiGO=ICLR 2023（GPT2-1.5B ~39%）、Memory Layers «不增 FLOPs» 原文 §1/§5.4 确有（上版检索失败，非来源缺失）。核验纪律（全文句级检索）已升级。

## 3. 模块插入点设计规格（要点）

- **认主头**：不承担拒绝服务（可被风格迁移绕过）；负样本 ≥300（rule of three，声称 FAR<1%）+ ≥20 作者×≥10 主题；**验收=主干线性探针 vs 打乱标签基线**，探针显著高于基线即不通过。
- **记忆层**：选型判据=「首 token 延迟 + 内存峰值 + 删除演练（0/1 硬判据）」；原文 «almost entirely memory bandwidth bound» → FLOPs 不是绑定项；训练三阶段、主干永不解冻。
- **蒸馏桥接**：50k 词表 full-KL 发散，必须 top-k 截断 + 被截断概率质量作必报诊断；「无损压进三值」信息论不可达，写成「能力 C/测 M/分布 D/容差 τ」；**fp32 扩展后量化**是唯一能分离「架构重置损失 vs 蒸馏增益」的对照臂。
