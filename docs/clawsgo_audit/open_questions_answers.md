## §0 先说：你清单里被推翻或修正的六条前提

### 修正 1 —— Q-12 的「三层收益乘性叠加」不成立〔推断〕

**输入压缩（词表）不降低 bits/汉字。** 它降低的是**序列长度**（计算量与上下文成本），不是信息量。算术编码的码长由负对数似然给出（Delétang 等原文：`the expected message length in bits of an optimal entropy encoder is equal to the negative log-likelihood of the statistical model`）〔原文〕——而 $$\sum_i -\log p(t_i)$$ 在换词表时**近似不变**：词少了，每个词携带的比特就多了。

**输出压缩（算术编码）不是第三层增益**，它是**把交叉熵兑现成码长的机制**——即它本身就是"怎么测"，不是"多赚一份"。

**所以真正的分解只有两项**：

$$\text{adjusted rate} \;=\; \frac{\underbrace{b_{\text{eff}}\cdot N}_{\text{模型比特}} \;+\; \underbrace{D\cdot H_{\text{nat/token}}}_{\text{数据比特}}}{D\cdot 32}$$

词表改的是 $$(D, H)$$ 而保持 $$D\cdot H$$ 近似不变；三值改的是 $$b_{\text{eff}}$$。**只有第二项是真杠杆，而且它只在语料小时才显著**（因为模型比特要被数据比特除）。你们恰好语料小，所以三值对你们**特别值**——这条结论没变，但理由换了。

**一条来自原文的旁证**：Delétang 的论文里**专门有一节比较不同 tokenizer（ASCII vs BPE）与不同词表大小对 raw compression rate 的影响**，并报告 adjusted compression rate 超过临界点后随参数增多而**变差**〔原文〕。也就是说，词表效应在原文框架里是**一个被测量过的、量级不大的效应**，不是 44% 的独立乘数。

### 修正 2 —— Q-08 的「文献空白」不再空白〔二手〕

我前两轮两次说过「固定语料多 epoch 是文献空白」。**本次检索到一篇正面对撞的工作**：标题直译为《重复训练数据在四到十个 epoch 内近乎免费：约束"免费重复带"的是记忆化起始点，而非容量-熵比》。

其摘要级要点（〔二手〕，未读到全文）：**218 次受控训练**；免费重复带是一个**有界的 4–10 epoch 区间**；带的坍塌在 9 个格子中的 8 个与**canary 记忆化起始**同时发生；超过阈值后超额损失随 epoch 数**约二次到三次增长**；这一结构是**容量不变的**（容量-熵比变化约 100 倍也不移动）；换优化器（Muon）把带向外推约 2.5 倍而非消除。另有一条更强的结论：**重复次数是记忆化的首要驱动因素之一，越频繁出现的串越容易被记住**〔二手〕。

**对你的意义**：你的「0.1B–0.4B 默认单遍」在 4–10 这个区间之内，**是安全的**；但「安全」的可测形式是**记忆化起始点**，不是 epoch 计数本身——所以判据要落到"记忆化"这个可观测量上（见 Q-08）。

### 修正 3 —— Q-05 的归因问错了方向〔原文〕

你把「小模型 ICL 弱」归因为**层数不够 / 头不够 / 训练数据格式**。Chan 等（NeurIPS 2022）原文摘要第一句就是答案：

> `Here, we show that this behavior is driven by the distributions of the training data itself. In-context learning emerges when the training data exhibits particular distributional properties such as burstiness (items appear in clusters rather than being uniformly distributed over time) and having large numbers o[f]...` 〔原文，摘要〕

**即：驱动 ICL 的是数据的分布性质，不是规模。** 原文还指出：**在错误的数据分布（均匀 i.i.d.）上训练的 Transformer 同样不表现出 ICL**；并且**架构也是必需的**——同样的自然分布，LSTM/RNN 不出现 ICL〔原文〕。

**这条直接指向你的预处理管线，而不是你的架构。** 两个常规预处理动作会**精确地破坏**这些性质：
- **文档级随机打乱（shuffling）会摧毁 burstiness**——同一实体不再成簇出现；
- **强去重（dedup）会砍掉长尾类**——而长尾类正是原文列出的第二个驱动因子。

**我的推断（优先级最高的一条可执行改动）**：你的小模型 ICL 弱，很可能**主要是预处理造成的，而不是容量造成的**。这是一个**可以在不改模型的情况下验证**的假说。

### 修正 4 —— Q-02 的口头置信度在小模型上无效〔二手〕

一批工作在 **3–9B** 的指令微调模型上发现：7 个模型里有 6 个在 **超过 87% 的试验中给出 ≥95% 的置信度**，作者把它称为**"有效性失败，而不是校准失败"**〔二手〕。另一条同方向的结论：口头置信度（CE）在三类不确定性方法里最差，因为系统性过度自信；而**样本一致性（sample consistency）优于 token 级概率与口头置信度**〔二手〕。

**对你的意义**：**元认知头必须读激活，不能读模型说出来的话。** 你的设计方向是对的，这条证据把它从"选择"升级成"必须"。同时它给出一个更好的探针（见 Q-02 的探针 B）。

### 修正 5 —— Q-14 的「576 维够吗」问错了量〔二手〕

ArcFace 的原始设定是 **512 维**〔二手〕，而你们的 576 维 hidden **绰绰有余**——身份数是 1–2 个，这是一个容量上极其宽松的问题。真正的限制在别处，而且文献里有一条直接相关的负面结论：

> 在少样本设定下比较时，ArcFace 损失**在多数测试中发散，只在一个案例里收敛**；作者结论是 ArcFace **对边际参数 m 极度敏感**，且"**与未归一化的 triplet loss 不可比**"，后者更稳健〔二手〕。另有工作报告：在小型、长尾的数据集上微调 ArcFace 反而**过拟合**——已知类提升而未见类下降〔二手〕。

**所以我的建议是反的**：**先用未归一化 triplet，不要一上来就上 ArcFace**。ArcFace 的角边际是为"几万类、百万样本"设计的，你只有一两个身份。约束改为：
- 有效维度用 **participation ratio**（协方差特征值的有效秩）度量，而不是标称维度；
- 判据是**间隔**（owner 与非 owner 的余弦间隙）而不是损失值；
- 只在 triplet 的间隔不够时，再引入角边际，并且 **m 从 0 开始扫**。

### 修正 6 —— Q-09 里 SWA/MoD 的合法性在 0.5B 与 0.1–0.4B 不同〔推断〕

**「禁改注意力」约束的适用对象是"扩容"**——即必须保住一个已存在的函数。**0.5B 是架构从零**，那里**没有旧函数要保**，所以 SWA、MoD 在 0.5B **是合法的设计选择**，而在 0.1B→0.4B 的扩容链上**不合法**。这条区分你的清单没有显式写出来，但它决定了 Q-09 能不能问。

**不过我要立刻加一句反方向的**：Gemma 3 的 **5:1 局部/全局比、窗口 1024** 是**为 128K 上下文**设计的，其收益是 **KV 缓存**〔二手〕。**你的 0.5B 端侧场景上下文不长、目标 CPU 15ms/token**——SWA 会**改变函数**（代价真实）而**收益（KV 缓存）在你的上下文长度下很小**。所以：**0.5B 第一版不要上 SWA**，只在上下文长度成为实测瓶颈时才作为 v2 候选。MoD 同理（见 Q-09、以及主报告 §1.4 的带宽/算力判定）。

## §1 理论真空带（Q-01 → Q-08）

### Q-01 知识的物理载体与定位

**① 机制（最佳现有理论）。** 有一条成熟的方法线叫 **causal tracing（因果追踪）**，原文摘要逐句已核：

> `We analyze the storage and recall of factual associations in autoregressive transformer language models, finding evidence that these associations correspond to localized, directly-editable computations.` … `This reveals a distinct set of steps in middle-layer feed-forward modules that mediate factual predictions while processing subject tokens.` 〔原文，摘要〕

具体做法是三次前向：(a) 正常跑；(b) 把**主语 token** 破坏掉（换成无关词）；(c) 逐层逐位置把 (a) 的激活**恢复**进去。恢复哪个位置的激活能让正确的宾语回来，那个位置就是承载该事实的地方。结论是**中层 MLP，且作用在主语 token 的位置上**〔原文〕。

**必须同时知道的一条反面证据**：后续工作发现**因果追踪的定位结果不能告诉你该编辑哪一层**——轨迹效应与编辑成功率只在一种受控设定下相关，且只能解释编辑表现方差的一小部分；选择编辑层比定位更重要〔二手〕。也就是说：**"事实存在哪"与"改哪里能改掉它"是两件事**。

还有第三条路线与上面两条竞争：**token embedding 在 Layer 0 充当实体身份（关联记忆的主键）**，下游层只是按这个键检索属性，且**不对身份做校验**〔二手〕。

**② 可执行方案。** 好消息：**causal tracing 只需要前向，CPU 完全跑得动**——这正是 node1 最该先做的机制实验。

```python
# 因果追踪：对 214M 模型，CPU 可跑
def causal_tracing(model, facts, n_prefix=10, layers=None, positions=None):
    # facts: [(prompt_with_subject, subject_span, expected_object), ...]
    aie = zeros(len(layers), len(positions))   # average indirect effect
    for f in facts:
        clean_logit = forward(model, f.prompt)[f.expected_object]
        for prefix in sample_random_prefixes(n_prefix):
            # (b) 破坏主语
            corrupt = replace_span(f.prompt, f.subject_span, random_token(prefix))
            base_logit = forward(model, corrupt)[f.expected_object]
            # (c) 逐点恢复
            for L in layers:
                for T in positions:
                    act = get_activation(model, f.prompt, L, T)      # 干净激活
                    logit = forward_with_patch(model, corrupt, L, T, act)[f.expected_object]
                    aie[L, T] += logit - base_logit                  # 间接效应
    return aie / (len(facts) * n_prefix)
# 判读：aie 的热图若在中层、主语末 token 处出现尖峰 → 定位成立
```

**成本估算（数量级，缺 B 与层数精确值无法精确判定）**：设 L=36 层、采样 13 层、主语位置 10 个、事实 100 条、前缀 10 个随机样本 → 约 **3.9 万次短前向**。每次前向是 10–20 个 token，在 64 核 CPU 上按你们 214M 的基准外推约 **0.1–0.3 s** → **1–3 小时**。**这是 node1 上性价比最高的机制实验之一。**

**③ 可证伪判据。**

> **FQ-01**：若 AIE 热图**不出现局部尖峰**（效应在层与位置上近似均匀，或尖峰不在中层 MLP 而在输入嵌入层），则「事实局部存储于中层 MLP」在你这个规模上**不成立**，第三种路线（嵌入即主键）更可能。
> **判据数值**：尖峰的 AIE 值须 ≥ 平坦背景的 **3σ**（σ 由不同随机前缀间的方差给出）。

**④ 对你装记忆层的直接后果。**
- **若尖峰存在（局部化成立）**：记忆层应挂在**中层 MLP 的读出路径**上，并且你可以用 rank-one 式干预做**事实修正**（这对个人记忆的"取代"需求极其有用，见 B1）。
- **若尖峰不存在**：记忆层应挂在**嵌入/输出接口**，因为身份与属性都在同一处流动，往中层塞东西会被下游的"不校验身份"逻辑吞掉。

**不确定的部分**：上述全部证据都来自 GPT-2 XL / LLaMA 级模型；**214M 是否仍有同样的局部化结构，没有原文支持**——这正是 FQ-01 要测的。

### Q-02 幻觉边界与「自知无知」的可训练性

**① 机制。** 校准难压的**结构性原因**是：模型的 softmax 概率反映的是**训练分布的频率**，而不是**它自己答案的正确率**。两者在分布内一致，在长尾与分布外分离。更麻烦的是：**在小模型上，连"说出来"的置信度都无效**（§0 修正 4：3–9B 上有 6/7 个模型 87% 以上的试验给出 ≥95% 置信度，被作者称为有效性失败而非校准失败）〔二手〕。

**② 关于你的探针假设（E2），我的预测与更好的替代。**

**预测**：「高 NLL 且低熵 = 系统性空洞」**部分成立，但会被一类假阳性淹没**。
- 真阳性（你要的）：模型**自信地做错**一个它"应该会"的任务 → 低熵 + 高 NLL。
- **假阳性（致命的那类）**：**长尾内容本身就是低熵高损失的**——罕见专名、随机编号、技术术语。模型对**格式**很确定（低熵），对**取值**不可能知道（高 NLL）。**这类片段在自然语料里占比很高**，会把簇填满。

**探针 B（我建议的替代，成本同样低）：用"语义一致性 × 正确率"二维分类，而不是逐 token 熵。**

```python
# 探针 B：区分「能力空洞」与「知识缺失」
def probe(segment, model, k=8):
    outs = [sample_continuation(model, segment, temperature=1.0) for _ in range(k)]
    sem_entropy = semantic_cluster_entropy(outs)   # 用句向量聚类后的熵
    loss = nll(model, segment)
    ref = reference_continuation(segment)          # 留出集里的真实后续
    consistent_wrong = (sem_entropy < tau) and not matches(outs, ref)
    divergent        = (sem_entropy > tau)
    return {'capability_hole': consistent_wrong,   # 自洽地错 → 能力空洞
            'knowledge_gap'  : divergent,          # 发散地猜 → 知识缺失
            'loss': loss}
```

**为什么这样更好（理论可答）**：**能力空洞与知识缺失的可分性来自"模型对自己的错误是否自洽"**。一个能力空洞是**系统性**的——多次采样都会错得**同一方向**；一个知识缺失是**局部**的——多次采样会给出**互相矛盾的猜测**。逐 token 熵读不到这个区别（它只读单个位置的分布形状），而**跨样本的语义聚类能读到**。这也与 §0 修正 4 的方向一致：**样本一致性优于 token 概率**〔二手〕。

**元认知头的接入位置与训练目标（你问的）：**

```
接入位置：中层到中后层的【主语/答案位置的末 token】残差流
         —— 与 Q-01 的因果追踪尖峰位置对齐；先用追踪结果定，再固定
结构    ：单层线性 → sigmoid → 标量 ŷ（不产生文本）
训练目标：BCE( ŷ , 1[模型自己采样出的答案是错的] )
         —— 标签必须来自【模型自己采样】的答案，不能用教师的
理由    ：头要预测的是"我会不会错"，所以标签必须是"我实际错没错"
```

**③ 可证伪判据。**

> **FQ-02a（探针 B 相对探针 A）**：若「能力空洞」类片段的**语义熵不显著低于**「知识缺失」类（即二维分类退化成一条线），则探针 B 的设计被证伪，退回探针 A。
> **FQ-02b（元认知头是否必要）**：做一个**只做温度缩放（post-hoc temperature scaling）的基线**。若一个全局温度就把 ECE 降到与元认知头同级，则**元认知头不必要**——这是最该先跑的对照，因为它便宜到可笑（几分钟）。**不做这个对照，你的元认知头有可能只是在学一个温度参数。**

**④ node1 最小版本**：探针 A 与 B 都是**零训练**（只需前向 + 采样），半天可出结果；元认知头是一个线性层，几十分钟可训完。

### Q-03 Grokking 的机制与主动利用

**① 机制。** 目前最受支持的机制是 **lazy → rich 转变**〔二手〕：
- 早期网络在**惰性（核）区域**拟合训练集——相当于以初始 NTK 做核回归；
- 后期**特征开始移动**（rich 区域），找到泛化解。

有一条新的定量理论把这条路径写成了可测的形式：对带 L2 权重衰减的齐次网络，记忆之后会剩下**有限残差**，残差最大的分量对应**最小的 NTK 特征值**；这些残差反过来推动 NTK 演化，形成"残差驱动的核增长 vs 权重衰减"的竞争；其绝热极限预言 **grokking 时间尺度由 $$\eta\lambda_W$$ 的乘积控制**（$$\tau \approx \eta\lambda_W(s-s_{\text{fit}})$$），并给出 $$(\eta\lambda_W)^{-1}$$ 的标度律〔二手〕。**相位图**包含：小 $$\eta\lambda_W$$ 的广泛记忆区、grokking 带、模式可达性截断、训练拟合截断、以及大学习率的稳定边界〔二手〕。

**同时有一条重要的否证**：**grokking 并非必须有权重衰减**——大的初始权重范数会近似线性化模型并诱发 grokking〔二手〕。

**② 主动诱导方案（你的 Q4 是被动检测，这是主动版）。**

```python
# 在【结构化子任务】上主动诱导 grokking（不适用于大语料预训练）
诱导配方：
  1. 数据集缩小到"刚好能被记住"的规模 —— 小数据集是 grokking 的必要条件
     （原文：smaller datasets require increasing amounts of optimization for generalization；
       数据集大时训练与验证曲线同步、无间隙）〔原文〕
  2. 提高 weight decay λ → 走相位图里向"grokking 带"的方向
  3. 监控 ηλW 的乘积，而不是单独调 η 或 λ
  4. 训练时长必须 >> 常规早停点（grokking 的定义就是"过拟合之后很久"）
单旋钮顺序：先加数据？不 —— 先缩数据 + 加 λ，最后才动 lr
```

**③ 一条必须点破的限制：主动诱导 grokking 与你的单遍语料原则冲突。** Grokking 的前提是**同一小数据集反复训练**，而你们 0.1–0.4B 默认单遍。所以：
- **在大语料预训练上，主动诱导 grokking 不适用**（原文的规模依赖结论直接排除）；
- **在结构化技能上（算术、格式遵循、代码语法）适用**，且这些技能恰好是你可以**单独造小数据**的。

**④ 可证伪判据。**

> **FQ-03**：把某技能既用「小数据 + 高 λ 诱导 grokking」教，也用「全语料直接教」，比较**最终性能**。
> - 若两者最终性能相同 → **grokking 只是一条更慢的路，不产生额外能力，主动诱导无价值**（我认为这是最可能的结果）。
> - 若诱导路线的最终性能更高 → 说明数据效率上真有差异，值得深挖。
> **不确定带**：两次运行在留出集上的差异若落在 σ 内，判为不确定，不要解读为"有趋势"。

**⑤ node1 最小版本**：一个 50M 以内的模型 + 一个合成的模运算或格式任务，几百步；用 **3 组 $$(\eta, \lambda)$$ 组合**扫相位图的一个小角。**半天到一天。**

**不确定的部分**：上述相位图结论全部来自**模运算 + 齐次 MLP / 单块 Transformer**〔二手〕；向语言建模任务的迁移未经验证。

### Q-04 STE 为什么有效 + 三值 QAT 的失败边界

**① 理论（这是本清单里我找到的最干净的答案）。** STE 产生的**不是真梯度**，学界的正式名字是 **coarse gradient（粗梯度）/"biased first-order oracle"**〔二手〕。为什么沿它下降还能work：

1. **与总体梯度正相关**：若 STE 选得合适，粗梯度的期望**与总体梯度正相关**；因此其负方向仍是**下降方向**（不保证是最速下降方向）〔二手〕。
2. **收敛性有证明**：对**二层、二值激活、高斯数据**的网络，粗梯度下降**收敛到总体损失的一个临界点**〔二手〕。
3. **STE 的选取不是任意的**：一个"好"的替代导数应当**单调**——具体地，形如 `g(x)=0 (x≤0)` 且 `g'(x) ≥ δ > 0 (x>0)` 的替代函数被证明能收敛；**而恒等 STE 在单层感知机上可行，在多层的网络上会失败**〔二手〕。

**② 由此得到一条可执行结论：不要用恒等 STE，要用单调有界的替代导数。**

```python
# 三值量化前向 + 反向（推荐形式）
def ternarize_forward_backward(W, alpha):
    # 前向：硬三值
    q = torch.clamp(torch.round(W / alpha), -1, 1)     # W in [-1,1]*alpha
    # 反向：单调、有界、在量化台阶"内部"为 1，跨界处衰减
    #   —— 不要用 1（恒等 STE）；用截断形式抑制边界振荡
    with torch.no_grad():
        gate = (torch.abs(W / alpha) < 1.0).float()     # 只在可分辨区内传梯度
    return q * alpha + (W - (W * gate).detach() - (W - W * gate).detach()) * 0  # 见下注
# 注：实现上即 q_ste = W + (q*alpha - W).detach()
#     再把 d/dW 按 gate 加权，避免"已饱和坐标继续被推"
```

**③ 三值 QAT 的失败边界与预警信号清单（你问的核心）。**

先说一句诚实的话：**「模型规模下限 / 数据量下限 / 任务类型」这三个是否构成失败边界，目前没有原文级证据——【需消融实验】。** 但我可以从 α 的统计性质给出**一条可检验的预测**，而且它正好解释你们已有的观测：

> **【推断】α 的估计噪声与稀释是一对反向的力。**
> α 是从一个组内的权重取均值得到的统计量，其相对标准差约 $$\propto 1/\sqrt{n_{\text{group}}}$$。
> - **组越大**（逐张量）→ α 越稳，但扩容时被稀释得越厉害（$$\alpha' = \alpha\, n/(n+k)$$）；
> - **组越小**（逐行）→ 稀释被限制在行内，但 α 本身噪声大 → **零锁与边界振荡的风险上升**。
>
> **推论：存在一个最优的 α 组大小**，而你们观测到的「全局共享 α 跳变 1.70%」与「分块 α 跳变 0.0000」正是这个张力的两端。**分块 γ 跳变 0 是好结果，但它把风险从"稀释"搬到了"估计噪声"上，而后者还没被测量过。**

**预警信号清单（全部是可在训练日志里逐 step 算的标量）：**

| 编号 | 量 | 定义 | 预警方向 |
|---|---|---|---|
| **W1** | α 崩溃 | $$\alpha_t / \alpha_0$$ 的滑动均值 | 单调下行 → 大量坐标被推向 0（零锁前兆） |
| **W2** | 零锁率 | 落在 $$|W/\alpha|<0.5$$ **且**梯度指向网格内 的坐标比例 | 上升 → 这些坐标不会再被激活 |
| **W3** | 边界振荡率 | 落在 $$0.4 < |W/\alpha| < 0.6$$ 的坐标比例随时间的变化率 | 高频振荡 → 学习率过大或 STE 不合适 |
| **W4** | 梯度同质化 | 逐坐标梯度的余弦相似度的均值 | 上升 → 优化退化为少数方向（三值特有） |
| **W5** | α 组内方差 | 组内 $$|W|$$ 的离散度 | 过大 → 该组的 α 没有代表性，量化误差集中 |

**④ 可证伪判据。**

> **FQ-04a**：把恒等 STE 换成单调有界 STI，若 W3（边界振荡率）**无改善**，则"STE 选取影响三值稳定性"在你方不成立。
> **FQ-04b（α 组大小的最优性）**：在**同一模型、同一数据**上，只改 α 组粒度（逐张量 / 逐块 / 逐行），测 W1–W5。
> **预测**：存在一个中间粒度使 **W2（零锁）与稀释同时最小**；两端（逐张量、逐行）各有一项指标显著更差。
> 若 W1–W5 对粒度**完全不敏感**，则本条推断被证伪，粒度只是一个实现细节。

**⑤ node1 最小版本**：W1–W5 是**纯日志后处理**，不需要新训练——**对你们已有的 1.70% 实验重算一遍就能得到**。这是我认为**本周就该做**的第三件事（另两件见上一轮的 Q1、Q2）。

### Q-05 ICL 在小模型上弱在哪 —— 见 §0 修正 3

**① 机制（已核原文）。** Chan 等：ICL **由训练数据的分布性质驱动**——**burstiness**（同一项成簇出现而非均匀分布）、**大量长尾类**、**动态含义**、**Zipf 型类频率**〔原文，摘要与正文〕。且：**在错误分布（均匀 i.i.d.）上训练的 Transformer 同样不出现 ICL**；**同样的自然分布下 LSTM 不出现 ICL**；原文结论是 `attention is not all you need—architecture and data are both key`〔原文〕。

**另一条独立的机制线**：**induction heads**（`[A][B] ... [A] -> [B]` 的复制头）在训练**恰好在 ICL 能力突增的同一点**出现，形成一个训练损失的"相位变化"凸起；在小模型里该行为由**两个注意力头构成的电路**（前一个 token 头 + induction 头）实现〔原文，摘要〕。作者自己强调这是 `preliminary and indirect` 的证据，且**"induction heads 解释 ICL 的论据在小模型上比在大模型上更强"**〔原文〕。后续工作还发现更关键的是 **function vector（FV）头**，而许多 FV 头是从 induction 头演化来的〔二手〕。

**② 可执行方案：把 ICL 当成数据设计问题，而不是架构问题。**

```python
# SFT / 继续预训练数据的 ICL 诱导配方（不改架构）
1. 恢复 burstiness：
   - 【停止文档级全局随机打乱】。改为：同一来源/实体的文档在序列内【成簇】
     具体做法：按主题或实体做聚类，同一簇内连续拼接，簇间再打乱
2. 保留长尾：
   - 去重阈值降低（或只做精确去重，不做近似去重）
   - 监控去重后的类频率分布，确保仍近似 Zipf（而不是被削成一条平线）
3. 注入显式的 in-context 映射任务（比例建议 3–8%，需消融确认）：
   - 复制任务：随机 token 序列 → 要求续写重复段
   - 映射任务：episode 内定义 [A]->[B]，同 episode 内其他 A 要求给 B
   - 关键：同一映射在【同一 episode 内】固定、【跨 episode】变化（原文的 dynamic meanings）
4. 监控指标：ICL 分数 = 序列内后段 token 的 loss 相对前段的下降幅度
```

**③ 可证伪判据。**

> **FQ-05**：**保持模型、步数、总 token 预算完全不变**，只改数据的 burstiness（成簇 vs 全局打乱），测 ICL 分数。
> - 若两者 ICL 分数**无显著差异** → 本条被证伪，ICL 弱是架构/容量问题，回到你的原假设。
> - 若成簇版本显著更高 → **你的 ICL 弱主要是预处理造成的**，这是一个零训练成本的修复。
> **阴性对照 NC-RANDLABEL**：把"簇"随机化（即打乱簇标签但保持簇结构），确认收益来自**语义簇**而非仅仅"数据顺序影响训练"。

**④ node1 最小版本**：**不需要新训练**——先做一件只读的事：**统计你们现有训练数据的 burstiness**（同一实体/主题在滑动窗口内的重复率）与**去重后的类频率分布**。**半天。** 如果发现 burstiness 被预处理抹平了，FQ-05 的答案在训练之前就已经知道一半了。

### Q-06 RL 训推理的泛化机制

**① 机制（证据分歧很大，我把锚点放在最强的一条）。** 最重的一条是 NeurIPS 2025 的《Does Reinforcement Learning Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?》，其结论：**RLVR 主要是提高采样效率（向正确路径收敛），而不是引出新的推理模式**——在小的 $$k$$ 下 RLVR 模型优于基座，但在**大的 $$k$$ 下基座模型得分更高**；RLVR 模型生成的推理路径**已经在基座的采样分布内**，且能力边界常常随训练**收窄**；而**蒸馏引入了真正新的推理模式**〔二手〕。

同时存在**反方向的证据**：合成迷宫任务上 RLVR 把空间推理从 0% 提到 50%+〔二手〕；以及一篇元分析指出「迁移」这个词在文献里至少指四个逻辑独立不同的量，多数争论是语义混淆，且**没有任何一篇已发表实验报告过一个完整的有向迁移矩阵**〔二手〕。

**② 对你的直接结论。** 在 **0.5B** 这个规模上：

> **蒸馏教师的推理轨迹优先于 RLVR。** 理由是上面前两条证据的组合：(a) RLVR 主要提升采样效率，而这个收益在小模型上更小（采样效率本就低）；(b) 蒸馏被明确指为**能引入新推理模式**的那一种；(c) RLVR 需要可验证环境 + 大量采样，**成本在 CPU 上是实打实的**，而蒸馏的样本已经在教师那里生成好了（且你们本来就要做 0.4B→0.5B 蒸馏）。

**RLVR 的正确位置是"蒸馏之后"**，作为一个**锐化步骤**，且只在你有验证器的任务上做。

**③ 可证伪判据。**

> **FQ-06**：在**等算力**条件下比较两条路线——(A) 0.4B 教师轨迹蒸馏；(B) 自产可验证题 + RLVR。
> 测 **pass@k 随 k 的曲线**（不要只测 pass@1）。
> **预测（来自上面那篇）**：B 在 pass@1 上可能更好，**A 在 k 增大时更高**。
> 若 B 在大 k 下也持续领先 → 上述"RLVR 只提采样效率"的结论在你的规模/任务上不成立，RLVR 值得做。

**④ node1 最小版本**：**先做不了。** RLVR 在 CPU 上的最小可行版本需要能自动验证的任务（例如小整数算术、括号匹配、单元测试执行），一次完整循环至少数天。**建议排到 GPU 之后。** 当前阶段：**只做蒸馏，不做 RLVR。**

### Q-07 数据配比的预测理论

**① 机制。** 你问"有没有不用先训大 proxy 的方法"——**答案是有，但形态不是"从数据特征直接预测"，而是"用多组小规模混合训练做回归"。**

- **Data Mixing Laws**（Ye 等，2024）：把数据混合律与训练步数/模型规模的缩放律**嵌套**，用少量混合配比在小规模上的结果，**预测未见过的配比**在大模型上的表现〔二手〕。
- **RegMix**：把配比选择直接表述为**回归任务**，在多种混合上训练小模型，用回归模型预测表现；**用 10% 的算力匹配或超过 DoReMi**〔二手〕。
- **BiMix**：双变量混合律，用**基于熵的轻量代理**替代昂贵的代理模型方法〔二手〕。

**所以对你最划算的是 RegMix 形态**：你们的 0.1B 就是天然的"小规模"。**在 0.1B 上跑 N 组配比 × 少量步数，拟合回归，再据此外推。**

**② 你方配比的结构性检查（这部分我给三条具体问题）。**

```
你的配比：通用 45 / 知识教育 25 / 创意 15 / 逻辑 5 / 自有 2
                                  ← 合计 92
```

**问题 A —— 有 8% 没有分配。** 这是一个明确的结构性缺口。它要么是笔误，要么是有一个未命名的类别。**这是清单里唯一可以直接判定为"错"的一项。**

**问题 B —— 「自有 2%」与记忆化起始点的耦合。** 2% × 3.5e9 = **7 千万 token**。但如果 owner_corpus 的真实规模远小于此，那么它在训练中就会以**高重复次数**被反复采样——而记忆化的首要驱动因素之一正是**重复次数**〔二手〕。**结果是：占比很小但重复很多 → 模型把个人语料"背下来"而不是"学会"**，这会同时伤害泛化与隐私（背下来的东西可以被提示词钓出来）。

> **建议改成"配额制"而不是"比例制"**：不设"自有 2%"，而设"**自有语料每遍 epoch 至多被采样 X 次**"，其余额度由通用数据补齐。**这与"单遍"原则一脉相承。**

**问题 C —— 「逻辑 5%」的信息量存疑。** 推理能力在 0.5B 这个规模上更多受**容量**门控而不是**数据占比**门控（Q-06 的结论同向）。5% 既不足以产生推理能力，也不太可能造成伤害。**它更像是一个心理安慰项**。建议：**把它并入通用，把省下的 5% 给长尾保留**（因为长尾才是 ICL 与泛化的驱动，§0 修正 3）——**但这条是推断，需要 FQ-07 检验。**

**③ 可证伪判据。**

> **FQ-07**：在 0.1B 上跑 8–12 组配比（每组几百步），拟合回归并预测一个**留出的**配比在 0.3B 上的表现。
> **预测**：留出配比的预测误差应显著低于"用默认配比的成绩"这一常数预测。
> 若回归预测**不优于常数预测**，则 Data Mixing Laws 在你这个规模/语料上不成立，配比只能靠经验试。
> **不确定带**：预测误差落在步间噪声内，判为不确定。

**④ node1 最小版本**：8–12 组 × 几百步 × 0.1B。按 19–29 s/step 外推，**一天以上**。建议**先做问题 A 的修补与问题 B 的配额改造**（零成本），再决定要不要跑回归。

### Q-08 多 epoch：学习与死记的边界

**① 机制。** 见 §0 修正 2：现在有正面对撞的工作，**免费重复带 4–10 epoch**，其边界由**记忆化起始点**界定而非容量-熵比，且容量不变、换优化器可外推约 2.5 倍〔二手〕。另外两条来自其他工作的机制性事实：**重复次数是记忆化的首要驱动因素之一**〔二手〕；以及**序列复杂度**是第二个驱动因素——简单、重复的序列更容易被记住〔二手〕。还有一条对**检测**很关键的：**序列可能被记住、遗忘、再被记住**（在 112 个 checkpoint 上只有 0.09% 的序列在每个 checkpoint 都被记住，但 3.7% 至少被记住过一次；且**随机权重扰动可以把"已遗忘"的记忆钓回来**）〔二手〕。

**这条对你们是硬警告**：**"这个 epoch 记不住所以安全"是错的判断**——记忆可能是**潜伏**的，在任何单个 checkpoint 上都看不出来。

**② 你问的"在线信号"——我给你一个，它是可算的且我没有在其他地方见过同样的形式。**

**信号：顺序似然比（order-likelihood ratio, OLR）**

```python
# 逐 batch 计算，零额外前向成本（复用同一次前向）
def olr(model, batch):              # batch: 若干条连续文档片段
    L_true = loss(model, batch)                      # 正常损失
    L_shuf = loss(model, shuffle_within_doc(batch))  # 同一批 token，文档内打乱顺序
    return L_shuf / L_true                            # ρ
# 监控 dρ/depoch
```

**为什么它能量化"记忆化"**：任何语言模型都会给真实顺序更低的损失（否则它就不是语言模型）。但**真正靠"记住顺序"来降低损失的部分，会让这个比值随 epoch 数上升**——因为被打乱的那份**不在记忆里**，而真实顺序那份**在**。而如果是**泛化**（学到了可迁移的规律），打乱版与真实版都会一起改善，比值**基本不变**。

- **ρ 平稳 → 学习（泛化）**
- **ρ 单调上升 → 记忆化**
- **ρ 上升先于外部 holdout 退化 → 它是领先信号**（这才是它有用的地方）

**第二个辅助信号（更标准）**：**梯度噪声尺度**（不同 micro-batch 之间梯度的一致性）。记忆化会让梯度方向高度一致（同一批数据反复出现），噪声尺度下降。

**③ 外部 holdout 仍然是最终裁决者**——这条我上一轮说过，这里加强：因为记忆可能是潜伏的，**"训练损失没降"不足以证明没记住**；而外部 holdout 的退化是**唯一**能穿过潜伏性的观测。

**④ 可证伪判据。**

> **FQ-08**：在第 2、3、4…遍 epoch 上同时记录 ρ 与外部 holdout CE。
> **预测**：ρ 的上升应**先于**外部 holdout 的退化（领先量至少一个 epoch）。
> 若 ρ **不随 epoch 上升**（即 ρ 对重复完全不敏感），则 OLR 不是有效的记忆化信号，本条被证伪。
> 若 ρ 上升但**晚于**外部 holdout 退化，则它是滞后信号，无预警价值。
> **阴性对照**：对比两遍 epoch 但**换不同数据子集**（不重复）——此时 ρ 应保持平稳。

**⑤ node1 最小版本**：**纯训练日志改造**，在已有训练里加几行计算即可。**半天。** 这是我认为本周该做的第四件事。

**不确定的部分**：OLR 是我基于机制提出的信号，**没有文献直接验证过**（〔推断〕）。免费重复带 4–10 的数字〔二手〕来自一篇我未读到全文的工作。

## §2 咱们路线特有的未决工程题（Q-09 → Q-15）

### Q-09 0.5B 架构最优配方

**① 机制（含一条对你 0.5B 解码成本的新发现）。**

先把自由度讲清楚（§0 修正 6）：**0.5B 是架构从零，没有旧函数要保**，所以「禁改注意力 / RoPE / 头数」这条宪法在 0.5B **不适用**。你能选的包括 SWA、MoD、GQA 比例、FFN 结构、norm 位置。这些在 0.1B→0.4B 的扩容链上则**全部不合法**。

参数量的骨架式（层状 Transformer，忽略 bias）：

$$N \;\approx\; 12\,L\,d^2 \;+\; V d \;+\; (\text{GQA 修正项})$$

其中 $$12Ld^2$$ 是 attention+FFN 的近似（FFN 比例 4 时 attention 占 1/3、FFN 占 2/3），$$Vd$$ 是 embedding（tied）。

**关键的一条成本核算（这是本清单里我认为你们最可能忽略的算术）**：0.5B 端侧解码在 batch=1 时是**内存带宽受限**，不是算力受限——时间 ≈ 权重总字节 / 有效带宽。按你们的已定方案（三值权重 + **fp16 embedding**）：

| 项 | 字节数（d≈1024, V=49152） | 占比 |
|---|---|---|
| 三值权重（按 2bit 存储 + 标度 ≈ 2.2 bit/权重） | ~124 MB | 52% |
| **fp16 embedding（tied 表）** | **~101 MB** | **43%** |
| 其余（norm / 激活缓存） | ~12 MB | 5% |
| **合计** | **~237 MB** | — |

**要打到 15 ms/token，需要约 16 GB/s 的有效带宽**〔推断，依赖实测带宽〕。这在服务器级 CPU 上可行，但**余量不大**，而且**这 237 MB 里有 43% 是 embedding**。

> **【推断，但很重要】embedding 的 fp16 决定现在成了 0.5B 解码成本的最大单项。** 你们当初定 fp16 是为了不伤词表质量，这个理由依然成立；但既然 0.5B 是**从零训**，**embedding 可以一开始就用 QAT 训练并量化**，而不必"保"任何东西。**这一项值得在 Q-09 的消融里单列一格**（fp16 vs int8 embedding 对下游 loss 与解码时间的影响）。这不是推翻决定，是提醒：**该决定是在"扩容保函数"语境下做出的，而 0.5B 不在那个语境里。**

**② 可执行方案：三个候选 + isoFLOP 消融 + 秩相关迁移检验。**

```
候选 A（保守·全注意力）  d=1024, L=24, h=16, GQA 4 KV 头, FFN 比例 4
                         优势：无新机制、CPU 内核成熟、可预测
                         劣势：KV 缓存随上下文线性涨

候选 B（Gemma-3 式混合）  同 A，但每 5 层里 4 层滑窗(1024)，1 层全局
                         优势：长上下文时 KV 缓存显著小〔二手〕
                         劣势：你的上下文不长 → 收益小（§0 修正 6）

候选 C（MoD 稀疏）        同 A，但每隔一层做 top-k 路由（k≈50%）
                         优势：平均 FLOPs 下降
                         劣势：动态计算图 → 端侧内核难写；CPU 上收益常被
                               分支开销吃掉〔二手，主报告 §10〕
```

**isoFLOP 消融的设计（这是给你的"怎么选"的可执行答案，而不是我替你选）**：

```python
# 在 ~100M 规模上做同算力比较，用秩相关判断排行榜能否迁移
configs = [A, B, C] × {d 与 L 的两个分配} × {embedding: fp16, int8}
for cfg in configs:
    train_isoFLOP(cfg, budget=固定FLOP)     # 或固定 wall-clock（CPU 上后者更实用）
    record(isolated_holdout_CE, decode_ms_per_token, peak_RSS)
# 迁移检验：100M 上的排名 vs 已有 214M 上的排名
spearman(rank_100M, rank_214M)          # 若 ρ > 0.7，认为排名可迁移到 0.5B
```

**③ 可证伪判据。**

> **FQ-09a（embedding 量化）**：在 0.5B 规模上比较 fp16 与 int8 embedding。
> 若 int8 的留出集 CE 上升 **< 0.5%** 且解码时间下降 ≥ 25% → **fp16 决定应在 0.5B 撤销**。
> 若 CE 上升 > 2% → 保留 fp16，接受带宽代价。
> **FQ-09b（架构排名迁移）**：若 100M 上的架构排名与 214M 上的排名**秩相关 < 0.3**，则"小规模消融不能预测 0.5B"成立，**必须在 0.5B 规模附近做消融**（意味着更多算力）。
> **FQ-09c（SWA 的收益）**：在**你实际的目标上下文长度**（不是 128K）上测 SWA 与全注意力的解码延迟。若延迟差 **< 5%**，则 SWA 在你这儿**不值得**（代价真实、收益为零）。

**④ node1 最小版本**：100M 规模 × 6 组配置 × 固定 wall-clock（例如每组 2 小时）。按 19–29 s/step 外推，**2–3 天**。若时间紧，**先只做 FQ-09a 与 FQ-09c 两格**（各半天量级），这两格直接改变已定决策。

**不确定的部分**：237 MB 的分解依赖我对"三值实际存储格式"的假设（2.2 bit/权重）；若你们的运行时用别的打包方式，占比会变。带宽 16 GB/s 的结论依赖 node1 实测带宽，**未测**。

### Q-10 蒸馏桥接拓扑

**① 机制。** 蒸馏有三条正交的轴，你的"拓扑"问题实际上是在这三条轴上各选一点：

| 轴 | 选项 | 关键权衡 |
|---|---|---|
| **监督信号** | logit KD / 序列级 KD / on-policy KD | logit KD 信息最密；序列级最便宜；on-policy 最贵但缩小 exposure bias |
| **散度** | 前向 KL / 反向 KL / JSD | **前向 KL = 均值寻求（mode-covering）**，学生会覆盖教师的低概率模式，小容量下会把质量摊薄；**反向 KL = 众数寻求（mode-seeking）**，学生集中抄教师最自信的模式，容量不足时更稳 |
| **温度** | T 扫描 | T→1 退化为硬标签；T→∞ 趋向均匀。小容量学生通常需要**更高**的 T |

**对你的关键约束（来自 L3 通道分离）**：0.4B→0.5B 是**架构重置**，蒸馏是**唯一**的继承通道，而这个通道被证明能传递**语义无关的行为倾向**〔二手，subliminal learning，付费墙〕。所以拓扑设计要同时优化**任务保真**与**倾向泄漏最小**。

**一条"容量缺口"警告**：教师远强于学生时，logit KD 会**伤害**学生（学生被要求匹配它无法表达的目标分布）。0.4B→0.5B 是**同规模同族**，缺口小，这是好消息——**但这也正是 subliminal 传递最强的构型**（同族）。好消息与坏消息来自同一个事实。

**② 可执行方案：三段式 + 门控 + 一个零训练检测器。**

```python
# 三段式蒸馏管线
阶段 1（对齐期）：只在【旧 49152 个 id 上】做 logit KD
    —— 新 append 的中文 token 在教师那儿没有定义，必须 mask 掉
    loss = KL( softmax(z_s/T) || softmax(z_t/T) ) * T^2  ,  T ∈ {2,4,8} 扫描
    散度先用【反向 KL】（小容量更稳），若欠拟合再切 JSD

阶段 2（轨迹期）：序列级 KD
    教师生成推理轨迹 → 学生做 teacher-forcing
    ★ 门控：对【分歧 token】做 mask（见阶段 3 的阈值来源）
    这里用前向 KL（轨迹的正确性比多样性重要）

阶段 3（on-policy 期，可选）：
    学生自采样 → 教师对学生的轨迹打分/纠正 → 只在纠正段回传
    成本最高，只在阶段 2 不收敛时启用

# 门控阈值不靠猜：由 E1 给出【分歧 token 的分布】，取分位数设阈
def gate(t, teacher, student, tau):
    d = divergence_token(teacher, student, t)   # 例如两边 top-1 不同的位置
    return 0.0 if d else 1.0                    # 或按分歧幅度软加权
```

**零训练检测器 D-CHAN（我建议先跑这个，几十分钟、零训练）**：

```python
# 学生是否继承了教师的行为指纹？不看任务指标，看【输出分布的形状】
def d_chan(student, teacher, control, probe_corpus):
    h_s = token_freq_histogram(student.generate(probe_corpus))
    h_t = token_freq_histogram(teacher.generate(probe_corpus))
    h_c = token_freq_histogram(control.generate(probe_corpus))  # 同架构随机初始化
    # 判据：学生的频率谱与教师更近，还是与同架构对照更近？
    return js_divergence(h_s, h_t), js_divergence(h_s, h_c)
# 若 D(student, teacher) < D(student, control) 而任务指标无提升
#   → 存在"任务无关的谱继承"，即 L3 通道在起作用
```

**③ 可证伪判据。**

> **FQ-10a（门控的价值）**：E1 给出的倾向传递量 与 门控后的传递量比较。
> 若门控**显著降低传递**且**任务损失上升 < 1%** → 门控该上（防御成功）。
> 若门控降低传递的同时任务损失上升 > 5% → **你买不起这份防御**，需要换更强的缓解手段（例如换非同族教师）。
> **FQ-10b（D-CHAN 是否有效）**：若 $$D(\text{学生},\text{教师})$$ 与 $$D(\text{学生},\text{对照})$$ **无稳定差异**（在 NC-RERUN 重跑下不显著），则 D-CHAN 不是有效检测器，本条被证伪。
> **不确定带**：两个 JS 散度的差落在重跑方差内，判不确定。

**④ node1 最小版本**：**阶段 1 在 CPU 上可跑**（0.4B→0.5B 的 logit KD 需要教师与学生同时驻留，214M+300M ≈ 500M 参数的 fp32 前向，64 核可承受但慢）。**D-CHAN 零训练、半天。** 建议顺序：**先跑 D-CHAN 与 E1，再决定门控阈值，最后才启动阶段 1。**

### Q-11 联网自学习的形态与安全

**① 机制。** 三个独立的危险源，必须分开处理：

1. **遗忘**：持续学习会在旧任务上退化（catastrophic forgetting）。**但注意：如果新信息只进可删除记忆层而不进权重，遗忘问题就不存在**——这正是 L3 通道分离的第二个用途。
2. **投毒**：联网取回的内容是**对抗者可控**的。文献里"后门能穿过安全训练存活"的结论〔二手，sleeper agents〕说明**过滤器不是免疫**。
3. **污染自增强**：模型生成的文本进互联网再被自己学回来，会导致退化〔二手，model collapse〕。你们的干预路径在 0.5B 前禁模型生成数据，这条暂时被挡住了——**但联网自学习一旦开，这条防线就自动失效**。

**② 可执行方案：分级准入 + 隔离地址空间 + 可删除性作为硬门。**

```python
# 三级流水线：任何外部内容必须逐级上升，不能跳级
级别 0  隔离区（quarantine）
    - 只写进一个独立的、按内容哈希寻址的库
    - 【永不进权重，永不进可寻址记忆的主库】
    - 来源白名单 + 域名分级 + 取回时间戳 + 内容哈希 + 取回者身份

级别 1  候选区
    - 通过：来源在白名单内 AND 与其他白名单来源的一致性检查通过
      （一致性 = 同一事实被 ≥2 个独立来源以非引用关系陈述）
    - 仍不进权重

级别 2  记忆层
    - 通过 L1 压缩准入规则（|∂ℓ_data/∂B_model| ≤ 1，即"存它比不存它更省"）
    - 每条记录带：内容哈希 + 来源链 + 写入时间 + 使用计数
    - ★ 删除 = 从这一层移除该记录。因为权重从没见过它，删除是【0/1】的

# 漂移阈值不靠拍脑袋，用【参考噪声宽度】定
def drift_threshold(model, fixed_probe_set, n_repeats=20):
    # 在模型权重完全不变的情况下反复评估同一探针集
    # —— 得到的是"评估本身的噪声宽度"（批顺序、数值非确定性）
    scores = [evaluate(model, fixed_probe_set) for _ in range(n_repeats)]
    return k * std(scores)      # k 取 3–5；这才是"漂移"的零假设宽度
```

**跨域一致性检查是这里唯一有真实防御力的东西**：单一来源永远不可信（无法验证）；**两个独立来源对同一事实的独立陈述**才能给出一阶保障。代价是覆盖率低——这是必须接受的。

**③ 长尾保留规则（过滤强度的设定依据）**：过滤器的每一次加强都会**砍掉长尾**（§0 修正 3）。所以规则是：

> **过滤强度的上限由"过滤后类频率分布是否仍近似 Zipf"反推**，而不是由"看起来干净"决定。具体：对过滤后的语料分位数拟合幂律指数 α，要求 $$\alpha$$ 的漂移不超过过滤前的 15%；否则说明过滤器在砍长尾，应该放松。

**④ 可证伪判据。**

> **FQ-11a（隔离是否真的隔离）**：在隔离区放一份**金丝雀投毒文档**（内容为一个唯一可检出的假事实）。
> **预测**：金丝雀**永远不出现在权重里**（可用 Q-01 的 causal tracing 或直接提示词探测）；只在记忆层里出现，且删除记忆后探测不到。
> 若金丝雀出现在权重中 → **隔离失败**，联网自学习必须停摆。
> **FQ-11b（漂移阈值的有效性）**：用参考噪声宽度做阈值。若在实际运行中，**任何**超过阈值的漂移都对应可检出的行为变化，且**没有**漏报，则阈值有效；若出现"超阈值但行为无变化"的常态，说明阈值定得太紧（假警报淹没真警报）。
> **FQ-11c（污染自增强）**：若开启联网后，模型输出的**多样性指标**（去重后 n-gram 熵）在 N 轮后单调下降 → 自增强污染已开始，需回滚。

**⑤ node1 最小版本**：**不需要真联网**。用一份**固定的本地快照**冒充"网络"，跑一遍三级流水线（含金丝雀）。**半天到一天。** 这是我认为本周该做的第五件事，因为它同时验证 L1、L3 与删除权三条宪法。

### Q-12 极限压缩的三层收益叠加模型 —— 见 §0 修正 1

**① 机制（修正后的两项式）。** 见 §0 修正 1：**只有两项，不是三层**。

$$\text{adjusted rate} \;=\; \frac{b_{\text{eff}}\,N \;+\; D\,H_{\text{nat/token}}}{D\cdot 32}$$

**极限锚点（这是你问的"极限"的实测形态）**：

- **最好的经典压缩器**在 enwik9 上约 **1.4–1.7 bits/byte**〔二手〕；
- **最好的神经模型**（Chinchilla-70B）在 enwik9 上 **0.664 bits/byte**〔二手，未核原文〕；
- Delétang 原文框架里**专门比较过 tokenizer 与词表大小对 raw compression rate 的影响**，并给出"越过临界点后 adjusted rate 反而上升"的结论〔原文〕。

**"极限"的正确表述**：极限不是某个数字，而是**一个随可用模型规模移动的上界**——因为 $$H_{\text{nat/token}}$$ 的估计就是"最好的模型给出的 NLL"。**你永远无法证明自己到达了极限，只能证明自己比上一版更接近。**

**② 可执行方案（含一个必须做的修正）。**

```python
# 1. 估计 H_nat/token：用两段式码率，不能用裸 NLL
def adjusted_rate(model, holdout_tokens, N_params, b_eff):
    nll_sum = sum(-log p(t_i) for t_i in holdout_tokens)   # 单位的 nat
    data_bits = nll_sum / log(2)                            # → bit
    model_bits = N_params * b_eff                           # 模型本身要记账
    return (model_bits + data_bits) / (len(holdout_tokens) * ???)
# ★ 修正：必须用 Delétang 的【离线两段式码】
#   —— 原文："the offline setting, which computes the adjusted compression rate
#      using a two-part code (i.e., it adds the model size to the -loss of the data)"
#   裸 NLL 会被两个方向污染：过拟合（低估）与有限样本（高估）
```

**给你们的判据表（"极限"在你们语料规模上的样子）**：

| 口径 | 3.5e9 token 语料的 N* | 说明 |
|---|---|---|
| fp32 | 51.9M | 参考下界 |
| fp16 | 87.1M | — |
| 1.58bit（纯三值） | 490.1M | — |
| **三值权重 + fp16 嵌入** | **201.9M** | **你们的口径；与 0.2B 里程碑重合** |

（表引自前一轮报告的表 A，常数与脚本在 `analysis/ladder_compute.py`。）

**③ 可证伪判据。**

> **FQ-12**：在**同一语料、同一留出集**上，比较 0.4B 与 0.5B 的 **adjusted compression rate**。
> **预测**：0.5B 应**更低**（更好）。因为架构重置的损失应由蒸馏补回。
> **若 0.5B 的 adjusted rate 反而更高** → **架构重置丢失的信息没有被蒸馏补回**，这是 L3 通道的**定量失败**，也是本轮最重要的可测结论之一。
> **不确定带**：两个 rate 的差落在"同一模型不同随机种子"的带宽内，判不确定。
> 阴性对照：同架构重置但**不做蒸馏**（随机初始化 0.5B）——若它与做蒸馏的差距 < 2%，说明蒸馏几乎没传东西。

**④ node1 最小版本**：**纯算术 + 一次留出集前向**（几小时）。**强烈建议做**：这是检验整条路线连续性主张的唯一严格形式。

### Q-13 多设备分布式推理的取舍

**① 机制（先说结论：在你们场景下不该做）。**

批大小 1 的解码延迟 ≈ Σ(每个设备上该阶段的时间) + Σ(通信时间)。**关键事实是：batch=1 时流水线没有可流水的东西**——只有一个 token 在飞，设备 2 在设备 1 工作时**空转**。所以逐层切分：

- **在批量大时提升吞吐**（不同 micro-batch 填满流水线）；
- **在批量 1 时纯粹增加延迟**（多段启动开销 + 通信 + 更小的 GEMM 效率更低）。

文献给出的量化旁证〔二手〕：小型 GEMM 的多段划分带来 **11–15% 的进程内开销**；某加速器在 3 段划分下**利用率从 60.1% 降到 43.6%**。**这些是"最小化损失"，不是"收益"。**

**对你们的直接判定**：0.5B 三值权重约 237 MB（Q-09 的算术），**单设备装得下**。分布式唯一合理的理由是"单设备装不下"。**你们不满足这个理由。**

**顺带说一条你可能没想到的**：有人会想"把外置记忆层做成共享缓存，多设备分担"。**这没有解决真正的瓶颈**——0.5B batch-1 的瓶颈是**权重字节流**（237 MB），不是记忆检索。

**② 可执行方案：不做分布式，做"单机多进程 + 缓存友好"的替代。**

```python
# 若目标只是提升吞吐（例如批量服务多用户），正确方向是批处理，不是切分
if batch_size >= 8:   # 批处理把权重读取摊薄到多个 token 上 → 带宽利用率上升
    use_batched_decode()
# 若目标是最小化延迟（单用户），正确方向是：
#   - 权重量化（Q-09 的 embedding 那 43%）
#   - 内核融合（减少每步启动开销）
#   - KV 缓存复用（多轮对话）
# 以上三项都不需要第二台设备
```

**③ 可证伪判据。**

> **FQ-13**：在**同一台机器**上人为插入一个 socket 边界（把 hidden state 序列化后过管道再反序列化），测"单进程"与"跨进程两段"的每 token 延迟。
> **预测**：两段版本**更慢**，且慢的幅度主要由**每 token 的通信 + 两段各自的启动开销**决定，而不是参数量。
> 若两段版本**更快**（例如因为两段各自能装进 L3 缓存），则本条被证伪，分布式在你们场景下值得重新评估。
> **不确定带**：差异落在测量噪声内，判不确定。

**④ node1 最小版本**：**不需要两台机器**——用进程间管道模拟。**半天。** 但老实说，**这题的答案已经足够清楚**，最小版本的意义只在于给你们内部一个可引用的实测数字。**优先级低于 Q-01/Q-04/Q-05/Q-08。**

### Q-14 认主嵌入的数学细节 —— 见 §0 修正 5

**① 机制。** 见 §0 修正 5：**这是个容量上极其宽松的问题**（身份数 1–2 个），而 ArcFace 的角边际是为**几万类、百万样本**设计的；在少样本设定下它**多数情况发散**且**对 m 极度敏感**〔二手〕。**先别上 ArcFace。**

```python
emb_owner     = stack(encode(model, x) for x in owner_samples)

# 有效维度用参与率（协方差的特征值有效秩），不用标称维度
pr = (sum(eig(emb)**2) / sum(eig(emb)))   # participation ratio

# 阶段 2（仅当间隔不足）：引入角边际，m 从 0 开始扫（0 = 纯余弦，退化回阶段 1）

# 存储位置：用户嵌入是【每人一份的可删除对象】→ 放记忆层，不进权重
# 这样"删除权 = 0/1"自动满足（Q-11 的级别 2）
```

### Q-15 情感 / 内在状态的工程化落点

**① 机制（先说一条泼冷水的）。**

**自我报告不可信，这条在你们这里已经确立**（§0 修正 4：连 3–9B 的口头置信度都是有效性失败）。所以 Q-15 如果被理解为"让模型说出它的情绪"，**前提本身就错了**。

可行的形态只有一种：**内在状态作为隐藏状态的侧信道（sidecar）**——即用一个小的激活级读数/写入接口，**不经过自然语言**。文献里的相关做法是 **PAD（愉悦-唤醒-支配）三轴激活引导**，在小模型上已做过〔二手〕，且发现 **span 宽度（作用区间长度）比位置更重要**〔二手〕。

**② 可执行方案（必须带退化对照）。**

```python
# 读取（不产生文本）
state_hat = W_read @ h_L[t]        # 3 维：P/A/D
# 写入（不改权重，不改提示词）
h_L' = h_L + v_PAD ⊙ mask_span     # 低秩扰动，作用在一段 span 上

# ★ 退化对照（这是整题的关键）：同容量的随机方向
v_rand = random_unit_vector(3)  # 同样是 3 维、同样范数、同样 span
# 判据：随机方向必须【不产生】同样的行为改变
```

**为什么这个对照是决定性的**：如果**随机 3 维方向的等范数扰动也产生同样的行为改变**，那说明这个改变来自"扰动本身"（任何扰动都会让输出分布偏移），**PAD 的语义并不在模型里**——Q-15 就是一条死路，应该终止投入。

**③ 可证伪判据。**

> **FQ-15a（语义 vs 扰动）**：在**多个下游任务**上，比较 P/A/D 方向与随机方向的效应量。
> 若两者**在统计上不可分** → **PAD 语义不存在于该模型**，Q-15 作废。
> 若可分但**只在单一任务上可分** → 是任务特化的伪影，需换任务复现。
> **FQ-15b（自我报告一致性）**：若模型自报的 PAD 读数 与 激活读出的 state_hat 的**相关性低于随机基线** → 自我报告通道无效（与 §0 修正 4 同向）。
> **不确定带**：效应量差异落在重跑方差内，判不确定。

**④ node1 最小版本**：在 214M 上，用对比提示集算 3 个 PAD 方向的差均值（difference-in-means），注入并测输出分布移动；对照为随机方向。**半天。** **优先级：低。** 因为它的成败高度依赖 FQ-15a，而这条的预期结果是"不可分"。

## §3 悬而未决的旧账

### 旧账 1 —— 矛盾 2：RoPE 值域外插路径 A 的 N* 代价

**我要先推翻这道题的前提〔推断〕。**

你问"路径 A（值域外插）的 **N\*** 代价是多少"。**答案是：N\* 代价约为零。** 理由是 $$N^*(D,b)$$ 是**参数量**与**语料量**的匹配点，而 RoPE 外插**不改变这两者中的任何一个**。外插改变的是**位置编码在训练分布内的覆盖**——这是一个**"位置上的分布外"问题**，不是"容量与数据不匹配"问题。

**真正的代价在别处，而且它是 D 的代价不是 N 的代价**：

> 若你想让模型在训练时没见过的位置区间上可靠工作，你必须**在那个区间上训练**。即：**长上下文的代价 ≈ 在扩展位置区间上的训练 token 数**，而不是更多参数。
>
> 定量上：若训练上下文为 $$L_0$$、目标为 $$L_1$$，则外插区间的 token 占比为 $$1 - L_0/L_1$$，你需要**至少与之同量级的总 token 被"重排"进扩展区间**才能让该区间上的位置表示可靠。

**并且有两条已知的更优替代**（这也推翻了"必须外插"的前提）：
- **位置插值（PI）** 把超长位置**压缩回**训练区间内，代价是**有效分辨率下降**（相邻位置更难区分），但**不产生分布外位置**；
- **NTK-aware / YaRN 式缩放** 通过改变 RoPE 频率基来缓解，文献报告**需要约 10× 更少的 token 与 2.5× 更少的训练步**〔原文，YaRN 摘要，前一轮已核〕。

**结论**：**路径 A 不是"代价高的正确路"，PI/频率缩放不是"便宜的近似路"**。在你的约束下（端侧、上下文不长、CPU 预算紧），**先做 PI 或频率缩放**；只有实测发现有效分辨率不足时，才考虑外插，而那时你要付的是 **D 的代价**（更多扩展区间 token），不是 N* 的代价。

**不确定的部分**：上述是关于"N\* 不随上下文目标移动"的推断，**没有直接文献验证**。且"扩展区间 token 数"的具体系数（1× 还是数×）没有原文支持。

### 旧账 2 —— 语料信息天花板数值：H_raw 的估计方法

**① 关键概念澄清**：$$H_{\text{raw}}$$（语料的真实可压缩信息量）**在有限语料上不可精确测量**——任何估计都有偏。

**② 两个方向的偏**：
- **经典压缩器**给出的是**上界**（因为它不比最优模型好）；
- **神经模型的 NLL**也是**上界**（最优模型的 NLL 收敛到真实熵，从上方）。
- **麻烦在于**：在**有限**语料上，神经模型会**过拟合**，导致 NLL **低于**真实熵——这就是 Delétang 原文要引入**两段式码**的原因〔原文：`it adds the model size to the -loss of the data`〕。

**③ 所以正确估计方法是三分法**：

```python
# 估计 H_raw 的可用区间（不是点估计）
H_upper = adjusted_rate(best_classical_compressor, corpus)   # 宽松上界，可复现
H_tight = adjusted_rate(best_neural_model, corpus)           # 紧上界（含模型大小记账）
# H_lower：不存在可计算的方法（需要证明，只能给出条件性的下界）
# 报告的形态必须是【区间 + 方法】，不能是单一数字
```

**④ 一条对你们特别重要的推论**：$$H_{\text{tight}}$$ 的**紧致程度随可用模型规模提升**，而你们的语料小（3.5e9 token）——**这意味着你们的 H 估计天然比较松**。所以：**不要用一次测量宣布"我们到顶了"**；用**同一个估计器、同一个留出集**做**纵向比较**（0.1B→0.2B→0.3B→0.4B 的 adjusted rate 序列），**趋势**才有意义。

**⑤ 可证伪判据**：若两个**规模相差 ≥ 4×** 的模型在同一留出集上的 adjusted rate 差 **< 0.5%**，则可以认为在该语料上已达实际天花板（继续扩容无收益）。**不确定带**：差异落在种子噪声内判不确定。

**⑥ node1 最小版本**：用你们已有的 0.1B 与 0.3B，**同一留出集**，各算一次两段式 adjusted rate。**几小时。** 这条与 Q-12 的 FQ-12 是同一个实验，**合并做**。

### 旧账 3 —— 斜率 x：CPU 单步耗时随参数的实测斜率

**① 预期形态〔推断〕**：batch 1 的**解码**近似**线性**于 N（带宽受限，读的字节线性于参数）；**训练步**也近似线性（反向 ≈ 2× 前向，加优化器状态更新），但在**中等规模**上常因**缓存层级**出现轻微**超线性**。所以预期：

$$t_{\text{step}} \;\approx\; a\,N^{x}, \quad x \in [1.0,\; 1.2]$$

**② 测量协议（这就是你问的最小版本）**：

```python
# 固定 batch size 与 seq len（否则测的是别的东西）
for N in [135e6, 214e6, 300e6]:
    t = median([step_time(model_N, bs=B, seq=L) for _ in range(50)])  # 50 步
    record(N, t)
x = polyfit(log(N), log(t), 1)[0]      # log-log 斜率
# ★ 必须报告：机器是否独占、是否开启 MKL 多线程、线程数是多少
#   —— 64 核机器上线程数不同，x 会有系统性变化
```

**③ 可证伪判据**：若实测 **x > 1.5**，则存在严重的**非线性瓶颈**（可能是内存分配或同步），此时"用斜率外推 0.5B 耗时"**不安全**，必须直接测。若 **x < 0.9**，则测量有误（例如计时把异步操作算漏了）。

**④ 依赖的缺失配置**：**必须报告线程数**。同一个模型在 8 线程与 64 线程下的 x 不同。**缺线程数，x 不可解释。**

### 旧账 4 —— P3 裁决：E1 出来前要不要预先实现「分歧 token 门控」

**裁决：先跑 E1，不预先实现门控逻辑——但先实现接口。**

**理由（这是一个成本-风险比算术）**：

| 选项 | 成本 | 风险 |
|---|---|---|
| 预先实现门控（含阈值） | 小（20 行） | **阈值是拍的**。E1 尚未给出分歧 token 分布，任何阈值都是猜的；猜错的门控**可能砍掉有用信号**（把教师的正确轨迹也滤掉） |
| 预先实现接口、不设阈值 | 更小 | 无 |
| 先跑 E1 再决定 | E1 ≈ 半天 | 无 |

**关键洞察**：**门控是数据过滤器，不是训练时的结构改动**——它作用在**蒸馏语料**上，可以**在 E1 之后、阶段 1 启动之前**随时插入，**不需要重训任何东西**。所以"预先实现"的唯一实际价值是省下 20 行代码的书写时间；而它的实际代价是**在没有阈值依据的情况下拍一个阈值**。

> **裁决：实现门控的接口（`gate(t) -> weight`，默认恒为 1.0），不实现阈值；跑完 E1 后按分歧 token 分布的分位数填阈值。** 这样既没有浪费，也保留了防御能力。**若 E1 显示传递量 ≤ 2σ（即传递不显著），则门控全部删除**，不给管线增加复杂度。

### 旧账 5 —— 外部中文 holdout 的构造

**① 抽源原则：语料家族不同（这是防泄漏的第一原则）。**

```python
# 训练池家族（推测）：网页爬取 + 新闻（这是最常见的组合）

```

**② 大小：由你想要的检测灵敏度反推，不由"看起来够大"决定。**

> $$n \;\ge\; \left(\frac{2.8\,\sigma}{\delta}\right)^2$$
> 其中 $$\sigma$$ 是该任务上**跨随机种子的指标标准差**，$$\delta$$ 是**你想检测到的最小退化幅度**。
> 例：若 $$\sigma = 0.02$$、想检测 $$\delta = 0.003$$ 的退化 → $$n \approx 350$$ 个独立样本组。**先把 σ 测出来，再定 n——反过来做会得到一个没有分辨力的 holdout。**

**③ 零重叠的四重机制（B2 指纹机制的具体化）：**

```python
1. 内容哈希：文档级 + 段落级（shingle）双向比对，交集必须为空
2. n-gram 重叠：训练池与 holdout 的 13-gram 集合交集必须为空（标准做法）
3. 使用计数器：holdout 目录【只读】挂载，训练采样器无权访问；
   ★ 并记录每次被评估的次数——评估次数过多会让它被间接记忆
4. 轮换指纹：维护 3 份互不相交的 holdout 分片（H1/H2/H3），
   每次评估轮换主分片；三片的一致性 = 评估器自身漂移的对照
```

**④ 长期不退化的机制**：

```python
# 每次评估同时记录：holdout 文件哈希 + 模型哈希 + 评估代码哈希
# ★ 任何一项变化 → 历史结果作废（不可与前次比较）
# 这样"指标下降"永远可以归因到具体哪一个哈希变了
```

**⑤ 可证伪判据**：若把 holdout 用同一模型评估两次，得到的指标差**超过 σ**，则评估器本身不稳定（探针集太小或评估代码不确定），**在修好之前所有 holdout 结论都不可用**。**这是必须先跑的自检。**

### 类别 A —— 扩容是一次性事件，但你们的叙述把它当成了持久性质

**A-1 优化器状态的跨扩容可迁移性〔推断〕。** Net2Net 保的是**函数**，不是**优化器状态**。扩容后，新坐标的 Adam 二阶动量是**零**（或者从旧坐标复制，这本身就是一个选择），于是**新旧坐标的有效学习率不同**，扩容后有一段**瞬态**。

> **预测**：扩容后的若干步内 loss 会有一个**凸起**，幅度 ∝ 新坐标占比。
> **可证伪**：比较"扩容后重置优化器" vs "迁移优化器状态（新坐标用旧坐标的二阶动量）"在后续 200 步的差异。若两者不可分 → 不是真问题。
> **node1**：135M→214M 扩容各做一次，**半天**。

**A-2 限制映射的插入后漂移（我认为这是本轮最重要的盲区）。** **"保函数"是一个瞬间性质，不是安全性质。** 扩容那一刻成立；**任何一个训练步之后就不再成立**——因为旧坐标自身也在被训练。所以：

> **你们需要的不是"保函数"这个事实，而是一个【漂移监测器】**：在固定探针集上，随时监测"旧能力"的输出漂移，并定义一个**可接受的漂移带**（由旧账 5 的参考噪声宽度设定）。
> **若漂移超出带** → "连续性"主张失效，实际上你已经在重训，应该按"新模型"对待（含 P3 的重估）。
> **可证伪**：若扩容后 200 步内的旧任务漂移**始终在噪声带内**，则这条担心不成立。

### 类别 B —— 可复现性 / 可审计性不是"工程细节"，是宪法级依赖

**B-3 训练非确定性 vs 位精确删除检验的结构冲突。** 64 核 CPU 训练的归约顺序不确定 → **训练不可复现**。而你们的删除权是 **0/1 硬需求**——如果删除验证的形式是"重训一遍比较输出"，**你永远无法通过**（因为两次训练本就不同）。

> **解法**：**把删除检验定义在【推理路径】上，而不是训练路径上。** 记忆层是**独立的可寻址对象**，删除它并重跑推理——只要**推理是确定性的**（单线程、固定归约顺序），这一步就是位精确的。
> **推论**：**必须把推理路径钉成确定性的**（这本身就是一条宪法级的实现要求，清单里没有）。
> **可证伪**：同一权重、同一输入、同一推理配置，跑 100 次输出哈希应完全一致。若不一致 → 推理路径不确定，删除检验不可实现。

**B-4 评估器自身的冻结。** 见旧账 5 ④：holdout、模型、评估代码三者都要哈希。**清单里没有"评估器的版本化"这一项**，而没有它，所有纵向比较都可能是**评估器漂移**造成的假象。

### 类别 C —— 同一物理机上的多进程共存

**C-5 训练 / 服务 / 看门狗的资源仲裁。** 你们的看门狗**内嵌、开机自启**，而训练跑在**同一台机器**上。训练吃满 64 核 → **服务进程错过 15 ms/token 的 SLA**；训练的内存压力 → **swap → 延迟尖刺**。

> 清单里完全没有这一类问题。**它是一个运维盲区，但它直接决定"端侧常驻服务"这个目标能否成立。**
> **解法**：cgroup 级别的 CPU 配额分离 + 优先级规则（服务 > 看门狗 > 训练）+ 训练在服务空闲窗口调度。
> **可证伪**：在训练满载时测服务延迟。若延迟超出 SLA 的 2 倍 → 仲裁设计不成立。

### 类别 D —— artifact 的版本化与向前兼容

**D-6 tokenizer 是模型 artifact 的一部分，它的任何变化都会作废下游一切。** 你们 0.4B 加词表只加不改（旧 id 不动），这是好的。但清单里没写的是：

> - **byte fallback**：若无字节回退，推理时遇到**未见字符**会 OOV。**必须先检查**（这是一个 5 分钟就能查、但不查会埋雷的项）。
> - **记忆层的键空间**：若记忆层用 **token id** 作键，则未来任何词表变化（哪怕只加）都会让旧键的**语义**不变（因为旧 id 不动）——**这一条你们是安全的**，但前提是**永远只加不换**，这应当是宪法级的显式条款。

### 类别 E —— 删除权的"对手模型"（本轮最容易被忽略的一类）

**E-7 删除的验证方与被删除物的派生性。** 你们把"删除权 = 0/1"定为硬需求，但清单里只问了"能不能删"，没问**"谁在验证删除、以及被删东西的派生物怎么办"**。

> **(a) 验证方问题**：删除的可验证性需要一个**用户信任的验证方**。若验证过程本身要把被删内容送到某处 → **验证过程成了一个信息通道**（与 L3 同构）。
> **(b) 派生性问题**：如果一条个人数据被用于**训练了一个 adapter**，那么**删除原始数据并不删除 adapter 里学到的东西**。**删除权必须定义在"从数据到 artifact 的传递图"上，而不是源文件上。**
> **推论（宪法级）**：**个人数据只能进【可寻址、可删除的记忆层】，永远不能进入任何【被训练的参数】，包括 adapter**——因为参数一旦学进去，删除就不再是 0/1。**这条把"0/1 删除"从一句口号变成了一条硬性的架构约束。**
> **可证伪**：构造一条 canary 个人数据，走完整管线，删除后做**提示词探测 + 激活探测**。若任一能钓出 → 该管线违反了 0/1，必须回滚设计。

### 三条我认为最有科学创新价值、且最易被忽略的（§12 式收尾）

1. **A-2 的漂移监测器**——把"保函数"从**一次性事实**重新表述为**可监测的带宽**。这个重新表述本身是可发表的：**扩容的连续性从来没有被给出过可操作的定义**，因为它被当成瞬时的；把它变成"探针集上漂移谱随训练步的演化"是一个新对象。
2. **B-3 的推理确定性 vs 训练非确定性分离**——**删除权与可复现性之间的结构性张力**。很少被讨论，但在"可删除"是硬需求的系统里是决定性的。
3. **E-7 的"派生性 vs 0/1 删除"**——**删除权必须定义在传递图上**。这是一个把隐私工程与 L3 通道分离规则接起来的论点。

**最快的组合实验（本周）**：在 135M→214M 上同时做 **A-1（优化器状态）** 与 **A-2（漂移谱）**——**同一个扩容实验就能同时回答两个问题，半天。**
