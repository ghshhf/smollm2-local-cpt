## 1. 认主对比头（0.4B）

### 核心开放问题
先问一个比 triplet 更前置的问题：**这个头要判定的是"身份"还是"授权"？** 两者要求完全不同。身份判定是生物特征识别（用文风/内容识人），是弱信号且可被模仿；授权是密码学问题，不该由学习模型承担。

### 候选方案与权衡
- **A. 学习式身份头（你们的方向）**。必须假设"主人的文风与内容分布与其他来源可分"。风险：可被风格迁移/转述攻击；对比梯度会把作者身份编码进主干（可用线性探针测出）；主干变成生物特征编码器，难以撤销。【推断】
- **B. 授权外置 + 轻量风格路由**。密钥/会话做拒绝服务，学习到的头只做个性化路由与体验。风险最低，代价是"认主"不再是模型的属性，而路由仍需软信号。【推断】
- **C. 完全不学，靠数据分区**。owner_corpus 与自有语料在训练时分源标记，退化为检索层的事。最保守。【推断】

**建议**：A 与 B 组合——头可以学，但**不得成为拒绝服务的唯一依据**（BS-11）。

### triplet 设计（若走 A）
- **anchor / positive**：同源不同段。这里有个陷阱：同源不同段的相似度会被**主题**而非**作者**主导。positive 必须做主题匹配（同主题、不同作者 vs 同作者、不同主题），否则学出来的是主题分类器。
- **negatives 三类缺一不可**：(i) 其他作者；(ii) **同作者风格的机器转写/改写**（对抗负样本，抓"能模仿但不是本人"）；(iii) 同作者不同体裁（防止把"体裁"当身份）。仅从语料里随机抽负样本是最常见的错法，会得到一个高准确率但无意义的头。
- **与主任务联合训练的梯度冲突**：对比损失的早期梯度量级通常压过 LM 损失。【推断】三个可选解法按侵入性排序：线性探测式排程（先冻结主干只训头）→ 损失按不确定度加权 → 梯度手术（PCGrad 一类投影）。**没有理论告诉你哪个更好，这是【待实验】。**

### 一锤定音的消融
1. **NC-AUTHOR-SHUFFLE**：打乱作者标签重训。头若仍"有效"，说明学的是捷径（主题/来源/长度），主分析作废。
2. **风格迁移对抗**：用改写模型生成"像主人但不是主人"的文本，测头给出的是身份还是风格。
3. **主干泄露探针**：冻结主干，用线性探针从主干激活里恢复作者标签。若探针准确率显著高于基线，主干已编码身份——这是隐私与不可撤销性问题，比头的准确率更重要。
4. **梯度冲突对照**：上述三种解法各跑一遍，看主任务损失曲线的退化幅度。

### 分层结论
- **【理论】**对比学习的负样本分布决定学到的等价关系；线性探针可测表征中的信息——这两条足以支撑消融设计。
- **【推断】**身份信息会渗进主干、头不宜做安全边界。
- **【待实验】**三种梯度冲突解法的相对优劣；主题匹配对头有效性的影响量级。
- **【缺配置】**owner_corpus 的规模与来源数（负样本池大小直接由它决定）——缺它无法判断 A 是否可行。

## 2. 记忆层选型（0.5B）

### 核心开放问题
你们给的约束是"不增 FLOPs"。**这个约束很可能是错的绑定点**（BS-10）：CPU-first 场景下真正的瓶颈通常是内存带宽与缓存，而检索式记忆每次前向都要搬运 KV 与索引。而且"Memory Layers 不增 FLOPs"这一说法**在本次检索边界内没有找到任何支撑材料**（检索结果明确说明既无两者对比材料，也无该 FLOPs 声明）——**该前提未经验证**。

### 候选方案与权衡（按我建议的优先级）

| 方案 | 机制 | 对你们的关键分歧点 |
|---|---|---|
| 外置可寻址 KV 记忆 + adapter | 记忆在权重之外，检索后进上下文 | **可删、可审、可版本化**；但每次前向有搬运开销 |
| 神经记忆（测试时在线更新参数） | 记忆模块以 surprise 信号在推理时更新自身参数，含遗忘/门控项 | 长上下文能力强；但个人数据直接进参数 → **删除权、审计、回滚都更难** |

关于第二类，检索到的二手材料这样描述：记忆模块在推理时在线更新自身参数，更新以"surprise"（关联记忆损失对参数的梯度）驱动，并带显式的遗忘/门控 `(1-α)M + S`；更深的记忆 MLP（4 层 vs 1 层）约有 15–20% 吞吐代价，换来 0.5–1.0 困惑度改善（[Titans 架构条目](https://aiwiki.ai/wiki/titans_architecture#1)、[第三方分析](https://raw.githubusercontent.com/lhl/agentic-memory/32e2bec4f65aa1286c81b6866fe815d7a61b71c2/ANALYSIS-arxiv-2501.00663-titans.md#1)）。**这是二手转述，我没有读原论文（arXiv:2501.00663），选型前请自行核对。**

### 我建议替换掉的选型标准
把"不增 FLOPs"换成三项并列的验收指标，因为三者都直接对应端侧体验：

1. **端到端首 token 延迟**（含检索与搬运）
2. **常驻内存峰值**（权重 + KV + 索引 + 缓存）
3. **可删除性 / 可审计性 / 可回滚性**（一个 0／1 判据，不合格直接淘汰）

第 3 项不是软要求：它是 BS-8 的落点，也是唯一能同时约束记忆选型和数据治理的判据。

### 一锤定音的消融
1. **空记忆对照（NC-EMPTYMEM）**：关检索跑同一套评测。若仍出增益，增益来自训练流程而非记忆。（已继承）
2. **搬运成本对照**：同硬件下分别测两种记忆的延迟与内存峰值，看瓶颈落在 FLOPs 还是带宽。这直接判定你们的约束写得对不对。
3. **删除演练**：写入一条后删除，检查 (a) 记忆里没有了；(b) 若该条已被闭环固化，权重里还有没有；(c) 能否在有限重训预算内撤销。**这个演练必须在选型阶段做，不能等上线。**

### 分层结论
- **【理论】**参数记忆与非参数记忆不是本质分野，差别在访问方式与更新成本。
- **【推断】**测试时更新参数的记忆与"个人数据可删除"要求相冲。
- **【待实验】**两种记忆在你们硬件上的延迟/内存实测；深度记忆的收益是否抵得上搬运开销。
- **【缺配置】**记忆层数据政策（§4 缺失）——缺它连"是否允许把个人数据写进参数"都无法判定，选型无意义。

## 3. 蒸馏桥接（0.5B）

### 核心开放问题
不是"用什么损失"，而是：**三值学生的可达损失下限在哪里？** 如果教师（0.4B fp32）的损失低于学生所能达到的格点天花板，任何桥接技巧都救不了。**先测天花板，再谈桥接。**

### 候选方案与权衡
- **格点天花板测量（必做且排第一）**：在**同一份数据上、不做蒸馏**、把 0.5B 三值模型训到收敛，得到的损失就是该架构在该语料上的下限估计。若它已经高于教师，桥接是徒劳的——此时正确的动作是改架构或改量化方案，不是换蒸馏损失。
- **损失形式**：前向 KL 与反向 KL 的行为不同（一个覆盖模式、一个寻找模式），在词表 5 万+、有长尾的 LM 上差异显著。**JSD 或 top-k 截断 + 温度**通常是稳健起点。【推断】具体选哪种是【待实验】。
- **中间层特征蒸馏**：架构从零重置后，**层与层之间没有自然对应关系**。需要显式的对应策略（按深度比例匹配块、或只做 logit 级）。这是本方向最容易低估的难点。【推断】
- **STE 下的梯度桥接**：前向走量化、梯度走潜变量，这一点你们已经在做，蒸馏损失只是多一个损失项。**但要注意**：教师的 logits 是 fp32 稠密的，学生的 logits 由三值权重算出，两者分布形状不同，温度与截断的作用比常规蒸馏更关键。【推断】
- **对照臂（你们没列出的）**：先在 fp32 下把 0.4B **保函数扩展**到 0.5B，再做量化（PTQ/短 QAT），与"从零 + 蒸馏"对照。这条路你们因为 BitNet 必须从零而没有选，但它是一个**必要的对照**：它告诉你"从零 + 蒸馏"这条路的代价有多大，以及断裂点到底损失了多少。**这不是质疑锁定决策，是把锁定决策的代价量化出来。**

### 一锤定音的消融
1. 格点天花板 vs 教师损失（若天花板 ≥ 教师，桥接方向不成立）。
2. 蒸馏损失形式的 A/B（前向 KL / 反向 KL / JSD / top-k），控制在同等步数。
3. 无蒸馏同预算对照臂（学生的"自学"上限）。
4. fp32 扩展 + 量化 对照臂。
5. **NC-RANDLABEL**（已继承）：在打乱标签探针上若也出增益，说明测的是压缩/正则通路。
6. **换教师对照（NC-OTHERTEACHER）**（已继承）：用一个无关教师蒸馏，看验收指标是否同样"好"。

### 分层结论
- **【理论】**蒸馏是带正则的重新训练而非函数复制；因此学生可以在域内超过教师，也可能在域外更差。
- **【推断】**细粒度词表下 KL 形式的选择影响显著；层对应是重置架构的主要难点。
- **【待实验】**天花板位置；损失形式；对照臂的相对代价。
- **【缺配置】**蒸馏损失的构成与蒸馏数据来源（§4 缺失）。**特别注意**：若教师是在 owner_corpus 上训的，蒸馏会把个人数据烘进 0.5B 权重——这条与 BS-8 的删除权直接相连，必须先过治理再开跑。

## 4. 压缩 operationalized

### 核心开放问题
把"固定语料存在最优容量点"从一句原则变成一条可执行程序。它缺三个东西：**下限锚、完整比特账、判据的统计形式**。

### 程序（我建议的四步）
1. **估下限**：用两个独立锚点估语料熵下限——(a) 一个远大于目标规模的参考模型的留出损失；(b) 强经典压缩器在同一语料上的码长。取更低者为乐观下界。
2. **算完整比特账**：`总比特 = 语料码长(留出) + 模型体积 + 索引体积`，其中模型体积必须包含**逐行 α、分块 γ、embedding、lm_head、记忆层参数**。缺一项就会把最优点算偏（BS-5）。**【缺配置】**：尺度粒度与 embedding/lm_head 是否量化未提供 → 现在无法计算。
3. **拟合曲线**：在阶梯上实测各档位的 adjusted rate，拟合出对模型规模的非单调曲线，取极小点。
4. **判越过**：边际验证收益（对新增参数）的置信区间覆盖 0，且训练损失仍在下降——这才是"已过最优点"的可证伪形式。**注意**这个判据只在固定分词口径下有效（BS-13）。

### 你们需要额外接受的一个事实【推断】
压缩最优 ≠ 服务最优。一个 adjusted rate 最优的模型不一定是延迟/内存最优的。**你们需要第二个目标函数（端侧延迟与常驻内存），真正要找的是合并目标的极小点**，而这两个极小点不一定重合。

### 一锤定音的消融
- **NC-RANDLABEL**（已继承）。
- **数据受限对照**：用一半语料训同一架构，若损失几乎不变，说明当前是**数据受限**而非容量受限——扩容无意义（BS-2）。
- **重复 epoch 对照**：语料重复 1/2/4/8 epoch，看收益衰减。**这直接决定阶梯能否继续往上走**。**【缺配置】**语料规模缺失 → 无法预判。

## 5. RSI 自进化防漂移

### 核心开放问题
"在变好而非在漂"需要**外部信号**。§3 已继承：闭环必须累积真数据、绝不替换；自产数据闭环下任务信息不增（数据处理不等式），替换式训练会崩溃。于是真正的问题是：**这个系统的外部信号从哪来？** 三个候选：

1. **用户交互与纠正**——最自然，但它是个人数据 → 治理闸门 + BS-8 删除权。
2. **可验证任务**——代码执行、算术、对照权威信源的事实校验。这是**唯一不需要个人数据**的外部信号，应作为闭环的主要驱动。
3. **累积的真实语料**——已继承的要求。

**若三者都不接**，闭环只能是压缩与重排，此时把它叫"自进化"是过度声明。【理论】

### 放行协议的候选形状【推断】
一次闭环更新只有在同时满足以下四条时才被接受：
- 在**冻结评测集**上净增益超过噪声宽度（BS-1）；
- 不使任何**受保护能力**低于预设下限（能力地板）；
- 度量到的**聚合功能漂移**（M-DRIFT，已继承）在预算内；
- 更新来源可追溯到具体数据条目（为 BS-8 的删除留下通路）。

并配**自动回滚**：任何一条不满足即回滚到上一个已验证快照。

### 一锤定音的消融
- **投毒演练**（BS-9）：注入一条错误但格式规范的个人记忆，看它是否经闭环固化进权重、能否撤销。
- **NC-EMPTYMEM**（已继承）。
- **累积 vs 替换对照**：只做一次即可确认 §3 的结论在你们管线里成立（不要跳过，管线实现常与论文设定不符）。
- **回滚演练**：人为让一次更新越界，检验自动回滚是否真的生效。

## 6. 个人记忆三层联合训练协议（triplet / 检索 / adapter）

### 核心开放问题
三层里哪一层**允许**承载个人数据？这决定了训练协议的形状，也决定了删除权能否满足。

### 候选协议（我建议的三阶段 + 一条硬约束）
- **阶段一**：冻结主干，只训 adapter（检索条件下的适配）。此时主干函数不变——如果你接受 BS-7 的读法 (a)，这一步反而是"准保函数"的；若按读法 (b)，它是模块插入，需要单独审查。
- **阶段二**：离线、确定性重建检索索引，按固定周期而非每样本，避免反馈回路；记录索引漂移量。
- **阶段三**：adapter 更新时对主干加**函数空间的信赖域**——以上一次已验证快照为参照，约束 adapter 造成的功能漂移（这正是 M-DRIFT 的用武之地）。
- **硬约束**：**闭环内不训练主干**。主干只在扩容节点上更新。这一条同时解决 BS-12（RSI 与 plateau 互斥）和 BS-8（个人数据不落进主干权重）。

### 三层 loss 怎么配
**【推断】**建议从最保守的组合开始并逐项消融：检索层不参与梯度（纯离线）；adapter 用 LM 损失 + 对主干的 KL 锚（防止漂移）；triplet 若不与认主头合并，则应完全独立、单独评测。**具体权重配比没有理论可依，只能实验。**

### 检索库更新时机与漂移
- 更新时机：按周期批处理，不在每次交互后即时写入——即时写入会把短期噪声固化成长期记忆。
- 漂移度量：两次重建之间，同一查询的 top-k 命中集合变化率 + 命中内容的相关性变化。

### 一锤定音的消融
- **信任域宽度扫描**：KL 锚权重从松到紧，看 adapter 的表达力与漂移量的权衡曲线。
- **索引重建周期扫描**：周期 vs 漂移 vs 体验。
- **同族未见项增益（已继承的判别器）**：只在被记住条目上提升 = 数据库更新；同族未见项也提升 = 策略层泛化。这个判别同时适用于 RSI 的"是否真的在进化"。

## 7. 我建议的行动顺序

如果只能做三件事，按此顺序：

1. **Gate 0：评测底座 + 血统管理**（BS-1、BS-15）。不依赖任何缺失配置，今天可做，且是其余一切的前提。
2. **plateau 三分类判据 + 语料熵下限估计**（BS-2、BS-3）。这两条决定"下一次扩容该不该发生"。
