## §2 算力基底定量拐点

### 2.1 两个已实测基准与它们的可用范围

| 基准 | 数值 | 可用性 |
|---|---|---|
| 本机 | 1 小时 ≈ 1.1e15 FLOPs（≈0.31 TFLOP/s） | **只够跑方法学对照**，任何 0.2B 以上的真实训练都不可行 |
| 魔塔 64 核 | 214M 全模型 18.7–29.1 s/step | 本节的定标点 |

**单步耗时模型**（本节全部计算的骨架）：

```
t_step(N) = t_ref · (N / N_ref)^x
t_ref = 18.7~29.1 s (取中值 23.9),  N_ref = 2.14e8
x = 1.0  计算受限口径
x = 0.7  带宽受限口径（CPU 上更可能，但【需消融实验】）
```

x 是本节最大的不确定源，且**它不经实验无法定**：判据是在同一台 64 核机器上跑 2–3 个不同 N 的模型各 50 步，做 log t_step ~ log N 的斜率拟合。**这一步花不到半天，建议在任何扩容启动前做完。**

> **falsifier**：若实测斜率 x < 0.6 或 > 1.15，本节的墙钟数字需整体重算。

**结论（不依赖 B 的部分）**：

- **CPU→GPU 的拐点应设在 0.5B 节点，而不是 1B。** 在 B 的 16 倍范围内（8k–131k tokens/step）变动，拐点只在 **0.3B–0.5B** 之间移动：B=8k 时 0.3B 已需 165 天，B=131k 时 0.5B 需 17 天、1B 需 35 天。**没有任何一个合理 B 能让 1B 的单遍墙钟落在一个可接受区间内同时让 0.5B 也在其内——0.5B 是这道墙的位置。**
  > **falsifier**：若实测 B ≥ 262144 tokens/step（即单步 26 万 token），0.5B 单遍降到 9 天以内，拐点应后移到 1B。请在扩容前把 B 报出来——它只需要读一次训练日志。
- **还有一道与 FLOPs 无关的墙**：训练显存/内存 ≈ **16 字节/参数**（fp32 权重 4 + 梯度 4 + Adam 一阶 4 + 二阶 4）。三值 QAT 并不降低这一项，因为潜变量、梯度和优化器状态仍是全精度。于是 1B→16 GB、3B→48 GB、**8B→128 GB**，再加激活（可被梯度检查点压到很小）。**8B 在 64 核 CPU 上不是慢，是内存装不下。** 3B 也只在 128 GB 以上的节点上可行。
  > **falsifier**：若你们实际采用 8-bit 优化器或梯度分片（如 ZeRO/offload），每参数字节数降到 6–10 B，3B/8B 的内存墙相应松动；此时以实测内存占用为准。

### 2.4 拐点如何随 1.58bit 记账移动

这是本节最容易被误答的一问。**1.58bit 记账对拐点有两个方向相反的作用，必须分开**：

1. **记账效应（把拐点推向更小规模）**：1.58bit 把「模型体积」这一项从 16/32 bit 降到 1.58 bit，于是同一语料下的最优容量点 N\* 变大（§4.1 给出 ×4.7）。**要训的参数更多 → 每级更贵 → 拐点提前。**
2. **算子效应（把拐点推向更大规模）**：若 CPU 处在**带宽受限**区，1.58bit 把权重搬运量降到 1/8～1/16，单步会变快，拐点后移。**但若处在计算受限区，位宽不改变 FLOPs，无加速**——BitNet 论文自身的 2.4×–4.1× 加速是在 **GPU** 上测的（原文 §3），CPU 上的收益需要你们自己测。

**净效应的判定式**：设带宽加速因子为 s（若 x=0.7 则 s 已包含在 x 中）。拐点规模 N_GPU ≈ N_GPU(fp16) × s^(1/x)。**这项不能推，只能测**——在 64 核上分别跑同一个模型的 fp16 与三值两个版本各 50 步，直接量 s。

> **falsifier**：若三值版与 fp16 版的 s 落在 0.9–1.1，说明 CPU 侧无带宽红利，第 2 项不成立，拐点只受第 1 项支配（提前）。

## §3 已立前提（照录 P1–P6）

P1 三值 Net2Net：宽度扩容跳变 +1.70%（加宽比例与规模未记录）；根因 γ=mean|W| 被零填充稀释；解法 A 在 fp32 潜权重上做结构操作、B 分块 γ（跳变 0.0000）；规避方案升级为「冻结旧坐标三值符号 + 该行 α」。
P2 词表 append 的类型论冲突：不变量须写成「旧 pre-softmax logits 逐位不变 + 输出分布变化有界」；softmax 分母 +≈0.04 nat；tokenizer.json 直接 append 使 loss 定义域不变。
P3 身份连续性：0.4B→0.5B 是架构重置 + 蒸馏；科学命题应写成「能力 C、用 M 测、在分布 D 上、容差 τ 内」。
P4 Delétang 三值重算：adjusted rate 计入模型存储后，三值口径把最优点推向更大参数；用 fp32 口径说「已过最优」是算错口径。
P5 RSI 红线：自体闭环信息不增；替换真数据→坍塌；累积不替换→安全；10M 记忆是容量天花板之一。
P6 十道 Gate；Gate 0 评测底座为其余前提；Gate 1 三分类只有「容量受限」放行扩容；RSI 激活后扩容与闭环不得并行。

## §4 执行手册

### 4.1 逐 0.1B 步进时间表（到 8B）

#### 4.1.1 N\* 的显式定义（非拍常数）

把 Delétang 的两支码长写成可最小化的目标：模型体积 `b·N` 比特 + 数据编码 `(D/ln2)·L(N,D)` 比特，其中 L 取 Hoffmann 2022 的拟合式。对 N 求导置零：

```
N*(D, b) = [ D · A · α / (b · ln2) ] ^ (1/(1+α))       A=406.4, α=0.34
        = [ D · b^-1 · 99.67 ] ^ 0.746

数据需求反解:  D_needed(N, b) = N^1.34 · b · ln2 / (A·α)
```

**N\* 是 D 与 b 的显式函数，不是一个常数。** 两条直接推论：

- **N\* ∝ D^0.746**：要让最优容量点扩大 10 倍，需要 **22 倍**的数据。
- **N\* ∝ b^(-0.746)**：把记载口径从 16 bit 改到 2 bit，最优容量点扩大 **4.7 倍**。

#### 4.1.2 现有 3.5e9 token 下的 N\*（本手册最关键的一张表）

| 记账口径 | bits/param | **N\*** | 说明 |
|---|---|---|---|
| fp32 全精度 | 32 | **52 M** | 参照 |
| fp16 全精度 | 16 | **87 M** | 参照 |
| 三值名义 1.58 bit | 1.58 | **490 M** | 若 embedding 也三值、无尺度开销 |
| 三值取整 2 bit | 2.0 | **411 M** | 本手册基准 |
| **三值权重 + fp16 embedding**（BitNet 原配方） | **5.50**（d=1024,L=12 时） | **193 M** | ← 最接近现实的一个 |

**读出三件事**：

1. **P4 的「三值把最优点推向更大参数」是对的，且量级可算**：相对 fp16，2 bit 口径把 N\* 从 87M 推到 411M，**×4.7**。
2. **但它没推到 8B**。在你们自己的语料规模下，**三值口径的压缩最优容量点 ≈ 0.2B–0.4B**，而不是 1B 以上。**「三值把最优点推大」不等于「三值让 8B 变成最优」。**
3. **embedding 是否量化，会把 N\* 砍掉一半（411M → 193M）**。BitNet b1.58 原文 §3 明确写 «the embedding remains full precision»。**这是一个已经写在原文里的配置事实，不是猜测**：若你们照搬配方，实际 bits/param 远高于 1.58，N\* 相应左移；若你们把 embedding 也三值，则要面对 0.4B 时中文新 token 的「均值初始化 → 低范数 → logits 天然小」与 lm_head 目标冲突（§7 矛盾 3）。

   > **falsifier**：把两个候选配置（embedding 三值 / 不三值）各自算一遍完整比特账；若两者算出的 N\* 差异小于 30%，本条第 3 点作废。

#### 4.1.3 各档位「成为最优点」所需的数据量（b=2）

| N | 0.1B | 0.2B | 0.3B | **0.4B** | 0.5B | 0.75B | **1B** | 1.5B | 2B | **3B** | 5B | **8B** |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| D_needed | 0.5B | 1.3 | 2.3 | **3.4** | 4.6 | 7.8 | **11.5** | 19.8 | 29.2 | **50.2** | 99.6 | **187** |
| 相对现有 3.5B | 0.2× | 0.4× | 0.7× | **1.0×** | 1.3× | 2.2× | **3.3×** | 5.7× | 8.3× | **14.3×** | 28× | **53×** |

**这是整条路线最硬的一道约束**：按你们自己的「压缩即模型」判据，现有 3.5B 语料只够支撑到 **0.4B 左右**。1B 需要 3.3 倍现有语料，3B 需要 14 倍，8B 需要 53 倍。

> **falsifier**：若在 1B 上实测的留出损失仍显著低于 0.5B（超出噪声宽度），且调整后的比特账显示总编码长度仍在下降，则说明 Hoffmann 拟合式在你们的语料/分词器上外推失效，本节数字作废（但需要给出失效的证据，不能只报结果更好）。

| 约束 | 首次 binding 的规模区间 | 绑定形态 |
|---|---|---|
| **C1 Delétang 数据最优点** | **0.2B–0.4B**（取决于 embedding 是否量化） | 一旦 N > N\*(D)，继续放大参数使 adjusted rate 上升 |
| **C2 plateau 三分类** | **每一步都在作用**（0.1B 起） | 决定当前该走扩容还是先调优化/补数据 |
| **C3 三值离散边界余量 F_δ** | **0.5B 起**（三值模型上的每一次结构操作） | 每级扩容的部署函数逐位不变性与跳变幅度 |
| **C4 RSI 累积不替换** | **仅当闭环激活后**（≥0.5B 的某个时点） | 互斥规则：闭环激活期冻结扩容 |

**首次 binding 的顺序是 C2 / C1 → C3 → C4**；其中 C2 是常开门，C1 是第一道物理墙。

#### 4.2.2 判定清单（每次扩容前机械执行）

```
输入: 当前规模 N, 语料 D, 记账 bits/param b_eff, 噪声宽度 σ

第 0 步  Gate 0 是否通过?  否 → 停止; 先建评测底座

第 1 步  计算 N* = [D·b_eff^-1·99.67]^0.746
         计算 adjusted_rate(N) 与 adjusted_rate(N_next)
         若 adjusted_rate(N_next) > adjusted_rate(N) + δ_acc:
             → 标记"已过压缩最优点", 进入第 4 步

第 2 步  Gate 1 三分类:
         优化受限? (换 LR/延长/换初始化 可复现同等损失)  → 调优化, 本轮不扩
         数据受限? (损失接近熵下限, 或 D < D_needed(N_next)) → 进入第 4 步
         容量受限? (更大模型同等预算下留出损失显著更低)     → 进入第 3 步
         三者皆否 → 不可判定, 补测量, 本轮不扩

第 3 步  F_δ 检查(仅当 N ≥ 0.5B):
         结构操作按"冻结旧符号 + 该行 α"执行 → F_δ = 0, 放行
         否则: 计算 t = 加宽比例; 若存在 |W/α| > 1.5/(1+t) 的坐标
               → 会确定性翻转, 必须改用冻结方案

第 4 步  插入能力模块, 四选一(按优先级):
         4a 补数据 (ΔD ≥ D_needed(N_next) − D)          ← 首选, 但受红线约束
         4b 词表 append (0.4B) / 认主头 (0.4B)
         4c 记忆层 (0.5B 起), 选型判据见 §4.4.2
         4d 蒸馏桥接 (0.5B 架构重置时), 见 §4.4.3

第 5 步  若闭环已激活: 扩容与闭环不得并行, 先冻结其一
```

#### 4.2.3 伪代码

```python
def next_action(N, N_next, D, b_eff, sigma, plateau_class, rsi_active):
    if not gate0_passed:                 return "STOP_BUILD_EVAL_SUBSTRATE"
    N_star = (D * 99.67 / b_eff) ** 0.746
    if adj_rate(N_next, D, b_eff) > adj_rate(N, D, b_eff) + delta_acc:
        return "MODULE_INSERT"                       # C1 已 binding
    if plateau_class == "optimization_limited":      return "TUNE_OPTIMIZER"
    if plateau_class == "data_limited":              return "ADD_DATA_OR_MODULE"
    if plateau_class != "capacity_limited":          return "MEASURE_MORE"
    if N >= 0.5e9 and not frozen_symbol_scheme:      return "ENABLE_F_δ_FREEZE"
    if rsi_active:                                   return "FREEZE_ONE_OF_TWO"
    return "SCALE_PARAMETERS"
```

> **falsifier**：若在 `SCALE_PARAMETERS` 放行的每一级上，扩容后的 Δval loss 都不超过 2σ，则判定本规则的分支条件失效（说明 N 已经过 N\*，而 4.2.2 第 1 步的 `delta_acc` 置得太宽），必须回标定 `delta_acc`。

### 4.3 CPU→GPU 墙钟拐点

**结论**：**拐点设在 0.5B**。理由由 §2.3 的两道独立墙给出——墙钟（0.5B 单遍 69 天 @B=32k）与内存（3B 需 48 GB、8B 需 128 GB 优化器状态）。

**给你们的执行建议**：0.4B 分水岭那一级在 CPU 上做完（这是现有语料支持的最后一级，§4.1.3），**0.5B 起切 GPU 基底**。这样 CPU 侧的总投入被限制在前四级，与「算力归用户」的分工一致。

**随 1.58bit 记账移动的方式**：见 §2.4。一句话——**记账效应把拐点提前（参数更多更贵），算子效应把拐点推后（若带宽受限）**，两者不能混在一起说。哪个占优由 x 与 s 两个实测数决定。

> **falsifier**：若在 64 核上实测三值版的 s < 1.2（即三值在 CPU 上几乎不快），则算子效应可忽略，拐点位置以记账效应为准，**应提前到 0.4B**。

### 4.4 三个模块插入点的设计规格

#### 4.4.1 0.4B 认主对比头

**① 角色界定（先于技术设计）**【合理推断】
该头**不承担拒绝服务**。学习式身份头作用在主干激活上，可被风格迁移（攻击者模仿作者文风）与简单规避绕过；把它当安全边界会把「模型的判别力」误当作「系统的授权」。授权放在模型之外（密钥/文件权限）。**这条不是可有可无的口径，它决定了后面的验收标准：该头要做的是「判得准」，不是「挡得住」。**

**② triplet 结构**【合理推断 + 需消融实验】

- anchor：owner 的一段文本。
- positive：同一作者的另一段（**跨主题**取样，否则学到的可能是主题）。
- negative 四类，必须都出现：
  - (n1) 主题匹配的他人文本（**困难负样本，最重要**——它专门吃掉「主题捷径」）
  - (n2) 主题不匹配的他人文本（简单负样本，防退化）
  - (n3) **风格迁移样本**：用另一个模型把他人文本改写成 owner 风格（对抗负样本）
  - (n4) 模型自产文本（自产样本与 owner 的边界）
- 采样配比建议初始 n1:n2:n3:n4 = 4:2:2:2，按困难负样本挖掘（每轮把判定边界附近的负样本加权）动态调整。

**③ 负样本池要多大**【合理推断，统计规则】
用 rule of three：要声称「误接受率 < r」，在 95% 置信下需要 **≥ 3/r** 个独立负样本。于是：

| 想要声称的误接受率 | 需要的独立负样本数 |
|---|---|
| < 10% | 30 |
| < 5% | 60 |
| < 1% | 300 |
| < 0.1% | 3000 |

再乘上「主题 × 作者」的交叉覆盖：至少 **K ≥ 20 个作者 × M ≥ 10 个主题**，即独立负样本 **≥ 1000 段**才能同时压住主题捷径并把误接受率说清楚。**「需要多少来源数」= 由你们想声称的误接受率反推，不是拍一个数。** 若 owner_corpus 的实际规模达不到，则**降低声称强度**（只能报「相对基线更低」，不能报绝对 FAR）。**【缺配置：owner_corpus 规模与来源数】**

**④ 与主任务的联合训练**【合理推断 + 需消融实验】
三阶段，**顺序不可颠倒**：

- **S1 冻结主干**，只训头（含一个投影层）。此时判别力上界清晰，且**主干泄露风险为零**。
- **S2 小 LR 解冻主干末 2–4 层**，交替 batch（主任务 : 对比任务 = 4:1）。监控梯度冲突。
- **S3 全解冻**——**默认不做**。做了就必须回到 S1 的探针复测。

**⑤ 梯度冲突**【合理推断】
先测量再选择。取一个训练批次，分别算 `g_main` 与 `g_head`，记录夹角余弦的分布：

- 若 `cos(g_main, g_head)` 为负的时间占比 **< 20%**：普通加权求和即可。
- **20%–50%**：用 PCGrad（把冲突梯度投影到对方正交补）或分离参数子集。
- **> 50%**：说明两个任务共享了不该共享的表示——**先收缩头容量或改用非学习式方案**，不要硬调权重。

> **falsifier**：若在 S2 上 `cos` 的负占比长期 > 50%，而判别力仍达标，则「梯度冲突」在本设置下不是瓶颈，本条设计的前提被推翻。

**⑥ 主干泄露探针（最关键的验收）**【需消融实验】
冻结主干，在主干激活（取最后 2–3 层）上训一个**线性**探针预测作者标签。

- 判据：`探针准确率 − 打乱标签基线的准确率`，与噪声宽度比较。**显著高于基线 = 不通过**（主干已编码身份）。
- 必须用 **NC-AUTHOR-SHUFFLE** 校准，不能拿 1/K 当随机基线（小样本下 1/K 严重低估）。
- 二阶检验：把探针换成 **风格迁移样本上的线性探针**——若主干能线性读出「风格」而非「作者」，同样是不通过。

#### 4.4.2 0.5B 记忆层联合训练协议

**① 选型判据（取代「不增 FLOPs」）**
「不增 FLOPs」这句话**在原文里是成立的**（§0.2 第 3 条已核验），但同一篇原文紧接着写了 **«memory layers … are almost entirely memory bandwidth bound»**。**FLOPs 不是绑定的量，带宽才是。** 于是判据改为：

| 判据 | 类型 | 阈值 |
|---|---|---|
| 端到端首 token 延迟（p50 / p99） | 预算 | 目标端侧实测后设定【缺配置】 |
| 常驻内存峰值 | 预算 | 同上 |
| **删除演练**（写一条 → 删一条 → 查记忆 / **查权重** / 重训撤销） | **0/1 硬判据** | 不通过即淘汰方案，不做权衡 |
| 条目→输出的可追溯 | 0/1 | |
| 版本回滚 | 0/1 | |

**这是对原路线的实质性修改建议**：把「不增 FLOPs」降级为背景事实，把「可删除 / 可审计 / 可回滚」升为选型的第一关。

**② 三种记忆方案的结构性差别**【理论可答】

- **外置可寻址记忆（Memory Layers 式）**：key/value 是**可训练参数**而非激活；稀疏查表；删除 = 删一个条目，**不触及权重**。
- **测试时在线更新参数的记忆（Titans 式）**：原文明确 «learns how to memorize/store the data **into its parameters at test time**»，用「惊讶度」（对输入的梯度）驱动更新，带遗忘门控。**个人数据会被写进参数**——与「个人数据可删除」的治理目标直接冲突，且删除需要从参数中移除信息，不是删一行。

**③ 三组件 loss 配比**【合理推断 + 需消融实验】
**不要按 loss 数值配比，要按梯度范数配比。** 三组 loss 的量级差异可达 2–3 个数量级，按数值配比会隐含地把小量级那组关掉。

- S1（对齐）：`L_task : L_recon : L_triplet = 1.0 : 0.10 : 0.05`（初始值）→ 按梯度范数归一后重标定
- 自适应权重用不确定度加权或 GradNorm，**并给出权重搜索的停止条件**（例如：任一组件权重的二阶差分低于阈值，或验证指标连续 3 次评测变化 < σ）。
- 必须报告三组 loss 各自的**分量梯度范数曲线**——这是权重是否合理的唯一直接证据。

**④ 训练顺序**【合理推断】

- **S1**：冻结主干 **且冻结 adapter**，只训 user embedding 与检索库。目的：让检索空间先立起来。
- **S2**：冻结主干，联合训 adapter（LR = S1 的 1/5）。
- **S3**：**主干永不解冻。** 这是安全前提（否则记忆投毒会经闭环固化进权重，§7 矛盾 4），也是「删除权」可成立的前提。

**⑤ 检索库更新时机与漂移**【需消融实验】

- 更新时机：只在 (a) 无梯度期、(b) 通过验收判据、(c) 已生成版本快照时。
- **漂移的两个可观测量**：
  - `IDX-DRIFT-1`：固定一组查询，更新前后 top-k 返回内容的重合率。
  - `IDX-DRIFT-2`：user embedding 与 key 空间的相对位移（Procrustes 距离）。
- 预防：**冻结 key 编码器** + 双索引影子期（新索引并行运行、离线评估、达标后原子切换）。

**⑥ 硬性约束**【原文级】
原文 §5.4：更换更多 FFN 层 «degrades performance»，稀疏与稠密层**likely complementary**；初始配置只替换 **middle FFN layer**。**不要一次性把所有 FFN 替换成记忆层。**

容量的天花板问题：**10M 记忆 vs 0.5B 主干 = 2%**（【缺配置】10M 指参数量还是字节数，两种解读差 4 倍）。若个性化能力主要住进记忆，则**个性化的天花板由记忆容量决定**，此时「模型进化」在功能上更接近「记忆演化」。这句话不是修辞，它有一个可测的推论：**冻结主干、只更新记忆，能否复现全部个性化增益？** 能复现 ⇒ 底座权重不承载个性化。

#### 4.4.3 0.5B 蒸馏桥接

**① 三值 STE 下的梯度路径**【理论可答】
前向 `y = Q(W)·x`，反向 `∂L/∂W_latent = ∂L/∂W_hat`（STE 直通）。**关键点：结构操作必须在 fp32 潜变量上做**（P1 解法 A），三值仅作推理表示；否则结构操作与量化是同一个不可微步骤，无法做函数保持。

**② 前端 KL 在 5 万词表下的差异**【理论可答 + 需消融实验】

| 目标 | 行为 | 5 万词表下的后果 |
|---|---|---|
| 前向 KL `KL(t‖s)` | mode-covering | 学生必须给**每个**教师 token 非零概率；教师长尾的 `p_t·log(p_t/q_t)` 在 `q_t→0` 时发散 → **梯度被大量极小概率项主导，数值不稳**。必须 top-k / top-p 截断 |
| 反向 KL `KL(s‖t)` | mode-seeking | 学生坍缩到教师的众数；在三值网格上更稳，但**加速能力谱系收窄**（与 P3 的「能力 C 在容差 τ 内」口径冲突） |
| JSD | 有界、对称 | 数值最稳；在教师接近零处梯度仍稀疏 |

**建议**：主目标用 JSD 或 top-k 截断的反向 KL，并对**被截断的概率质量做显式记录**（每批次的 `Σ_{truncated} p_teacher` 是必须报告的诊断量，它不是超参，是信息损失的直接度量）。

> **falsifier**：若前向 KL（带 top-k=1000 截断）与 JSD 在 5 万词表下的收敛曲线无显著差异，则本条关于「前向 KL 数值不稳」的推断在本设置下不成立。

**③ 「无损压进三值」的正确表述**【理论可答】
三值网格每参数 1.58 bit，教师是 fp16。**信息论上「无损」不可达。** 可达的是 P3 的口径：**「能力 C、用 M 测、在分布 D 上、容差 τ 内」**。因此桥接的目标函数应写成带 τ 的约束优化，而不是「最小化 KL」。

**④ 对照臂（四个都要有）**

| 臂 | 作用 |
|---|---|
| A. **无蒸馏**（从零训到收敛） | **格点天花板**——这是「蒸馏有没有空间」的前提测量 |
| B. **TEACHER-SWAP**（换同规模不同来源的教师） | 分离「教师能力」与「正则化效应」 |
| C. **fp32 扩展后量化**（fp32 扩容 → 蒸馏 → 再量化） | **唯一能分离「架构重置损失」与「蒸馏增益」的臂** |
| D. **学生天花板**（不蒸馏，同架构训到收敛） | 判据：若 D > 教师损失，任何桥接都不可达，先改架构 |

**⑤ 执行顺序**：先测 A 与 D（便宜、结论硬），再决定是否需要 C。

### 4.5 三值离散性沿整链的聚合漂移预算（M-DRIFT）

**① 单位定义**【合理推断】
在冻结的探针集 `D_probe` 上，一次操作的漂移

```
d = KL( p_before(·|x) ‖ p_after(·|x) )  在 x ~ D_probe 上的均值
```

**注意分母**：漂移必须用 **softmax 之后**的分布度量。只比 pre-softmax logits 会通过，比分布会失败（P2 已立）。两个测试都要写进验收。

**② 安全阈值判据**【理论可答】

- **硬约束（0/1，可做到精确 0）**：结构操作前后，**部署函数在 D_probe 上逐位相同**。
- **达成条件（两个都得满足）**：
  - (i) fp32 潜变量坐标不变（P1 解法 A）；
  - (ii) **该行的 α 不变**（冻结该行 α）。
- **「在 fp32 潜变量上操作」单独不充分**：若 α 是组/全局共享统计量，加入 k 个零行后 `α' = α·n/(n+k)`，**所有旧坐标的量化值都会重新取整**。两个条件是「与」不是「或」。

- **软预算（蒸馏、记忆插入、数据更新带来的漂移）**：`M-DRIFT ≤ κ·σ`，σ 为 Gate 0 的噪声宽度。**κ 必须在看到结果前定死**；事后定 κ 等于没有预算。

**③ 翻转与加宽比例的解析关系**【理论可答】
设加宽比例 `t = k/n`（新增通道 / 原通道），稀释后 `α' = α/(1+t)`。坐标 `x = W/α` 在操作后变为 `x(1+t)`，**翻转当且仅当它跨过 0.5 或 1.5 的取整边界**。于是：

- 存在 `|x| > 1.5/(1+t)` 的坐标 ⇒ **确定性翻转**（不是概率事件）。t = 0.5 时，所有 `|x| > 1` 的坐标都会翻。
- 因此**安全阈值**是：要么冻结（F_δ = 0，精确），要么保证 `t < 1.5/max|x| − 1`。
- **已实测的 1.70% 无法外推**：它同时依赖加宽比例 t、规模、以及你们对「跳变」的度量口径（是 loss 跳变、翻转坐标占比、还是输出漂移）。**【缺配置：该测量对应的加宽比例与度量口径】**

> **falsifier**：若在固定 t 下重测跳变，发现其与 `1 − P(|x| ∈ 边界带)` 的解析预测偏差超过 2 倍，则「稀释机制」这个根因表述不完整，需要补其他机制。

**④ 整链预算分配**【合理推断】

| 事件 | 次数 | 单次配额 | 依据 |
|---|---|---|---|
| 0.1B→0.4B 的 MLP 扩容 | 3 | **0**（硬约束） | 尚无三值，且保函数可精确实现 |
| 0.4B 词表 append | 1 | **分布漂移有界**：`ΔlogZ ≈ k/V ≈ 0.04 nat` | P2 已立 |
| 0.5B 架构重置 | 1 | **不计入漂移预算**——它是新模型，功能 KL 是蒸馏目标不是漂移 | P3 已立 |
| 0.5B→8B 的三值扩容 | 8–10 | **0**（冻结符号 + 该行 α） | 硬约束 |
| 蒸馏 / 记忆插入 | 每次 | `≤ κ·σ` | 软预算 |

**结论**：在冻结方案下，**结构操作对漂移的贡献应为精确 0**，M-DRIFT 的预算全部留给软操作。这是这条路线里唯一一处可以做到「精确」的地方，值得把验收写成逐位比对而不是阈值。

## §7 结构性矛盾（直接点破，不做圆场）

**矛盾 1｜Gate 1 与「逐级扩容到 8B」在 3.5B 语料下互斥。**
过了 N\*（≈0.2B–0.4B）之后，你们会观察到的每一个 plateau **在定义上都是数据受限的**。届时 Gate 1 会正确地拒绝扩容——但它每次都会拒绝。**「学满 plateau 再扩容」这条规则在 0.4B 之后会自动变成「永不扩容」。** 这不是 bug，是规则在语料约束下的必然结果。**必须在 0.4B 之前就把 §4.2 的模块插入分支写进规则，否则路线会在 0.4B 停下来而没人知道为什么。**

**矛盾 2｜「三值把最优点推大」与「端侧最小内存最快速度」方向相反。**
三值把 8B 的存储从 16 GB（fp16）降到约 1.6 GB，但 8B 成为压缩最优需要 187B token——是现有语料的 53 倍。**两件事不能同时要。** 三值买到的是「同样的参数用更少比特」，不是「同样的语料可以撑更大参数」。

**矛盾 3｜BitNet 原配方的 fp16 embedding 与「1.58 bit/参数」的记账口径冲突；且若改成三值 embedding，会与 0.4B 的中文 token 初始化设计冲突。**
原文 §3 明确 «the embedding remains full precision»。照搬 ⇒ 实际 bits/param 在 0.2B 时是 **5.50** 而不是 1.58，N\* 从 411M 掉到 193M。改成三值 ⇒ 0.4B 时用「旧子词 embedding 均值」初始化的新行范数偏低，logits 天然接近 0，需要额外补偿。**两条路都可行，但必须显式选一条并同步改记账；不选就会出现「用 1.58 的说法做决策、用 5.5 的实物付账」。**

**矛盾 4｜Titans 式记忆与「个人数据可删除」不可调和。**
Titans 原文：记忆模块在**测试时把数据写入自己的参数**。个人数据一旦进入参数，删除不是删一行，而是要从参数里移除信息——这需要权重级血统与重训撤销。若记忆层数据政策允许个人数据进入闭环，**Titans 式方案在删除演练上几乎必然失败**，应在选型阶段就用 0/1 判据淘汰，而不是上线后补救。

**矛盾 5｜RSI 闭环与「学满 plateau 再扩容」互斥。**
闭环持续改模型，plateau 这个触发条件在连续更新下无定义。已有的互斥规则（闭环期冻结结构）是对的，但还没有说明**闭环期间 Gate 1 如何取值**。建议显式规定：闭环激活期，Gate 1 停用，改用 Gate 8 的地板判据。

**矛盾 6｜Gate 4 的「旧 logits 逐位不变」测试会通过，而「输出分布不变」测试会失败——两个测试都被写进了验收，但它们给出相反结论。**
这不是设计缺陷，是 P2 的必然结果。**必须在验收文档里预先写明：logits 逐位不变是放行条件，分布变化有界是记录项。** 不写明，两条验收会在评审时打起来。

**矛盾 7｜「累积不替换」的文献保证覆盖不到你们的实际做法。**
Gerstgrasser 的理论结论是：**累积**（新数据不断加入）时测试误差有与迭代次数无关的上界；Shumailov 的反例是**替换**。而你们的路线在 0.4B 之后需要 **3.3×–53× 的 epoch 重复**——这是第三种情形：**固定语料的多轮重复采样**，两份文献都没有覆盖。**这是一个真实的未覆盖区间，不是文献矛盾。** 必须标【需消融实验】，判据见 P-R1。

**矛盾 8｜"保函数"保证的是第一步不劣化，不保证后续学得更快——而后者才是阶梯经济性的全部依据。**
原文级证据：bert2BERT §4 写明直接复制参数 «is not effective»（只省 13.8%）。**保函数是必要条件，不是充分条件。** Gate 3 测的就是这个缺口。
